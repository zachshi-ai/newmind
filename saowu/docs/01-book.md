# 01 · 选书：《后汉书·陈蕃传》与清·刘蓉《习惯说》—— 扫屋

## 原文

《后汉书》（南朝宋·范晔撰；本文引文据中国哲学书电子化计划《后汉书·陈王列传》同文）：

> **蕃年十五，尝闲处一室，而庭宇芜秽。**父友同郡薛勤来候之，谓蕃曰：
> 「孺子何不**洒埽**以待宾客？」蕃曰：「大丈夫处世，当**埽除天下**，
> **安事一室**乎！」勤知其有清世志，甚奇之。

诚实注记：原典里薛勤听罢是「甚奇之」——**并未反驳**；「一屋不扫，何以扫
天下」的训诫式反用，是后世流传中对这段对话的引申。把反用坐实的，是清代
刘蓉的《习惯说》：

> 蓉少时，读书养晦堂之西偏一室……**室有洼，径尺，浸淫日广。每履之，足
> 苦踬焉。既久而遂安之。**一日，先君子来室中坐，语之，顾而笑曰：「**一室
> 之不治，何以天下家国为？**」命童子取土平之。……噫！**习之中人甚矣哉！**
> ……故君子之学，**贵乎慎始**。

两段合起来，正好是一课完整的治理学：陈蕃说大丈夫当扫除天下、安事一室——
**做大事业的，最容易看不上收拾自己的屋子**；刘蓉说一室之不治，何以天下
家国为——而且屋子里的坑会「既久而遂安之」：**踩惯了坑，坑就成了地板**。
习之中人甚矣哉。

## 为什么是这本书

Agent 干活恰好相反于陈蕃：它没有「扫天下的志」可以拿来做借口，它只有一
间一间的屋子——可它照样不扫。最典型的一屋是**调试残迹**：修 bug 时撒下
的探针——`console.log("DEBUG: here")`、`debugger;`、`breakpoint()`、
`binding.pry`、`set -x`——问题修完，探针全数留场，任务照常宣布完成。
这不是功能的缺失（测试绿、功能对），是**收拾的缺失**；而且它符合刘蓉
说的每一个特征：撒的时候脚会踬（探针在日志里吵、在启动时挂），「久而
遂安之」（agent 没有保洁环节，每一次没扫都在强化「留着也没事」），
「习之中人甚矣哉」——撒针不扫是**系统性的积习**，不是偶发的疏忽。

病的代价不是「难看」：`debugger;` 落进交付的前端，生产环境浏览器当场
挂死；`breakpoint()`（PEP 553）落进服务端代码，无环境变量覆盖时进入
调试器阻塞进程；带 DEBUG 标记的打印把内部路径与中间态写进生产日志——
信息泄漏面、日志污染与性能损耗；下一个会话读码，「这行 log 是功能还是
调试」无从分辨。业界对此病有结构性招供：pre-commit 官方 hooks 仓库
有一个 hook 名字就叫 **debug-statements**（专查 `breakpoint()`、
`pdb.set_trace`、`import pdb`），ESLint 有 `no-console`/`no-debugger`，
RuboCop 有 `Lint/Debugger`——每个主流工具链都造了扫帚。但工具链造扫帚
是一回事，**这间屋子的住户扫不扫**是另一回事：lint 规则可以被关掉
（静音指令自有一层在审），lint 不在器册时无人跑 lint，而 agent 的调试
发生在 lint 看不见的时刻——「当时撒没撒、末卷还剩没剩」只发生在会话流
内，任何仓库快照工具都回不到那个时刻。

两段古文的治理姿态合起来就是本层的全部设计：**一室之不治，何以天下
家国为**（残迹是既成的落笔事实，账要记在「室」上——码面末卷，不记在
「志」上）；**久而遂安之**（积习之垢要有一本让积习可见的账——垢值与
门禁）；**洒埽以待宾客**（交付是对下游的待客——末卷净，是 agent 自己
能出示的待客之礼）。本层不假装能读懂「这个 log 是不是故意的」（语义
判断是禁区），它只做词法可证的三问：**撒了什么、末卷还剩什么、剩的
那几处是不是留册上明言的正当之留**。
