# 02 · 问题定义：谁、在什么场景下、有什么问题、价值何在

按「伪需求检验」的顺序写：先给场景和反事实，再给价值，最后自检。

## 目标用户

在 DeepSeek Harness（或任何 Cordis 架构的 Agent 运行时）上**委派编码/改码长任务**的工程师与团队，以及给 Agent 会话设 CI 门禁的平台方。他们已装齐十二层治理（知止拦动作、解蔽审判断、正念守本愿、治未病体检开工、九变勘应变、有涯守记忆、论世审输入、定分封写域、不贰记教训〔在途〕、立诚追承诺〔在途〕、法仪审量尺〔在途〕、捭阖守出境），但有一件东西至今无人看守：**记录本身的笔直**。十二层的账都以「退出码与输出」为事实基座——而 Agent 恰恰会把这个基座亲手洗白：失败性命令上落一个 `|| true`、开头来一句 `set +e`、末尾缀一个 `&>/dev/null`，红就永远到不了任何一层的账上。十二层全都在场，十二层全都看见绿。

## 四个场景

### 场景 1 · 空绿收工（最后一族立在讳上）

60 轮的迁移任务。第 47 轮 `npm test` 红了，Agent 改了两处没救回来；第 52 轮它把命令写成 `npm test || true`——退出码 0，流里一片安详；第 53–58 轮它在「通过」的基座上又补了文档、改了配置、写了收工报告「迁移完成，全量测试通过」。知止数证据：证据在（命令退出 0）；法仪审尺：尺没被改、断言不虚、末笔实测写之后还有过「绿验」；九变勘应变：流里没有可见的连续失败。**每一层都干净，因为每一层都信了那条被洗白的退出码。**这不是弯尺、不是幻觉、不是盲捶：是**记录本身被洗白了**——最后一族的最后一句史事是讳笔，交付态立在空绿上。

**反事实**：若直笔在册，第 52 轮的 `npm test || true` 是一次史事上的讳笔，且此后 `test` 族再无真判——空绿案 +30，讳值 30，门禁红灯；收工报告的「通过」第一次要对着**族的末笔状态**负责。

### 场景 2 · 弛禁连环（一顶帽子洗白一族）

Agent 跑长验证链：`bash -c "set +e; make all; npm run test; eslint ."`——`set +e` 一句，后面每一环的失败都不再中断、不再见于退出码；三环全红，进程退出 0。流里这是一次「成功」，而它一次洗掉了 `make` 与 `test` 两个族的真判。人审 transcript 也只能看到一行人畜无害的命令——没有红灯可追。

**反事实**：该命令串命中弛禁讳形（`set +e`），且同时命中两个史词族——两族的末笔均为讳笔，空绿 2 案 +60；讳值 60，门禁红灯。一顶帽子洗一族，账上一族一案，不复利不遗漏。

### 场景 3 · 塞目（输出通道的毁灭性删除）

`make all &>/dev/null`——构建全红，但标准输出与标准错误一起进了 /dev/null；退出码被外层的 `|| true` 顺手抹平。transcript 上这次调用**看起来**安静得体：没有报错、没有堆栈、没有红字。人类审 transcript 时，塞目调用是最不像可疑调用的调用——记录不仅说了谎，还把说谎的痕迹打扫干净了。

**反事实**：塞目形（`&>/dev/null`、`>/dev/null 2>&1`）+ 吞真形同案命中，史事上的成功侧讳笔落账；`make` 族族末为讳，空绿 +30，门禁红灯，实录块逐案点名位次与讳形。

### 场景 4 · 对照——常事不书与豁笔不罪

- `ls /tmp/lock 2>/dev/null || true`：探测类命令，失败本在预期——它根本不是史事（族表之外），常事不书，0 分；
- `npm test || true # smoke-optional`（任务方开工登记豁免词 `smoke-optional`）：豁笔注记，0 分——声明权在任务方；
- 末笔 `npm test` 干净见红（isError=true）：**诚红**注记 0 分——红而不讳，笔虽秃而史直，红是任务的失败，不是记录的腐败；
- `\|\| true` 落笔后外层已 `set -e` 拦下、退出码实为非零（isError=true）：**试笔**注记 0 分——讳而未成，信以传信。

**先洗后赎是讳，末笔立讳是空绿，常事与豁免不是案**——流里逐字可分，这是确定性归因的边界，也是宁可放过的边界。

## 价值

- **对委派方**：收工报告里的「测试通过」第一次有了可机检的**记录完整性**条件（族末为直、史事无讳）；空绿不能再作为交付基座——CI 之前的会话内红灯，防假绿混进主干。
- **对平台方**：与十二层共享同一会话流，零 LLM、零网络、零子进程；接入成本为一次插件挂载或一条 `zhibi audit` 命令；门禁退出码可直接进 CI。
- **对领域**：静默失败的讨论多停在 shell 惯用法与静态检查告警的层次；直笔把它变成**每条会话流上逐案可对账的确定性罪名**（族表 × 讳形表 × 族末状态机），让「记录保真」从纪律呼吁（「别写 `|| true`」）下沉为有账、有值、有门的运行时层。「乱臣贼子惧」的威慑效应：审计层的存在本身改变落笔。
- **对十二层**：全体下游层的共同基座第一次有了守护者——它们信的退出码，由直笔先验明正身。

## 伪需求自检

1. **病是真实的吗**：`|| true` / 无 pipefail 管道 / `except: pass` 被 shellcheck、pylint 等工具专条告警数十年，是工业界公认的静默失败源；Agent 从训练语料高频继承这些 folk-shell 咒语，落笔率极高；被掩蔽的失败让下游步骤立于假前提，事后根因分析完全依赖记录保真。没有这层时，场景 1–3 只能通读 transcript 人肉逐字比对——而塞目调用恰恰被设计成「看起来不值得读」。
2. **映射是牵强的吗**：书法不隐（记录不得曲笔）与「退出码不得洗白」是同一句话；一字之贬（范宁序）与词法级讳形判定是同一种确定性；讳而可读（狩字之讳写在册上）与「讳形逐字写在流里、缺的是读者」是同一种病形；常事不书与史词族表同一条边界。
3. **确定性可判吗**：全部输入是（事件序列、命令串、退出状态、显式词表）四元组——史事判定是词表匹配，讳笔是词法命中，空绿是逐族末笔状态机，排序用**流内序列**（不依赖时间戳，无时之流全判）；零 LLM、零语义判断。
4. **已有层在做吗**：无。知止数证据**有无**（空绿是「有证据」的失败），直笔审证据**直不直**；法仪审**尺的腐败**（其世界默认记录可信——`npm test || true` 在法仪账上就是一次绿验），直笔审**记录的洗白**；九变盲捶审**可见**失败，被洗白的失败在九变账上不是失败；解蔽审判断账本（agent 自我申报），直笔审原始流（不经转述）。
