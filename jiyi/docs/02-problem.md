# 02 · 问题定义：谁、在什么场景下、有什么问题、价值何在

按「伪需求检验」的顺序写：先给场景和反事实，再给价值，最后自检。

## 目标用户

在 DeepSeek Harness（或任何 Cordis 架构的 Agent 运行时）上**委派任务到陌生环境**的工程师与团队、给 Agent 会话设 CI 门禁的平台方。他们已装齐运行时治理（zhizhi 拦动作、jiebi 审判断、zhengnian 守本愿、weibing 体检开工、jiubian 勘应变、youya 巡见闻、lunshi 审输入、dingfen 定并发、baihe 守出境、fayi 审量尺、zhibi 保记录、yuli 审退路、duzhi 量总量、erbing 审权柄、zhongshi 记终始、xiaoyan 称效实、mingshi 核名，及在途的 buer 记教训 / licheng 追承诺），但有一条通道至今无人看守：**Agent 动手之前，问过环境没有**。面对环境的未知，它用内心猜测代替稽问——猜命令、猜规矩、猜结构——猜错的每一笔都是真实的失败调用与返工，但事后审计连「第一笔动作之前它查过环境的规矩没有」都无处问起。

## 四个场景

### 场景 1 · 猜命令（谋不及物的最贵形态）

接手一个陌生仓库的任务，Agent 没看 package.json 的 scripts，直接跑 `npm run build`——这个仓库的脚本叫 `npm run compile`。炸。它再猜 `yarn build`。再炸。两次失败调用 + 两轮重试，只因为开工前没读一眼 scripts。weibing 只在 t=0 审**任务书里写了的**命令在环境里存不存在——任务书没写、Agent 自己猜的，体检无册可查；jiubian 审失败后的盲捶，但第一猜之前它无账可记；duzhi 把这两笔失败记成两笔出，却看不出「这两笔本可免」。**失败之前的可避免性，全仓无账。**

**反事实**：任务方立疑册（`--ask package.json --on exec`），收工稽问：首笔 exec 之前流内无任何对 package.json 的成功读取、命令文本也不含它——独谋案，+15/条入账。浪费从「invisible」变成「账上点名」。

### 场景 2 · 猜规矩（声明文书无人强制）

仓库有 AGENTS.md：commit 用 conventional commits、测试文件放 test/、不许改 public/ 下内容。Agent 不读它，直接写代码提交——CI lint 炸、文件放错位、重做。更微妙的是：lunshi 把 AGENTS.md 当**物渠道**防注入（它的祈使句不该被默默吸收），却没有一层要求「开工先读它」——防注入与该读之间差着半个语义层，零 LLM 分不清哪个祈使句该听。稽疑不判义、只判形：**声明文书读没读，是纯流内事实**。

**反事实**：默认形表把 AGENTS.md / CLAUDE.md / README.md 列为写域必问之疑（显式可关）；首笔 write 之前没有成功读取——独谋案入账。读了没读，收工对账，一问便知。

### 场景 3 · 猜结构（重复造已有的轮子）

Agent 要格式化日期，没搜过现有代码，凭记忆重写一个 `formatDate`——仓库 utils/ 里早有一个。youya 管「读过的忘了再读」（复见），不管「该读的没读」；xiaoyan 管绿不绿，不管写之前找过没有。本层以默认形表（README.md on write）兜底点名：写之前连 README 都没读过的工作集，账上见。

**反事实**：README.md 触发首笔 write 前无问凭据——默认条独谋 +5（默认条环境里未必有此文件，轻罚点名不冤枉；任务方显式登记才重罚——登记即作保）。

### 场景 4 · 清白之问（豁免道全部在册）

治理若错罚三种清白，比疾病更贵：(a) Agent 试读 AGENTS.md 得到 404——它**问了**，环境答「没有」，疑自解，不该罚；(b) Agent 跑了 `cat package.json`——bash 是执行族黑盒，但命令文本含其名，**词法相交即认问**（先例：yuli 影写词法相交）；(c) 纯阅读任务全流没有 write/exec——触发域未命中，不判。三种清白都必须在判定序里有显式位置。

**反事实**：判定序锁死（谋及 → 空疑 → 迟问 → 独谋 → 未见 → 无动）：404 读取归空疑（免）、先动后问归迟问（+5，毕竟问了）、bash cat 命令含名归谋及（免）、域内无动作不判——四条清白道逐案有名有分。

## 价值

1. **把「动手前稽问」从美德变成账目**：CI 门禁读谋值，≥30 即红。每单活第一次有了机制性回答：「它的第一笔动作之前，查过环境没有」。
2. **把 RTFM 从口号变成流内凭据**：读没读不靠任何人的自述，靠成功读取与命令词法——词法可欺但骗一次留一次形。
3. **不误伤清白**：404 空疑免、bash 词法认问、迟问减半、默认条未见不罚——放行道全部在册，宁可放过不可错罚。
4. **与 jiubian/youya/weibing 三层正交**：jiubian 管失败后改不改途、youya 管读过的忘不忘、weibing 管任务书写没写全——稽疑管首动之前问没问。四账并行不悖，各审各的形。
5. **零 LLM、零网络、零文件系统探测**：源的存在性以流内证据自证（读过、读过失败、或任务方作保），离线流对账，与全仓同规，可进 CI、可验尸任何历史会话。

## 伪需求自检

- **浪费是真的吗**：猜错命令 = 一次失败调用 + 重试一轮，真实成本（duzhi 能数出失败笔数，jiubian 能数出盲捶次数，但两者都以失败已发生为前提）；本层审的是失败之前的那一步缺失——三层账对不上「本可免」的部分由本层补。
- **判定是确定性的吗**：触发域是工具族词表（与 mingshi/jiubian 同源）、问凭据是对象键逐字相等 ∪ 命令词法相交、时序以流序为准——全程零语义判断。
- **会错罚吗**：默认形表只列三个协作文书且「未见不罚」（环境可能根本没有）；显式登记是任务方声明权（无册不判）；404 豁免、词法豁免、迟问减半全部显式入序。
- **声明权会不会架空它**：不会——默认形表在无显式登记时也生效（fayi/baihe/yuli 先例），`--no-defaults` 显式可关；显式登记的重罚（独谋 +15）与默认条的轻罚（+5）分层，登记价值明确。
