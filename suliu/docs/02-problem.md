# 02 · 问题：Agent 因果断言无验（据理臆断——因出于推理，验未入流）

## 谁在什么场景下的什么问题

**谁**：下游每一个照着根因行动的人与会话——照复盘报告调 TTL 的值班
工程师、照排障结论回滚依赖的下一个 agent、照 incident 报告做容量规划
的平台组、按「root cause: race condition」决定要不要重构连接池的
reviewer。

**场景**：agent 修完一单活写诊断类文书——postmortem.md 里写「根因是
缓存过期导致的数据不一致」；排查报告里写「问题在于测试环境与生产的
配置漂移」；incident 复盘里写「The root cause is a race condition in
the connection pool」。这些归因通顺、具体、有专业外观，可其中一部分，
agent 从头到尾**没有对所断言之因做过一次干预性验证**：没有改过那个
缓存配置再看错误是否消失、没有把可疑依赖降级复测过一次、没有复现过
一次竞态——它读过几眼日志（看过现场），凭「一般的系统都是这样坏」的
先验之理推出了一个「确论」，然后众服为确论：值班照「缓存过期」调
TTL，无效；下一个 agent 照「配置漂移」对环境，白对——**假根因比无
根因更毒，因为它自带权威外观**（同伪引之毒，而对象是因果）。

**问题**：诊断文书的**归因无验**无账：

- **归因是决策的把手**：复盘报告最有杠杆的一句话就是根因结论——它
  决定下游一切动作的方向；一句话臆断，全下游买单（讲学家一句话，全
  寺沿着错误方向挖沙十余里）；
- **看过现场 ≠ 验过因果**：读日志、跑一次报错、看一眼监控——这些
  「望」的姿态 agent 全有，唯独「改一下因、再看一眼果」的干预性验证
  在流里缺席；因果推断的基本立场（相关非因果）在 agent 的报告写作里
  无从落地——因为没有任何一层在收「验因」的账；
- **诚实的假设与确信的臆断同纸而居**：「可能是缓存过期」（假设）与
  「根因是缓存过期」（确论）只差两个字，下游的信任却天差地别——事后
  连「这句根因当时验没验过、是望来的还是溯来的」都无处问起；
- **事后无处问**：文书上了库、根因进了档——「它断的什么因、动没动过
  疑因、动后验果没有、验在断言前还是断言后」四问在任何一层的账本上
  都无处问起。

相邻层的空白地：文书对世界的每一面都有层在审——察传审断言之**物**
进没进流（存在性）、市虎审状态对作工、矫托审引语对原文、考诚考物对
契、指瑕审卷内自洽——**没有一层审断言之「因」验没验**（因果性）。
关键在于**证据等级差**：察传的清白线是「目见」——看过即据（物在场
即可断言其存在）；而因果断言里「看过现场」恰恰不够——讲学家也看过
现场。归因之验要求的是**干预**（动因）加**对照**（验果），这是察传
的存在性对账照不到的一层。错误还在流里跑（jiubian 勘得到失败后的盲
捶——但它勘的是行为重复，不是归因之言）、报告也在卷面上（shihu 只
认状态词、xiaoyan 只称成功成报、fangchuan 只扫代码里的吞错口）——
因果断言之验，全仓真空。

## 问题（治什么病）

一个病根、三档案别，全部真实存在、全部当众可验：

| 档 | 卷面词迹 | 现实对应 |
|------|----------|----------|
| **臆断**（立案档 +30） | 归因形（根因是/root cause/caused by…）+ 因面词元，流内三通道（拔验/重演/勘验）全查无 | 「根因是缓存过期」而全流没改过缓存、没复现过、没看过一眼相关现场——讲学家的「确论」 |
| **望断**（立案档 +15） | 归因形 + 因面词元，流内只有勘验/重演（看过现场或重现过错误），无拔验 | 读了日志、跑过两次报错就下「根因」——寺僧式的动手，动而无当（看过≠验过） |
| **显疑**（注记档） | 归因形 + 推测之词（可能/或许/suspect…） | 「根因可能是缓存过期」——疑而后言者，留痕不入罪 |
| **迟验**（注记档） | 归因在前，拔验（干预验证）在后 | 先写根因后补做的对照实验——0 分留痕（补的是溯，不算枉）；望档证据在后不采——望不洗臆 |
| **泛因**（注记档） | 归因形而因面无所指（「根因如下」「见下节」） | 因之无物，无从对账（宁纵） |

价值锚点：「写下根因之前动没动过因、验没验过果」是**零 LLM 能确定性
回答的一问**——归因形是显式词表、因面是词元集合、拔验/重演/勘验是
流内事件与词面的三元对账，逐字节可复算；不需要稿外之物（不读文件
系统、不装语料、不跑模型）。本层不做语义判断（不判根因内容对不对——
缓存到底过没过期，词法不知道；裁决权归人：臆册免案明言即免），只做
形迹判断（断必有因、因必有所动、动必有所验、验在断言先）。

## 价值（为什么不是伪需求）

1. **归因无验是真实且高价的病形**：debugging 是 agent 编码工作流里
   占时最长的环节之一，而「plausible but wrong」的幻觉根因直接毒化
   下游一切决策——业界对 SWE-agent 类系统的评测反复暴露「改症状不
   改因」「诊断与修复脱节」病形；incident 复盘文书 LLM 化之后，编造
   root cause 已是可靠性工程社区的显性抱怨。因果断言无验证形迹，正是
   这一族病的**最小可判定内核**；
2. **清白道宽、立案门窄**：拔验在前 0 分、推词在行显疑 0 分、迟验
   注记 0 分、泛因注记 0 分、演域与臆册免案——只有「归因形 ∧ 因面
   有物 ∧ 流内无任何验因形迹」才立臆断，勘验在场也只望断黄牌——
   不冤枉验过之言，更不冤枉疑而后言者；
3. **记账不禁行**：不拦写（拦是 zhizhi 的地盘）、不改文书、不跑语义
   分析——归因形与验因通道全是公开词法与流内事件比对，观察永不反噬；
4. **与察传的证据等级互补而非重叠**：察传审「物在场」（看过即据），
   本层审「因被验」（看过只算望档）——同一份复盘报告，chachu 查它
   说的文件进没进过流，本层查它说的根因验没验过；词表零交集、谓词
   正交、两账并行；
5. **可证伪**：诊面形表、归因形表、推词门、验因三通道、时序规则全部
   锁死于 03；同流重放必得同判词；跨项目历史流可验尸复算——错了改
   实现，不改标准。

## 产品形态

- **溯流式插件**（DeepSeek Harness 插件层，Cordis，结构性零拦截）：
  挂 `tools/result` 观察口，验因三通道记流内之验，诊面稿入断账逐行
  判归因，溯牌块接缝供给；
- **零依赖审计 CLI**（`suliu`）：多流离线合审（跨会话验因证据互认），
  可验尸任何历史会话；
- **Agent Skill**：给派活方与 agent 的归因协议（凡因必验、疑而后言、
  望不洗臆）。
