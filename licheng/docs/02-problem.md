# 02 · 问题定义：谁、在什么场景下、有什么问题、价值何在

按「伪需求检验」的顺序写：先给场景和反事实，再给价值，最后自检。

## 目标用户

在 DeepSeek Harness（或任何 Cordis 架构的 Agent 运行时）上**委派长任务**的工程师与团队，以及给 Agent 会话设 CI 门禁的平台方。他们已装齐运行时治理（zhizhi 拦动作、jiebi 审判断、zhengnian 守本愿、weibing 体检开工、buer 记教训〔在途〕、jiubian 勘应变〔在途〕），但有一个通道至今无人看守：**Agent 自己说出口的话**。每一轮上下文重新生成，Agent 对自己上一轮承诺过什么没有任何机制性的记忆——它说过的话不进任何账本，落空了也不欠任何账。

## 四个场景

### 场景 1 · 允诺蒸发（微承诺的静默失踪）

40 轮的迁移任务。第 3 轮 Agent 说"接下来我会补齐边界用例"，第 7 轮说"稍后把 README 的示例同步更新"，第 12 轮说"提交前我会跑一遍全量测试"。主任务完成，收尾报告整洁——三句承诺**一句都没发生**，也没有任何机制让它们发生或显式作废。这不是幻觉（jiebi 地盘）、不是漂移（zhengnian 地盘）、更不是动作失控（zhizhi 地盘）：主任务做得很好，**蒸发的是未来的承诺**。用户想发现，只能通读全量 transcript。

**反事实**：承诺若在出口那一刻成为绳账上的**结**（带兑现凭据），结账引擎在第 40 轮会确定性报出：3 结悬而未解，咎值 90，门禁红灯。蒸发从"没人记得"变成"账上见"。

### 场景 2 · 无凭之诺（连"怎样算兑现"都没说）

"我会优化这里的性能""回头把这块整理干净"。这类承诺没有凭据（discharge 判据），即使 Agent 想兑现也无从对证——它自己都不知道怎样算做到。《周易》叫**拟之而后言**：未经拟议的言，本身就是小疵（吝）。

**反事实**：立诚的账本协议里，凭据是诺的组成部分（哪个工具、调用含什么字样、成败）；无凭之诺在结账时单独立为**轻诺**计吝——不是拦你许诺，是让"随口一说"在账面上有价。

### 场景 3 · 无声改诺（范围变了，账没变）

第 10 轮发现原方案不可行，Agent 换了实现路径——第 3 轮承诺的"迁移全部 12 个模块"实际只迁了 9 个，剩余 3 个被新路径取代。**改诺本身合法**（《周易》：无咎者善补过；管理学：renegotiation 是承诺链的正规环节），病在它发生得**无声**：账上第 3 轮的结还悬着，结账时就是失诺，用户看到的是"agent 又跳票了"，而真相是"它改了主意但没说"。

**反事实**：改诺/弃约是一等公民——带理由显式登记（`revise`/`abandon` 条目），旧结合法关闭（悔，不记分）。账平，且**改约的过程可审计**：为什么改、改成了什么，全在账上。

### 场景 4 · 伪造兑现（账实不符）

诺账上写了凭据（`bash` 含 `npm test`），但会话流里根本没有那次调用——或调用报错了而凭据要求成功（`ok:true`）。承诺的兑现可以像完成宣称一样被口头伪造。

**反事实**：兑现凭据必须在会话流里**真实发生过**才算解结——工具调用逐字匹配（账实对账，jiebi 同源机制），`ok:true` 还要求那次调用未报错。说了没做、做了没成，都解不开结。

## 价值论证

1. **"自己说过的话"第一次成为治理对象**：现有六层治理的对象分别是动作、判断、本愿、任务书、错误教训、环境变化——全部是"做事"的侧面。Agent 对外**承诺**的侧面（未来时态的话语）至今没有任何机器账本。立诚补的是这个空位。
2. **信用第一次有了质量单位**：咎值（0–100）是确定性的、可复现的数字，回答一个此前无法回答的问题："这个会话的诺言信用几分？"委托关系的地基是信用（中孚），不可测量 → 不可管理。
3. **插件层的第六种能力类型**：zhizhi 证明插件可以**拦**，jiebi 证明可以**审**，zhengnian 证明可以**供给**，buer 证明可以**记习**，weibing 证明可以**只出诊**；立诚证明插件可以**结绳**——在结果接缝观察真实执行、维持一张在途绳账、宿主随叫随结账。观察照旧永不反噬，结构性零拦截（无 pre-execute 监听器）。
4. **改诺合法化了，蒸发非法化了**：立诚不制造"盲目守诺"的道德绑架——改约弃约永远合法且免费，只要显式登记带理由。它消灭的只有一种行为：**无声蒸发**。这让治理与孟子的"惟义所在"不冲突。
5. **可证伪的价值主张**：对团队自己的历史会话跑 `licheng settle`，数一数多少悬结、多少无凭之诺、多少伪造兑现——每一例都能对回一句 transcript 里蒸发掉的原话。价值自证，不靠叙事。

## 伪需求自检清单

| 质疑 | 回应 |
|------|------|
| "这不就是 TODO 列表吗？" | TODO 是**自愿维护**的计划状态：没有任何机制审计 TODO 真的被做掉、也没有任何机制把**说出口的话**绑定到它上面——自愿式不构成机制（weibing 同款论证）。立诚的差别有四：①诺与凭据绑定，兑现必须**账实对账**（TODO 打勾可以作假）；②咎值+门禁可进 CI（TODO 没有分数）；③改诺/弃约有理由入账，区分"重谈"与"跳票"（TODO 只会默默消失）；④诺活在**话语**里，TODO 活在工具里——治理的对象不同。 |
| "zhizhi 不是已经核对完成宣称了吗？" | 时态与对象都不同：zhizhi 在完成时点核对**过去时**的宣称（"我做过了，证据呢"，一次性）；立诚清算**未来时**的承诺（"我说过我会做，做了吗"，跨全程、多条、逐笔结清）。两者互补而非重叠：zhizhi 绿灯的会话照样可能蒸发了十句承诺。 |
| "zhengnian 的本愿契约不是覆盖了'说到做到'吗？" | 对象不同：本愿是**主人交代的**（起点，向上对齐），诺是 **agent 自己说出的**（途中，向下负债）。一个 agent 可以完全没漂移（本愿在场）而蒸发了自己随口的十句承诺；反之守诺守得再好也可能早已漂离本愿。两层各管一张账。 |
| "和 buer / jiubian（在途）撞车吗？" | buer 记**过去的错误教训**防重犯（跨会话）；jiubian 勘**环境变化**对计划的冲失（失机）。立诚管的是**对未来的负债**（自己说出口的承诺）——三张账互不重叠（根 README 方向登记表可查）。 |
| "用 LLM 读 transcript 把承诺抽出来不就行了？" | 三个老问题：不可复现（两次抽取结果不同）、有成本（抽承诺本身烧 token）、不可门禁（"我觉得它失诺了"进不了 CI）。立诚零 LLM：账本协议 + 确定性对账 + 逐字重放。抽不出账外的话，就诚实承认读不到（speech 缺失时 `unaccounted: null`，绝不假装核对）。 |
| "agent 不承诺不就永远 0 分？这是激励倒挂吧" | 是特性不是漏洞：「古者言之不出，耻躬之不逮也」——少诺是德。立诚从不强迫许诺；它改变的是许诺的**价格**：出口即入账、无凭记吝、悬结记咎。另外 speech 事件齐备时，`audit` 提示会显出"流中诺言措辞 N 处 / 账内立诺 M 条"的漏账缺口，倒逼账面诚实。 |
| "改诺免分会不会被滥用成'先诺后改'逃费？" | 改诺必须带理由显式登记，且**全程可审计**（改约链在账上永久可见：p-003 → p-003r → …）。滥用的成本是把"无声蒸发"升级成"公开出尔反尔"——对委托人反而更有用。治理目标是消灭蒸发，不是消灭变卦。 |
| "凭什么说是真实问题？" | "agent 说会做 X 结果没做"是 agent 用户访谈与 issue 区的高频抱怨；harness 自带 TODO 工具这件事本身就是问题的存在证明——但 TODO 是自愿式计划工具，没有人对**话语承诺**负责。Promise-based management（HBR）在人类组织中论证过的承诺链治理，Agent 世界至今没有机器化的对应物。 |
