# 02 · 问题：Agent 无见立言（幻证自陈——言出于想象，物未进流）

## 谁在什么场景下的什么问题

**谁**：下游每一个照着文书决策的人与会话——照 README 装环境的下一个
工程师、照交接书接手的下一个 agent、照迁移报告排期的任务方、按报告
里的「位于/使用/包含」核验收的 reviewer。

**场景**：agent 修完一单活写交付文书——「配置集中在 src/config.js，
使用 CommonJS 导出」「测试位于 tests/e2e」「日志输出到 logs/agent.log」
「本项目使用 Redis 做会话存储」。这些断言通顺、具体、可执行，可其中
一部分**所指之物从未进过会话流**：全流没有一次对 src/config.js 的成功
装载，没有一次对 tests/e2e 的列目，没有一行写入 logs/agent.log——话是
模型先验想象里「一般的仓库长这样」的投影，被当成勘察结论写进了交付。
reviewer 照「配置在 src/config.js」去核配置、下游会话照「日志在
logs/agent.log」去取日志、运维照「使用 Redis」做容量规划——每个读者
都把一句想象当成了事实。

**问题**：交付文书的**无见立言**无账：

- **无引号的断言比伪引更泛滥**：jiaotuo 已收编「引语对不上原文」——
  那要求引号与自称原文的引形；而文书里最大量的断言**没有引号**：
  「使用 X」「位于 Y」「包含 Z」——一句都不自称引用，一句都无处过堂；
- **先验想象的投影当众落地**：模型对「一般仓库」「常见配置」的先验
  会被写成「本仓库的事实」——幻觉是 LLM 的结构性病形（Ji et al.,
  *Survey of Hallucination in Natural Language Generation*, ACM
  Computing Surveys 2023，事实性幻觉分「与事实冲突」与「与输入冲突」
  两类；HaluEval，EMNLP 2023，逐 claim 评测幻觉），RAG 时代忠实度
  （faithfulness）已成专门评测轴（RAGAS，EACL 2024）——而 agent 交付
  文书里的本地事实断言，逐 claim 的流内核验没有任何一层在做；
- **下游以幻言为真**：交接书与报告是下一个会话的输入——照幻径找
  配置、照幻目录跑测试，第一脚踩空之后它还得先分辨「是文档错了还是
  世界变了」；
- **事后无处问**：文书上了库、断言进了档——「它断言了什么、所指
  何物、这物流内进过没有、断言当时有没有据、后来补看没有」五问在
  任何一层的账本上都无处问起。

相邻层的空白地：文书对世界的每一面都有层在审——市虎审状态陈报对
自流作工（状对作工）、矫托审引语对所托原文（引对原文）、考诚考交付
物对任务方之契（物对契）、效验称成报对流内证据（报对证据）、名实核
码面之名对环境之实（名对实）、指瑕审稿面对稿面自己（数对稿面）——
**没有一层审言对所见**：文书里那些不自称引用、不对应契约、不算状态
陈报的平铺断言，其所指之物进没进过流，全仓真空。文档说「配置在
src/config.js」时，作工是真的（市虎放行）、引语没出场（矫托沉默）、
契约未必有（考诚不判）、绿也是实的（效验放行）——假的只在言与物
之间：**物根本不在场**。

## 问题（治什么病）

一个病根、三档案别，全部真实存在、全部当众可验：

| 档 | 卷面词迹 | 现实对应 |
|------|----------|----------|
| **幻言**（立案档 +30） | 得言形（使用/包含/位于/写着…）+ 径指物，所指之物流内无见据 | 「配置集中在 src/config.js」而全流无一次成功装载/落笔/执行——所指之物不在场 |
| **疑言**（立案档 +15） | 得言形 + 目录指物（裸目录名 tests/dist/src…），无见据 | 「测试位于 tests」——裸目录断言，信一半 |
| **迟证**（注记档） | 断言之笔在前，见据在后 | 先断言后补看——后来补上的勘察，0 分留痕 |
| **虚指**（注记档） | 得言形而无所指之物 | 「项目包含多个功能模块」——言之无物，无从对账（宁纵） |

价值锚点：「所指之物进过流没有」是**零 LLM 能确定性回答的一问**——
得言形是显式词表、指物是径形词法、见据是流内事件对账，逐字节可复算；
不需要稿外之物（不读文件系统、不装语料、不跑模型）。本层不做语义
判断（不判断言内容对不对——那是把流内之见与断言之文逐义比对，NLI
做不了也不假装能做；裁决权归人：证册免案明言即免），只做在场判断
（言有所指、指有所见、见在言先）。

## 价值（为什么不是伪需求）

1. **无见立言是真实且被学界收编的病形**：事实性幻觉是 LLM 结构性病
   （ACM Computing Surveys 2023 综述；HaluEval 逐 claim 评测），RAG
   忠实度已成专门评测轴（RAGAS）——而 agent 交付文书里的本地事实
   断言恰恰是「与输入冲突」类幻觉的高发位：模型对本地世界的先验
   投影冒充勘察结论，mingshi 已收编它的一角（幻包名——供应链面），
   其余的本地事实断言全仓无账；
2. **清白道宽、立案门窄**：目见/书见/验见在前 0 分、基径在册 0 分、
   自指 0 分、迟证注记 0 分、虚指注记 0 分、靶场与证册免案——只有
   「得言 ∧ 指物 ∧ 流内无见据」才立案，不冤枉有据之言；
3. **记账不禁行**：不拦写（拦是 zhizhi 的地盘）、不改文书、不跑语义
   分析——得言形与指物全是公开词法，见据对账是流内事件比对，观察
   永不反噬；
4. **可证伪**：得言形表、指物词法、模态门、见据三通道、时序规则全部
   锁死于 03；同流重放必得同判词；跨项目历史流可验尸复算——错了改
   实现，不改标准。

## 产品形态

- **察传式插件**（DeepSeek Harness 插件层，Cordis，结构性零拦截）：挂
  `tools/result` 观察口，见据三通道记流内之见，写稿入传账逐行判言，
  证牌块接缝供给；
- **零依赖审计 CLI**（`chachu`）：多流离线合审（跨会话见据互证），
  可验尸任何历史会话；
- **Agent Skill**：给派活方与 agent 的立言协议（言必有据、指物在先、
  后见补证）。
