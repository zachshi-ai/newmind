# 察传 · Chachu — Agent 立言协议

> **「夫得言不可以不察，數傳而白為黑，黑為白。」**
> **「聞而審則為福矣，聞而不審，不若無聞矣。」**
> **「凡聞言必熟論，其於人必驗之以理。」——《吕氏春秋·慎行论·察传》**

你写下的每一句断言——「配置集中在 src/config.js」「测试位于 tests/e2e」
「日志输出到 logs/agent.log」——都在替你向世界陈说事实。读者不问这话
是你看来的还是你想出来的，他们照着走。本协议不限制你落笔（拦是知止
的地盘），它要求：**言必有据、指物在先、后见补证**——得言而不察物，
与穿井得一人只差一个读者的距离。

## 何时用此 Skill

- 工程师想防住「agent 把先验想象写成流内事实」——无引号的本地事实
  断言（使用/位于/包含）在交付文书里泛滥的日常形态；
- CI 需要一道立言门禁（幻值 ≥ 30 即红——单幻言即红、双疑言即红）；
- 多 agent 编排里，主会话要防子 Agent 的交接书夹带幻径幻目录；
- Agent 需要自查：我断言的每一样东西，流里进过吗——读过、写过、
  还是只是想当然？

## 给派活的工程师

```bash
cd your-repo
chachu register --path "docs/reports/*"            # 免审稿径（模板文书等），先立证册
chachu audit session.jsonl --file .chachu.json     # 收工审言（exit 码可进 CI）
chachu block --file .chachu.json                   # 证牌块：证册与词法公示
```

- 证册 `grounds` 列是**基径**：任务书里已明言的物（「配置在
  src/config.js」写进任务书则 src/config.js 言之有据）——声明权全在
  任务方；
- **无册照判**：得言形与指物开箱在岗——不立册也审，册只管免审与基径；
- **靶场天然豁免**：tests/specs/fixtures/mocks 等名段不审——演武之地的
  断言是道具；
- **门禁**：幻值 ≥ 30 即红——单幻言即红、双疑言即红、单疑言黄牌不咬门。

## 给 Agent 的五条纪律

1. **言必有据**：写「X 使用/位于/包含 Y」之前，确认自己真的看过 Y——
   读过（目见）、写过（书见）、跑过（验见）三者居一，才可以说；
2. **指物在先**：断言要落在具体的径上——「项目包含多个功能模块」这类
   无所指的话无从对账，要么点名、要么别说；
3. **失败不是见**：404 的 read、报错的 exec 不是证据——试看未得而断言
   在场，是比不说更坏的幻言；
4. **后见补证**：先写了断言才想起来看？补上看——迟证只留注记不计分
   （闻而审则为福）；但交出去的幻言留痕入账，斯言一玷；
5. **词法可欺但骗一次留一次形**：改措辞躲词表、换写法避指物——改得掉
   一次判词，改不掉档案上的形；立言之据是本份，不是审计的博弈。

## 判定语义速查

| 档 | 对象 | 判定 | 分值 |
|---|---|---|---|
| 幻言 | 得言形 + 径指物，流内无见据 | 断言之物不在场 | +30/案（单案即红） |
| 疑言 | 得言形 + 目录指物，无见据 | 裸目录断言信一半 | +15/案（双案即红，单案黄牌） |
| 迟证 | 断言之笔在前，见据在后 | 后来补上的勘察 | 注记 0 分 |
| 虚指 | 得言形而无所指 | 言之无物 | 注记 0 分 |

见据三通道：**目见**（observe 成功）∪ **书见**（write 成功，含自指）∪
**验见**（exec 成功 ∧ 原文含指物）；先于本笔为据。判词与证牌永不携带
行原文（只载 稿径:行:案别:指物:指纹）。

## 一句话

市虎审状态对作工、矫托审引语对原文、考诚审物对契约；**察传审言对
所见**——读者会原谅一句粗陋的话，不会原谅一句凭空而来还煞有介事的
话。
