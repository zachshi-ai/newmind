# 02 · 问题定义：谁、在什么场景下、有什么问题、价值何在

按「伪需求检验」的顺序写：先给场景和反事实，再给价值，最后自检。

## 目标用户

在 DeepSeek Harness（或任何 Cordis 架构的 Agent 运行时）上跑**需要下判断的长任务**的工程师与团队：让 Agent 自主做根因诊断、方案选型、技术调研的人。他们已经接受了"Agent 能干活"（知止 zhizhi 治理的是这一层），正在为另一种账单付钱：**Agent 干活时下的那些判断，错得自信、无从审计、不可复盘**。

## 四个场景

### 场景 1 · 单候选锚定（蔽于一曲）

调试任务：Agent 在第 3 轮说出"应该是缓存的问题"，此后 20 轮全部在为这个假设工作——改缓存配置、清缓存、加缓存头。第 23 轮它宣布"缓存方案失败，问题很复杂"。真相在别处，但**从第 3 轮起，备选假设就没有在它的世界里存在过**。

**反事实**：现有 harness 没有任何机制问一句"你还严肃考虑过谁？"提示词里写"请考虑多种可能"属于**原则**——原则会被违反，且恰恰在上下文最长、锚定最深的时候最容易被忽略。只有**产物校验**（"没有 ≥2 个带 steelman 与 kill condition 的候选 → 蔽值 +40 → CI 红灯"）不可协商。

### 场景 2 · 确认偏误（欲为蔽 / 不以所已臧害所将受）

技术选型：Agent 被要求在 A/B 两案之间选择。它的报告结论是 A，列了 6 条理由——检索关键词全是 A 的优点，B 的部分只有一句"也有一定风险"。用户事后发现 B 的一个致命缺陷 Agent 根本没查过：**不是查了没发现，是从未查询**。

**反事实**：人眼审阅只能发现"理由是否充分"，发现不了"反证是否缺席"——缺席没有痕迹。解蔽账本把缺席变成痕迹：`disconfirming[]` 为空 → 蔽值 +15，一目了然。

### 场景 3 · 无证伪的结论（梦剧乱知）

调研任务：Agent 交出结论"我们的瓶颈在序列化层，建议换库"。没有可证伪条件：什么证据出现时这个结论应该作废？没人知道。两周后序列化换了库，瓶颈纹丝不动，结论当初对不对已不可考。

**反事实**："结论"目前是纯自然语言，没有携带自己的死亡条件。虚壹静三门里的"静"门把可证伪条件变成账本必填项：`verdict.falsifiable` 缺失 → 蔽值 +15。**结论必须自带验尸条款。**

### 场景 4 · 伪证据与不可审计（账实脱节）

最隐蔽的一种：账本制度上线后，Agent 在账本里写"方案 B 已测试、被基准测试否证"——但回放会话流，**那个基准测试从未运行过**。判断的产物一旦也可以伪造，账本就退化成新的表面文章。

**反事实**：zhizhi 用"运行时拦截 vs 离线重放逐字一致"证明了行为可对账。jiebi 把对账带进认知层：账本里的每条证据引用必须能在会话流里落到一条真实工具调用，且成败方向一致（`jiebi reconcile`）——**宣称的证据必须真实发生过**。对账机制本身可被测试证伪（注入不一致必须能被查出）。

## 价值论证

1. **判断第一次有了质量单位**：蔽值（occlusion score，0–100）是一个确定性的、可复现的数字，回答一个此前无法回答的问题："这个判断在程序上还有多少被锁死的余地？"——不可测量 → 不可管理。
2. **把去偏从"人品"变成"产物"**：consider-the-opposite / premortem 在心理学里有效的前提是**结构化强制**。jiebi 把强制点放在产物上（账本校验 + CI 门禁），不消耗 token、不依赖模型自觉、模型无关（model-free）。
3. **与 zhizhi 正交，补全治理拼图**：zhizhi 治"手"（动作发生前拦截），jiebi 治"眼"（判断形成后校验）。两者共用同一种会话流格式——jiebi 的审计器可以直接审计 zhizhi 导出的流，一个实验室的两层治理互认账本。
4. **插件层的新能力类型**：zhizhi 证明了插件可以**拦截**；jiebi 证明插件可以**对账判断**——观察式插件（结构上不可能拦截动作）+ 运行时账本注册服务（`ctx.jiebi.check(ledger)` 同步返回蔽值），给"Cordis 生态里治理类插件能做什么"增加了一个新的种类。
5. **可证伪的价值主张**：对一个团队的历史会话跑 `jiebi audit`，能数出多少"单候选连击"窗口、多少无反证判断——价值可以像 zhizhi 一样自证，不靠叙事。

## 伪需求自检清单

| 质疑 | 回应 |
|------|------|
| "模型越来越强，自我批判能力会内建，还需要外挂校验吗？" | 结构性通患不随智力消失：更强的模型意味着更流畅的辩护词，锚定后"看起来更有理"。人类专家也一样——premortem/红队不因为团队聪明而取消。且 jiebi 的成本是一次 CLI 调用，收益是可审计性。 |
| "这不就是 ADR / decision record 模板吗？" | 模板不校验、不对账、不可门禁。jiebi 的三件套是 schema 校验 + 蔽值评分 + 账实对账——模板是纸，jiebi 是闸门。见 docs/01-book.md 第四节。 |
| "用另一个 LLM 当批评家（critic/debate）不行吗？" | 行，但不可复现、有成本、且引入新偏置（critic 自身的 sycophancy 与位置偏置）。jiebi 走确定性路线：零 LLM 调用、可逐字重放、可离线对账。两者互补不互斥，但只有确定性层能当 CI 门禁。 |
| "会不会把 Agent 拖慢？" | 校验对象是**重大判断的产物**（每任务几个），不是每轮对话。一次 `jiebi check` < 10ms。阈门只在 CI/收尾时把关，运行时插件纯观察、零拦截、零延迟。 |
| "蔽值低就是好判断吗？" | 不是。蔽值度量的是"程序上是否还可能被骗"，不度量对错（docs/01-book.md 第五节）。它是必要条件门禁，不是充分条件保证——这个诚实边界写进了设计。 |
| "凭什么说是真实问题？" | 四个场景各对应一类可复现的公开失败模式（锚定/确认偏误/无证伪结论/证据不可审计），且 `jiebi audit` 能对你自己的历史会话量化"单候选连击"与"零反证"窗口——价值主张可自证。 |
| "和 zhizhi 撞车吗？" | 正交：zhizhi 在 tools/pre-execute **拦截动作**（手）；jiebi 全程**零拦截**（插件里根本没有 pre-execute 监听器，结构性保证），只在判断产物上校验（眼）。见方向登记表的边界声明。 |
