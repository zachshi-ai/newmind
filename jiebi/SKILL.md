# 解蔽 · Jiebi —— 判断的产物必须过得了三门

你在长任务里形成的判断（"根因是 X""选方案 A""结论是 Y"）会被下游当作地基施工。
本协议不让你更聪明，只让你的判断**在程序上不可能被一个点锁死**：《荀子·解蔽》的
虚、壹、静三门，落成一份 JSON 账本 + 一次确定性校验。

## 何时必须产出账本

满足任一条，就在宣布最终判断**之前**产出并校验一份账本：

1. **根因诊断**：你准备说"问题的根因是 X"；
2. **方案选型**：你准备在 ≥2 个候选方案里定一个；
3. **结论定稿**：调研/检索任务的最终结论即将交付；
4. **推翻自己**：你要放弃先前结论、另立新论（新判断 = 新账本，引用旧账本 id）。

不适用于：纯执行步骤（改文件、跑命令）、中间试探（那正是你的证据来源）。

## 操作流程

```bash
jiebi template --kind diagnosis > d-001.json   # 1. 拿骨架（kind: diagnosis|approach|conclusion）
# 2. 填写（见下方三门清单）
jiebi check d-001.json                          # 3. 校验：退出码 0 才算过门
jiebi reconcile d-001.json <本会话事件流.jsonl>  # 4. 账实对账：宣称的证据必须真实发生过
```

`check` 退出码 1 = 蔽值超阈（≥30）：**不要宣布结论**，先补齐账本再校验。
`reconcile` 报 `dangling` = 你引用的证据在会话流里不存在——去真的跑那次调用，
或删掉这条宣称。**宣称没发生过的证据是账本的死罪。**

## 三门清单（写账本时逐条自问）

**壹门（兼陈万物）—— `alternatives`**
- ≥2 个候选。第二个候选必须**诚实**——写你不想选的那个里最强的，不是稻草人；
- 每个候选带 `steelman`（它的最强辩护）与 `killCondition`（出现什么证据它就死）；
- 每条 `evidence` 引用会话流里真实调用的 id（如 `t2-c1`），可带 `expect: "fail"|"success"` 声明方向。

**虚门（不以所已臧害所将受）—— `disconfirming`**
- ≥1 条与你的首选**相左**的证据/观察，并写明你如何回应它；
- 如果你真的找不到任何反证，先去制造一次反证尝试（换个角度探一次），再回来填。

**静门（不以梦剧乱知）—— `verdict`**
- `choice` 必须与某个 `alternatives[].name` **逐字一致**；
- `weights`：秤为什么倾向它——显式的比较理由，不是"综合来看"；
- `falsifiable`：什么证据出现时本结论作废。写不出来 = 结论还不配存在。

## 与运行时的关系

- 装了 jiebi 插件的 harness 会自动观察你的探针行为：同一目标换着参数连击 ≥4 次
  会被记 monoculture flag（不拦你，只记账）。flag 不是禁令，是提醒：换个角度探一次。
- `ctx.jiebi.check(ledger)` 可被宿主在其他接缝调用——蔽值是公开的，别赌没人看。

## 诚实边界

蔽值 0 不等于正确。它只保证：你的结论曾在候选竞争中存活、反证被登记并回应、
自带可证伪条件。这三件事让你的错误**可被发现、可被修正**——这就是全部，也不少了。
