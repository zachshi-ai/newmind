# 02 · 问题定义：谁、在什么场景下、有什么问题、价值何在

按「伪需求检验」的顺序写：先给场景和反事实，再给价值，最后自检。

## 目标用户

在 DeepSeek Harness（或任何 Cordis 架构的 Agent 运行时）上**批量下发任务**的工程师与团队：每天给 Agent 派发几十个任务的人，以及给 Agent 任务设 CI 门禁的平台方。他们已经装齐了运行时治理（zhizhi 拦行为、jiebi 审判断、zhengnian 守本愿、buer 记教训），但每个新任务仍然**裸奔着进场**：任务书没有经过任何机器检查，第一枚 token 烧掉的时候，没人知道这场运行的体质如何。

## 四个场景

### 场景 1 · 无验开工（终验缺席——完成将对着空气宣布）

批处理任务："把这 40 个仓库的 license 头补齐"。任务书没有声明任何终验。第 N 轮，Agent 宣布完成，证据是它自己顺手跑的一次 lint。zhizhi 的证据核对会问"**有没有**证据"——有，绿灯；正念的终验门想对账——**契约里根本没有终验可对**。缺的不是执行力，是开工时没人逼着把"什么叫完成"写下来。

**反事实**：任务书模板里的"验收标准"一栏是自愿式的；reviewer 靠眼尖。只有**体检**（acceptance 缺失 → 无验病灶 +45 → 门禁红灯）不可协商，因为它读的是任务书本身，不是任何人的自觉。

### 场景 2 · 无界无止（愿界无穷、止法缺席——漂移从第一个文件就开始）

迁移任务："把代码迁到新框架"。没有 allowRoots——每一处写入都在界内，因为界是无穷大；没有 stop 条款——没有任何人在 t=0 回答"到哪儿算完"。此后的一切治理都迟到：正念的攀缘分结构性沉默（无界则越界不存在），知止的浪费账本只能事后入账。**漂移不是从第 40 轮开始的，是从任务书没写愿界的那一刻开始的。**

**反事实**：愿界与止法必须是开工时声明的**形状**（allowRoots / maxSteps·maxMinutes），体检才能在其缺席时确定性报警；下游层（zhizhi / zhengnian）才有据可执。

### 场景 3 · 妄证缺资（证与资落空——mid-run 才完成的确诊）

任务书终验写着 `--acceptance: artifact=reports/coverage.txt`、依赖写着 `jq`。开工后 Agent 干了 20 轮，直到第一次对账才发现：`reports/` 目录不存在（任务本身也没包含创建它的步骤）、`jq` 不在这台机器的 PATH 里。**全部信息在 t=0 就可测**：一次 `stat`、一次 PATH 扫描，成本纳秒级；现实的确诊方式却是烧掉几十轮 token 后用失败换。

**反事实**：切诊是**只读实测**不是声明信任——artifact 路径 stat 不到 → 妄证 +35；命令不在 PATH → 缺资 +35；两次落空即入病带，门禁红灯。

### 场景 4 · 相克（自相矛盾——预定好的中局爆雷）

任务书同时写着："把 anchors.paths 指向的模块全部重写"与愿界 `allowRoots: ['docs/']`——目标径全在愿界之外；两条终验引用同一个 artifact 路径但断言不同。这两个矛盾在 t=0 用一次前缀匹配与一次去重就能发现；现实里它们在第 50 轮同时到期，Agent 陷入不可恢复的返工，token 双倍烧完，两个要求各完成一半。

**反事实**：相克是**结构可判定**的（径与前缀、引用去重、目标与界的相交），不需要语义理解；体检在开工前把它变成一条医嘱，而不是一场事故。

## 价值论证

1. **t=0 第一次被体检**：Agent 任务的生命周期里，code review 审代码不审任务书，evals 测模型不测单次任务的就绪度，pre-mortem 是会话不是机制——开工时刻的任务书与环境，第一次有了机器检查。
2. **体质第一次有了质量单位**：病值（illness score，0–100）是确定性的、可复现的数字，回答一个此前无法回答的问题："这场运行开工时的体质值几分？"——不可测量 → 不可管理。
3. **插件层的第五种能力类型**：zhizhi 证明插件可以**拦**，jiebi 证明插件可以**审**，zhengnian 证明插件可以**供给**，buer 证明插件可以**记习**（在途）；weibing 证明插件可以**只出诊**——结构性零监听，源码里没有任何事件监听器，不参与任何接缝，只在被问时给出确定性报告。"治理类插件"的第五种姿态：诊断式插件。
4. **医嘱喂给下游三层**：体检不是终点——无验的医嘱是"声明终验"（正念终验门的输入），无界的医嘱是"立愿界"（正念 allowRoots），无止的医嘱是"立止法"（知止层的参数）。体检报告是下游治理层的**预告警与安装说明书**：先有体检，契约才立得住。
5. **可证伪的价值主张**：对团队自己的历史任务书跑 `weibing exam`，能数出多少无验开工、多少妄证缺资、多少相克——每一例都能对回一次真实的 mid-run 失败或一次代偿完成。价值可以自证，不靠叙事。

## 伪需求自检清单

| 质疑 | 回应 |
|------|------|
| "这不就是任务书 linter 吗？" | linter 审的是**代码**与风格的匹配；weibing 审的是**任务书与环境**的匹配（切诊真的去 stat 文件、扫 PATH）加上就绪条款的缺席（无验/无界/无止是"没写"，linter 无法对"缺席"报警，因为没有标准文件可 diff）。更重要的是 linter 没有传变规则与下游医嘱——体检报告指名下游哪一层将失守。 |
| "planning 模式 / 任务模板不就够了吗？" | 它们是自愿式的：模板里的验收栏可以空着提交，plan 可以不带愿界开工——没有度量、没有门禁、没有实测。weibing 的三件事——病灶（缺席与落空有了数字）、探针（声明被实测）、退出码（CI 可拒收）——把好习惯变成机制。 |
| "和 zhengnian 的本愿契约不是重复吗？" | 时序与对象都不同：zhengnian 的契约是**立完之后**守漂移（对象：动作流），weibing 的体检是**契约立得起之前**验就绪（对象：任务书与环境）。恰恰是体检的医嘱在喂契约的形状——无验则终验门无事可对，无界则愿界无处画。先有体检，后有契约。 |
| "开工前用 LLM 看一眼任务书不就行了？" | 三个问题：不可复现（同任务书两次判断可能不同）、有成本（体检环节烧 token 就是已病求药）、不可门禁（LLM 的"我觉得不行"进不了 CI）。weibing 零 LLM：显式词表 + schema + 只读探针，逐字重放。 |
| "病值 40 就拦，探索性任务怎么办？" | 诊而不拦：门禁只是退出码，`--gate` 可调（`--gate 100` 即只报告不拦）。而且"这是探索性任务"本身就该写进任务书——止法声明了吗？探索也可以有 maxSteps。体检不反对任何开工方式，它只要求开工方式被声明。 |
| "词表匹配太粗，体检会漏掉大量病灶？" | 会——诚实边界写死在 docs/01-book.md 第五节：闻诊是显式词表不是语义。weibing 承诺的是：报出来的每一条都可复现、可门禁、可重放；词表可扩展（`--lexicon`），声明权在任务方。确定性与覆盖面分开承诺。 |
| "会不会拖慢开工？" | 体检是纳秒–毫秒级的 stat 与 PATH 扫描加一次字符串匹配，零 LLM、零网络、零子进程；插件零监听，不占用任何接缝。体检的成本与一次 `ls` 同量级。 |
| "和 zhizhi / jiebi / zhengnian / buer 撞车吗？" | 正交且有明确边界（见根 README 方向登记）：四层都在运行开始**之后**工作；weibing 只在 t=0 体检任务书与环境，结构性零监听、诊而不拦；不做动作治理（zhizhi）、不校验判断账本（jiebi）、不度量意图在场（zhengnian）、不管理跨会话学习（buer）。 |
| "凭什么说是真实问题？" | 四个场景各对应一类可指认的公开失败模式：无验收标准的完成宣称（代偿完成，zhengnian 已证）、范围蠕变（同上）、依赖缺失的 mid-run 失败（各家 Agent CLI 的 issue 区高发）、矛盾需求的返工（软件工程经典：shift-left 的成本曲线）。pre-mortem / FMEA / DoR 三个管理学实践的普及本身就是问题的存在证明——但它们都停在人的环节，没有进运行时。 |
