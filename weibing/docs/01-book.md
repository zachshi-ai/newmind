# 01 · 选书：《黄帝内经》——为什么两千年前的"上工"，治的是 2026 年 Agent 最贵的一种烧钱方式：带病开工

## 一、2026 年，Agent 的第四种昂贵失败：不是停不下来，不是想错了，不是忘了本愿——而是**开工那一刻，病就已经在了**

本实验室已上线的四层治理，全部在运行**开始之后**工作：

| 层 | 思想源头 | 治什么 | 工作的时点 |
|---|---|---|---|
| 知止 zhizhi（手） | 《道德经》 | 行为失控：连败死循环、未读先写、无证据宣称完成 | pre-execute 拦截 / 完成时核对 |
| 解蔽 jiebi（眼） | 《荀子·解蔽》 | 判断失真：锚定、确认偏误、不可证伪 | tools/result 审判断账本 |
| 正念 zhengnian（心） | 《六祖坛经》 | 意图漂移：失念、攀缘、代偿完成 | 全程度量 + 接缝供给 |
| 不贰 buer（习，在途） | 《论语》"不贰过" | 重蹈覆辙：同样的错跨会话再犯 | 事故过账后 |

四层合起来，一个 Agent 运行时的"手、眼、心、习"都有了看护。但跑过几十个 Agent 任务的人都知道还有第五种下午：**任务书发下去的那一刻，这场运行就已经注定失败**——只是病还没发作。

- 任务书没写终验：完成将由 Agent 自选的轻量检查宣布（正念的终验门将无事可对，zhizhi 的证据核对将无据可核）；
- 任务书没立愿界：范围从第一个文件起就是无穷大（正念的攀缘分结构性沉默——"愿界之外不存在，越界也就不存在"）；
- 任务书没立止法：没有任何人在 t=0 问过一句"到哪儿算完"；
- 终验写的 `npm test` 在这个环境里根本没有 npm，终验写的报告目录根本不存在；
- 任务书自相矛盾："迁移到 v2" 与 "不得改动 src/" 互斥，注定在第 50 轮同时到期。

这些病有一个共同的残酷特征：**在开工时刻全部无症状，却决定了中局与终局**。Agent 会在第 3 轮才发现命令不存在，在第 50 轮才撞上矛盾——而发现的方式是最贵的那种：烧掉几十轮 token 之后，用自己的失败来确诊。《黄帝内经》对这种确诊方式有一句两千年的差评：

> 夫病已成而后药之，乱已成而后治之，譬犹**渴而穿井，斗而铸锥**，不亦晚乎！（《素问·四气调神大论》）

## 二、为什么是这本书

《黄帝内经》是中医理论的奠基经典，医道同源的思想原典。它对"何时治"的立场极其强硬，且给了三条可直接工程化的条款：

### 2.1 原文条款 → Agent 失败模式逐条对照

| 原典 | 直译 | Agent 的病 |
|---|---|---|
| **圣人不治已病治未病，不治已乱治未乱**（《素问·四气调神大论》） | 圣人不在得病后才医治，而在未病时治理 | 全行业的治理预算花在"恢复"上：重试、重规划、self-healing、compaction——全是已病之治；开工时刻的任务书与环境，**无人体检** |
| 夫病已成而后药之……**渴而穿井，斗而铸锥，不亦晚乎**（同上） | 渴了才挖井，开战才铸兵器，不晚吗 | 第 47 轮才发现 `jq` 没装、终验目录不在——用最贵的方式（mid-run 失败）完成本可在 t=0 完成的确诊 |
| **上工救其萌芽……下工救其已成，救其已败**（《素问·八正神明论》） | 上工在病症萌芽时救，下工在已成已败时救 | 任务书里"所有文件都优化一遍"这类无边措辞是萌芽期的病灶——单条不致命，攒起来就是一场大病；现无任何机制度量它 |
| **上工治未病，不治已病**（《灵枢·逆顺》） | 上工治未病 | 同一规律的另一表述：治理的重心应该在运行开始**之前** |
| **望而知之谓之神，闻而知之谓之圣，问而知之谓之工，切脉而知之谓之巧**（《难经·六十一难》，四诊传统的定型） | 四种由表及里的诊断 | 体检必须是**分层确定性**的：望（环境事实）、闻（任务书措辞信号）、问（就绪条款是否声明）、切（只读探针实测）——而不是一次语义生成的"感觉" |
| **见肝之病，知肝传脾，当先实脾**（《金匮要略》开篇，张仲景对"上工治未病"的展开） | 见肝病就知道会传脾，先把脾实了 | 病灶有**传变**：无验之愿注定代偿完成，无界之愿注定攀缘失度——开工前就应预告下游哪一层将失守 |
| 魏文王之问扁鹊：**长兄治病，治病于病情未发之前**……故名声不出于家（《鹖冠子·世贤》） | 最高的医术治未发之病，因此默默无闻 | 行业庆祝的是"Agent 自我恢复"（扁鹊之名闻天下），没有人给"从未生病的运行"记账——体检报告就是那本没人记的账 |

### 2.2 治未病三义 → 本层的取舍

古典对治未病有三层含义，本层取前两义、把第三义划给已有的层：

1. **未病先防**（运行开始前体检）——weibing 的主战场：`weibing exam` 在第一枚 token 之前完成；
2. **欲病救萌**（萌芽信号度量的不是对错，是风险）——险兆词表只计分不开药方式的禁令，萌级任务可以开工；
3. **既病防变**（得病后防传变）——这是运行时各层的地盘：zhizhi 拦、jiebi 审、zhengnian 供、buer 记。weibing 明确不进运行时。

### 2.3 扁鹊三兄弟 → 一次价值重估

行业叙事偏爱扁鹊：Agent 卡死了，它自己恢复了——起死回生，名闻天下。长兄的工作没有故事：任务书在开工前被体检出两处病灶，改了，任务平平无奇地一次跑通。weibing 的立场：**治理的至高处是无事**，体检报告要给"从未生病的运行"记上那笔没人记的账。

## 三、管理学与工程侧写（同一规律的另外三种语言）

- **Pre-mortem**（Gary Klein，HBR 2007 "Performing a Project Premortem"）：在项目开始前假设"已经失败，回看死因"，被证明显著提高风险识别率——但它是**人的会议**，不在运行时里，无法门禁。weibing 把 pre-mortem 的"事前回看"下沉为确定性探针。
- **FMEA**（失效模式与影响分析，质量管理学）：对每种失效模式先定"检测手段"，再定权重与处置——病灶表（W1–W6）的权重与上限就是一张 FMEA 表。
- **Definition of Ready**（敏捷管理学）：任务进入执行前必须"就绪"（有验收、有边界、有依赖）——但 scrum 的 DoR 靠人肉站会执行，Agent 运行时里没有任何对应的机器检查。weibing 是 Agent 任务的**机器 DoR**。
- **Shift-left**（软件工程）：缺陷发现得越晚，修复成本越高——对 Agent 尤甚：mid-run 发现任务不可行，烧掉的每一轮 token 都是纯亏损。
- **长时程可靠性断崖**（METR，2025，arXiv:2503.14499）：时程越长，偏离与崩坏越显著——开工时刻的体质决定这条断崖的起点在哪。

**结论一致：对抗"带病开工"靠的是开工前的确定性体检，不是更聪明的 Agent，也不是更恳切的任务书。**

## 四、与提示词方案的根本区别（为什么这不只是一个"任务书检查清单"）

1. **清单不实测，weibing 实测**：任务书模板与 review 清单是原则——原则会被违反。weibing 的切诊是真的去 `PATH` 里找那个命令、真的去 `--cwd` 下看那个目录：声明了而落空 → 妄证计分，第一次有了实据。
2. **清单无门禁，病值有 CI 门**：`weibing exam` 病值超阈退出码 1——"带病开工"第一次可以被 CI 拒收，而不是靠 reviewer 眼尖。
3. **清单无传变**：单条缺陷的后果是局部的，weibing 的传变规则回答"这个病灶会烧到哪一层"——无验 → 正念终验门失守，无界 → 攀缘分失守。体检报告因此不只是体检，还是下游各层的**预告警**。
4. **零 LLM 调用**：不用另一个 LLM 判断"这个任务书行不行"——不可复现、有成本，且在体检环节烧 LLM 本身就是"已病求药"。四诊全部是显式词表、schema 校验与只读探针：可逐字重放。

## 五、一个诚实的边界

- **词表不是语义**：闻诊的险兆来自显式词表匹配（无边之词、无度之动词），不是 NLP——聪明的任务书作者可以写出体检不认识的病句，正如症状可以从容地骗过望诊。词表可由用户扩展（`--lexicon`），这是"声明权在人"的诚实设计，不是语义理解的伪装。
- **诊而不拦**：weibing 的门禁只是一个退出码；拦不拦由 CI 与宿主决定。插件结构性零监听——源码里没有任何事件监听器，运行时各接缝它都不在场。
- **未病不保证成功**：病值 0 是必要条件，不是充分条件。体检保证三件事：**就绪条款有了机器可读的形状；带病开工有了确定性的数字；每个病灶有一条可执行的医嘱。**
