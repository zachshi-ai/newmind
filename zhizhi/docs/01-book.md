# 01 · 选书：《道德经》——为什么一部两千五百年前的书，回答的是 2026 年最新的问题

## 一、2026 年，Agent 的病从"不够聪明"变成了"行为失控"

Agent 基础设施在 2025–2026 年发生了决定性变化：模型推理与工具调用精度跨过生产阈值，DeepSeek Harness（"Everything is a plugin"）等运行时把"模型 + 挂具"变成标准架构，智能体开始整夜自主跑测试修复循环、迁移、批量重构。

于是失败模式换了一批。**今天烧钱最多的不是"不会做"，而是"停不下来、管不住手、不敢担保"**：

1. **打转（thrash）**：同一命令连续失败，Agent 原样重试，六七次之后才被人工叫停；
2. **盲写**：对从未读过的文件直接 edit/str_replace，靠猜写匹配串；
3. **轻诺**：没跑过任何验证就宣布"完成"，下游基于这个"完成"继续施工。

这三个病的共同点：**都不是智力问题，是行动的经济学问题——何时该动、何时该停、动作的代价由谁买单。**

## 二、为什么是这本书

候选很多：德鲁克《卓有成效的管理者》（效能先于效率）、《系统之美》（杠杆点）、禅宗（念起即觉）。最终选《道德经》，因为它不是泛泛地谈"节制"，而是给了**三条可以直接工程化的行动纪律**，且每一条都能逐字落到 Agent 运行时的接缝上：

| 原文 | 直译 | 工程化翻译 |
|---|---|---|
| **知止可以不殆**（三十二章）/ 知足不辱，知止不殆（四十四章） | 知道止境，才可以长久不危 | Agent 必须有结构性的"止境"：同一动作反复失败到达阈值，必须停——不是靠它"想通了"，是靠闸门 |
| **为之于未有，治之于未乱**（六十四章） | 在未发生时处理，在未混乱时治理 | 拦截必须发生在动作**之前**（pre-execute），不是事后统计 |
| **轻诺必寡信，多易必多难**（六十三章） | 轻易许诺必然少有信用 | "完成"是许诺。没有验证证据的"完成"，必须在账本里现形 |
| **无为而无不为**（四十八章） | 不妄为，则没有什么做不成的 | 中间层最好的形态是不发电：零 LLM 调用、零提示词注入、零语义判断——用结构约束，不用智能说教 |
| **多言数穷，不如守中**（五章） | 说得越多，越快穷竭 | 每拦下一次失败重试，省掉的是一整轮模型往返（请求 + 响应 + 全量上下文重算） |
| **自知者明**（三十三章） | 认识自己才算高明 | 知止账本：Agent（和它的人）第一次能看见自己的行为模式 |

## 三、管理学侧写（同一规律的两种语言）

- 德鲁克：*"There is nothing so useless as doing efficiently that which should not be done at all."*（高效率地做不该做的事，是最无用的事。）——Agent 打转正是"高效地做不该做的事"。
- 丰田生产方式的**安灯绳**（Andon Cord）：任何工人有权拉停整条产线，因为"带缺陷的继续生产"是最昂贵的浪费。知止门就是 Agent 的安灯绳：失败积累到阈值，拉闸。

一本道家经典与一套现代工厂制度在同一个判断上汇合：**让系统停下来，是系统里最贵的能力，必须制度化地赋予，而不能指望当事人临场自觉。**

## 四、一个诚实的边界

《道德经》不承诺"止了就对"。知止拦下的动作可能本来就会成功（阈值误伤），放过的动作可能才是灾难（漏拦）。所以本项目的每一层都保留了可证伪性：阈值可配置、拦截必带理由、账本全量可导出、运行时与离线重放必须逐字一致（对账机制本身可以被测试证伪）。

**知止不保证正确，知止只保证：同样的错误不会被原样重复购买第二次。**
