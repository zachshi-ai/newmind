# 02 · 问题定义：谁、在什么场景下、有什么问题、价值何在

按「伪需求检验」的顺序写：先给场景和反事实，再给价值，最后自检。

## 目标用户

在 DeepSeek Harness（或任何 Cordis 架构的 Agent 运行时）上跑**长任务**的工程师与团队：让 Agent 自主执行测试修复循环、依赖升级、批量重构、迁移脚本的人。他们已经过了"Agent 能不能干活"的阶段，正在为"Agent 干活的方式太贵、太不可信"付账。

## 四个场景

### 场景 1 · 打转（thrash）

Agent 跑一次测试 → 失败 → 改一行 → 再跑 → **同样的失败** → 再改再跑……同一个测试命令连续失败六七次，烧掉几万 token，直到人看不下去手动叫停。

**反事实**：没有止损层时，没有任何机制区分"第 2 次重试"和"第 9 次重试"——对 Agent 来说它们一模一样。提示词里写"不要重复无效操作"属于**原则**——原则会被违反；只有**触发器**（"同一指纹连败 ≥ 3 → 拒绝"）不可能被违反。这正是 harness-fields 的核心洞察，本项目把它从文档层下沉到运行时。

### 场景 2 · 盲写

Agent 对一个本会话从未读过的文件直接执行 edit/str_replace——它在对文件内容**猜测**。猜对了是运气，猜错了浪费一轮往返，更坏的情况是写坏文件。

**反事实**：现有 harness 的文件编辑工具各有本地校验（如要求先 read），但 bash 重定向（`echo x > file`、`sed -i`、`tee`）完全绕开这层约束。知止把"读过"作为跨工具、跨调用形态的会话级状态。

### 场景 3 · 轻诺

Agent 的最后一句话是"Done! 问题已修复。"——但这一个 turn 里没有跑过任何测试、构建或 lint。下游同事基于这句话继续施工，半小时后发现地基是空的。

**反事实**："完成"目前是纯自然语言声明，没有任何证据门槛。知止不判断语义（那要靠模型），它只做确定性记账：**验证性命令的成功执行 = 证据**；一个 turn 内证据为零，账本直接点名（`unverifiedTurns`），CI 门（`--fail-on-unverified`）可以让这种"完成"在流水线里红灯。

### 场景 4 · 不可见

以上三种浪费每天都在发生，但没有任何账本——团队说不清自己的 Agent 有多少动作是被浪费的，自然也无从改进。

**反事实**：不可测量 → 不可管理。知止账本把每次拦截、每次放行、每个无证据 turn 记成 JSON 账本，what-if 审计还能对历史会话回答"如果当时装了知止会怎样"。

## 价值论证

1. **直接省的钱可计算**：每次拦截发生在 pre-execute——模型还没看到失败结果、还没生成下一次调用。一次拦截 = 省一轮完整模型往返（长上下文 Agent 单轮轻松数千至数万 token + 数十秒延迟）。账本单位是诚实的"轮模型往返"，不编造 token 数。
2. **结构性价值**：把"原则会被违反，触发器不会"从协作方法论下沉为运行时代码约束——约束不再依赖 Agent 的记性与自觉。
3. **生态价值**：只用 DeepSeek Harness 的公开接缝（`tools/pre-execute` waterfall、`tools/result` 事件、服务注册），不 fork 不改源码，是"Everything is a plugin"哲学的第三方治理能力实证。
4. **方向价值**：Agent 领域当前的瓶颈不是能力上限而是可靠性下限。让 Agent 从"行动力更强"走向"行动更可信"，是引领而非跟风。

## 伪需求自检清单

| 质疑 | 回应 |
|------|------|
| "Agent 模型越来越聪明，还需要外挂约束吗？" | 越强的自主性越需要结构性刹车。丰田安灯绳不因为工人技能提升而拆掉；约束的成本近乎为零（确定性规则），收益随任务时长线性增长。 |
| "拦截错了怎么办？" | 只罚"连续失败的同指纹重试"，单次失败永不拦截；阈值可配置；拦截必附完整失败历史与换路建议；全程 fail-open——门自身故障时放行并留痕。 |
| "凭什么说是真实问题？" | 每条规则对应一个可复现的公开失败模式（thrash / blind write / unverified completion），且 what-if 审计可以对**你自己的历史会话**量化"本可拦截 N 次"——价值主张可自证。 |
| "为什么不放进 prompt / 系统提示词？" | 提示词是原则，原则会被违反；且提示词方案每次都要消耗 token 重复说教。知止零提示词、零 LLM 调用，拦截发生时模型反而收到一条更短的、确定性的教学信息。 |
| "做完了会不会没人用？" | 这是价值问题不是真伪问题。本仓库的承诺是"问题真实、机制可验证、账本诚实"，采用与否交给 measurable 的 audit 结果说话。 |
