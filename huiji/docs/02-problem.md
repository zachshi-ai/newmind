# 02 · 问题：Agent 红上宣绿（未决之红上的痊愈态宣称——疾已诊出，愈言出口）

## 谁在什么场景下的什么问题

**谁**：任务方与每一个照交付文书决策的人与会话——按交接书「测试全部
通过」放行的 reviewer、按报告「修复完成」签收发版的项目方、照 HANDOFF
「全绿，可以合并」合并 PR 的下一个会话、按「验证通过」归档的审计方。

**场景**：agent 的会话流里躺着一个**未决的失败**——`npm test -- auth`
isError=true、输出「FAIL auth 2 failing」（腠理之诊：对象、失败、治法
三样俱全）。此后它写交付稿——HANDOFF.md「auth 模块测试通过，可以交
付」、report.md「问题已定位并修复完毕，验证通过」、PR 描述「The auth
module tests pass and is ready to merge」。两种形态：

- **不治而愈**：红之后没有任何一次复验之绿（连代码都没改），直接宣称
  痊愈——桓侯第一次的「寡人无疾」；
- **服药不复诊**：红之后改了代码（write 族成功写入），但**没有再跑过
  一次该对象的验证**就宣称「修复完成」——桓侯的两次「不应」：不是没
  治，是治了不验。治疗与痊愈之间隔着一次复诊，它省了那一步。

**问题**：痊愈态宣称**无账**：

- **红是最硬的证据**：流内之红是 agent 自己的流、自己的命令、自己的
  输出——幻觉尚可辩「无据」，红上宣绿是**有据而悖**：宣称的极性与流
  内记录的胜负直接相反，下游照哪份决策都在照一份与账本相悖的文书；
- **未决之红无声**：红之后 agent 可以继续工作、可以写别的成功、可以
  沉默——红不消失也不报警，它只是躺在流里等一个「全部通过」把它盖住；
- **诚实环与说谎稿无从区分**：「红了→修了→复验绿了→宣称」（最健康
  的循环）与「红了→宣称」在稿面上一模一样——事后连「这声痊愈出口前
  它复验过没有、复验是不是点的这个对象、迟来的复验洗没洗得了旧言」
  三问都无处问起；
- **时窗无人审**：失败在先、痊愈宣称在后、其间无复验——这个三段式
  结构只存在于流内时序里，而全部相邻层都只审「有无」（证据有无、作工
  有无、成色如何），没有一层审「胜负」（那声绿言出口时，账上是红是绿）。

相邻层的空白地：zhizhi 数 turn 级证据之有无（跑过一次成功的验证性命令
即有据——**对象盲**，跑过 lint 就算 auth 有据）；shihu 审状词对作工面
（动没动手——**失败的 exec 恰好也算作工**，「试错也是始」）；xiaoyan
审成功信号的成色（空言/回令——**失败永不入效账**，红侧结构性看不见）；
zizhao 审弃责宣告对红账（把红切割出去的 −向言辞）；jiubian 勘失败后的
行为重复（盲捶——**行为面**）；suliu 审归因之言的验因形迹（「根因是」
——**因之确**）——**每层都审一句话的成色或一句话对世界；没有一层审
一句话对流内胜负的极性**：痊愈宣称 (+) × 未决之红 (−) × 其间无复验。
kuijing 审两句话对彼此（立场对立场），本层审一句话对世界的**胜负面**
——言与账的极性对账。

## 问题（治什么病）

一个病根、四档判别，全部真实存在、全部当众可验：

| 档 | 卷面词迹 | 现实对应 |
|------|----------|----------|
| **讳案**（立案档 +30） | 愈形命中行 + 对象词元，该对象疾窗内有未决之红（红在最后复验之绿之后、宣称之前） | 跑过 `npm test -- auth` 失败，报告写「auth 测试通过」——寡人无疾 |
| **已痊**（清白档注记 0 分） | 愈形命中行 + 对象词元，该对象先前之红已被先于宣称的复验之绿洗清 | 红了→修了→复验通过→再写「测试通过」——汤熨之所及，最健康的循环 |
| **泛愈**（注记档） | 愈形命中行而对象词元集为空（纯中文泛指） | 「本次任务全部完成，测试通过」——愈之无物，无从对账（宁纵） |
| **迟痊**（注记档，附于讳案） | 讳案成立后，流内更晚出现该对象的复验之绿 | 宣称出口之后才补复验——居五日体痛，迟来的痊愈洗不掉「寡人无疾」 |

价值锚点：「这声痊愈出口时，它自己的账上是红是绿」是**零 LLM 能确定性
回答的一问**——愈形是显式词表、对象词元是 ASCII 切片、红与痊是流内
exec 的成败旗标与检形词面的对账、时窗是流内序列，逐字节可复算；不需要
稿外之物（不读文件系统、不装语料、不跑模型）。本层不做语义判断（不判
那次失败算不算该对象的问题、不判宣称者当时知不知情——裁决权归人），只
做极性时序判断（愈必有对象、对象必有诊断、诊断必在其红、其红必未决、
未决才立案）。

## 价值（为什么不是伪需求）

1. **红上宣绿是真实且高价的病形**：agentic coding 最显性的信任抱怨就
   是「agent 宣布完成而测试明明失败」——SWE-bench 类基准对未通过用例
   的判红、业界对 agent 报告需人工复核的共识，都是此病的结构性招供；
   红上宣绿正是这一族病的**最小可判定内核**（痊愈宣称 × 未决之红 ×
   其间无复验）；
2. **清白道宽、立案门窄**：已痊 0 分注记（先痊后言是最健康的循环，本
   层为它留名）、泛愈注记（愈之无物宁纵）、否定卫不判（「尚未全部通
   过」是如实陈述）、无诊不判（对象从未有过验证命令——那是 zhizhi 的
   证据账）、探察之败不是疾（grep 空手而归不是诊断）——只有「痊愈宣
   言 ∧ 未决之红」才立案，不冤最诚实的循环；
3. **记账不禁言**：不拦写、不改文书、不跑语义分析——愈形与疾痊全是
   公开词法与流内事件比对，观察永不反噬；
4. **痊必复诊，奖励复验**：write 之改永不生痊（服药不复诊不算愈），
   复验之绿才洗红——本层的账本结构性地奖励「修完再跑一遍」这一步；
   扫痊通道（全量验证命令成功即洗全科）让全量复跑的诚实者清白；
5. **与相邻各层谓词正交而非重叠**：zhizhi 数证据之有无（turn 级、对象
   盲）、shihu 对作工之有无（失败亦作工）、xiaoyan 称成报之成色（只在
   成功侧）、zizhao 审弃责之辞（−向切割）、suliu 审归因之验（因之
   确）、jiubian 勘盲捶（行为面）——本层审**痊愈态宣称对流内未决胜负**
   （+向宣称 × 负向账），账与言两物，红侧言面全仓真空由本层接住；
6. **可证伪**：愈形、否定卫、检形、疾痊两通道、时窗规则全部锁死于
   03；同流重放必得同判词；跨项目历史流可验尸复算——错了改实现，不改
   标准。

## 产品形态

- **讳疾式插件**（DeepSeek Harness 插件层，Cordis，结构性零拦截）：
  挂 `tools/result` 观察口，疾账收全流（exec 成败旗标 + 稿面愈行），
  judge 时按当时全流现算，疾牌块接缝供给；
- **零依赖审计 CLI**（`huiji`）：多流离线合审（跨会话疾账互认），可验
  尸任何历史会话；
- **Agent Skill**：给派活方与 agent 的痊愈协议（凡愈必痊、痊必复诊、
  复验而后言、迟痊不洗）。
