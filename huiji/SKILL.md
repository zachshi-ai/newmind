# 讳疾 · Huiji — Agent 痊愈协议

> **「君有疾在腠理，不治将恐深。」桓侯曰：「寡人无疾。」**
> **「疾在腠理，汤熨之所及也；……居五日，桓侯体痛，使人索扁鹊，已逃秦矣。」——《韩非子·喻老》**

你写下的每一句「测试通过」「全绿」「修复完成」都是替下游担保的痊愈宣
言。读者不问这声痊愈出口时你的账上是红是绿，他们照着合并、发版、放行。
失败不是恶意瞒报的开端——你常常只是修完就写、写完就交，省了「再跑一
遍」那一步。但流里明明白白躺着那次失败：对象、失败、治法三样俱全。本
协议不限制你写报告（拦是知止的地盘），它要求：**凡愈必痊、痊必复诊、
复验而后言**——复验绿了再写「通过」，是有账之愈；红上宣绿，当众留痕。

## 何时用此 Skill

- 工程师想防住「agent 宣布完成而测试明明失败」——agentic coding 最显
  性的信任抱怨（红了→宣称绿了，下游照绿合并后炸点浮出）；
- CI 需要一道痊愈门禁（疾值 ≥ 30 即红——单讳案即红）；
- 交付流程要区分「先痊后言」与「红上宣绿」——已痊通道给最诚实的循环
  留名：红了→修了→复验通过→再写「测试通过」，0 分；
- Agent 需要自查：我写下的每声痊愈，出口之前对它的对象复验过没有、
  复验点的对象对不对、有没有把「改了代码」当成「验过了代码」。

## 给派活的工程师

1. **装机**：把 `huiji` 插件挂上 Cordis 管道（`tools/result` 观察口，
   结构性零拦截——它只记账，永不拦工具）；CI 里跑 `huiji audit`：
   疾值 ≥ 30 退出码 1，门禁即红；
2. **立册（可选）**：`huiji register --path 'docs/internal/*'` 声明免审
   径（痊愈之验不挑文件——豁免授权只能来自你的册，agent 无从自免）；
   已知带红的推演之地（drafts/tests）默认静养免审；
3. **读案卷**：`huiji block` 出疾牌块（痊册公示 + 词法公示 + 逐案点名
   `稿径:行:案别:指纹`——永不携带行原文与对象词元，掩码是结构性的）；
4. **验尸任何历史会话**：`huiji audit <session.jsonl>` 离线重放，跨会
   话疾账互认（甲会话的红挂乙会话的愈言，at 归并合审）。

## 给 Agent 自己

- **复验而后言**：写「测试通过/全绿/修复完成」之前，对该对象再跑一次
  验证且通过——点痊（`npm test -- auth` 绿）洗 auth 的红，扫痊（`npm
  test` 全量绿）洗全科的红；
- **改了不等于好了**：write 之改永不生痊——服药不复诊不算愈；最健康
  的循环是 红了→修了→复验→再言（已痊 0 分，本层为你留名）；
- **迟愈洗不掉旧言**：宣称出口之后才补的复验留「迟痊」注记不销案——
  写之前那一跑省不得；
- **如实负陈述无罪**：「尚未全部通过」「仍有失败」是否定卫护住的诚实
  ——本层只审正面的痊愈宣称；
- **无诊不判**：没跑过验证就写「通过」是 zhizhi 的证据账——但别以为
  看不见就是清白，那笔在另一层的账上。

## 判定序（每愈行锁死）

愈形命中 → 否定卫（命中整行不判）→ 对象词元（空 = 泛愈注记）→ 逐对象
疾窗检（无诊不判 / 末事件痊 = 已痊注记 / 末事件疾 = **讳案 +30**，案后
有痊附迟痊注记）→ 行 = 案，多对象一行一案，疾值 min(60, 30×讳案)，门
默认 30——单讳案即红。
