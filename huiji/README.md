# 讳疾 · huiji —— DeepSeek Harness 的红上宣绿治理层

> 《韩非子·喻老》扁鹊见蔡桓公 × Agent 红上宣绿（未决之红上的痊愈态宣称）
>
> 「扁鹊曰：『**君有疾在腠理，不治将恐深。**』桓侯曰：『**寡人无疾。**』」
>
> 「疾在腠理，**汤熨之所及也**……居五日，桓侯体痛，使人索扁鹊，已逃秦矣。」

agent 的会话流里躺着一个未决的失败——`npm test -- auth` 退出码非零，
输出明明白白写着「FAIL auth 2 failing」（**腠理之诊：对象、失败、治法
三样俱全**）——然后它在交付报告/交接书里写「auth 模块测试通过，可以交
付」（**寡人无疾**）。另一种更常见的形态：跑过失败、改了几笔代码（吃
药），但**没有复验**（没有复诊）就写「修复完成」。流内之红是它自己的流、
自己的命令、自己的输出——幻觉尚可辩「无据」，红上宣绿是**有据而悖**。
假痊愈也没有恶意，只是没有人逼它**出示痊愈出口时账上的胜负**。讳疾就
是那个逼问者。

- 它只判一件零 LLM 能确定性回答的事：**这声痊愈出口时，它自己的账上是
  红是绿**——愈形是显式词表、红与痊是流内 exec 的成败旗标与检形词面
  的对账、时窗是流内序列；
- **凡愈必痊**：痊愈宣称的对象在流内有未决之红（红在最后复验之绿之后、
  宣称之前）→ **讳案 +30 单案即红**（寡人无疾）；
- **痊必复诊**：write 之改永不生痊（服药不复诊不算愈），**复验之绿**
  才洗红——点痊（复验点的就是它）与扫痊（全量复跑洗全科，`npm test`
  裸跑即白）两通道；先痊后言 = **已痊 0 分注记**（最健康的循环，本层
  为它留名）；迟来的复验 = **迟痊注记不洗案**（居五日体痛，迟愈洗不掉
  寡人无疾）；
- **无诊不判**：对象从未跑过验证命令——那是 zhizhi 的证据账；探察之败
  （grep 空手而归）不是疾——只有检形（test/lint/build 44 形）的失败才
  是诊断；
- 只审愈形（测试通过/全部通过/全绿/修复完成/verified/tests pass 等
  复合痊愈词迹 13∪14）——工作态形（已完成/已修复/done）归 shihu，
  风险放行形归 kuijing，切割之辞归 zizhao，词表零交集；静养（tests/
  drafts 等名段）与痊册明言之径免审。

## 快速开始

```bash
npm install                      # devDependencies 供集成验证；CLI 本体零依赖
node src/bin/huiji.js audit fixtures/huiji-stream.jsonl; echo $?   # 1（单讳案 30 红）
node src/bin/huiji.js audit fixtures/yukuang-stream.jsonl; echo $? # 0（已痊·先痊后言）
node src/bin/huiji.js audit fixtures/chiyu-stream.jsonl; echo $?   # 1（迟痊不洗）

npm test                         # 65 tests（core 38 + cli 16 + 真实管道集成 12）
```

CLI：

```bash
huiji audit <s1.jsonl> [s2.jsonl …] [--file <痊册>] [--gate n] [--json]
huiji register --path <glob>     # 立免审（推演/草稿性质文书，重复去重）
huiji revoke --path <glob>
huiji list / block / gate --value <n>
```

## 判定速查

| 档 | 词迹 | 分值 | 经义 |
|---|---|---|---|
| 讳案 | 愈形 ∧ 对象疾窗内有未决之红 | +30/案（单案即红） | 桓侯曰：寡人无疾 |
| 已痊 | 愈形 ∧ 先痊后言（红已被先于宣称的复验之绿洗清） | 注记 0 分 | 汤熨之所及 |
| 迟痊 | 讳案成立后流内才出现复验之绿 | 注记 0 分（不洗案） | 居五日体痛 |
| 泛愈 | 愈形命中 ∧ 对象词元空 | 注记 0 分 | 愈之无物，宁纵 |

疾值 = min(60, 30×讳案)；分带 安 0–14 / 恙 15–29 / 疾 ≥30，门默认 30。
