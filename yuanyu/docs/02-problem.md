# 02 · 问题：Agent 敏感面装载失账

## 谁在什么场景下的什么问题

**谁**：任何在真实仓库里干活的 DeepSeek Harness agent 会话——以及事后要为这份会话负责的人（工程负责人、安全合规、下一个接手的会话）。

**场景**：调试一个鉴权失败，agent 决定「先看看环境配置」：`cat .env`。探索未知仓库，`ls ~/.ssh`、翻 `keys/server.pem`、开 `.npmrc`。每一眼都是真实的装载——密钥、令牌、凭据从暗处进入上下文窗口与会话 transcript，随之进入：会话日志与归档、贴进 issue 与聊天群的「会话记录」、下游模型服务商的留存、以及后续轮次的摘要压缩。**什么都没偷出去，但每一件都已经是既成事实。**

**问题**：事后连「哪次装载、看了哪类密物、是不是本职」都无处问起。仓库侧有 gitleaks/trufflehog 把守入库，出境侧有各层闸门，唯独**会话的入目侧没有任何账**：

- baihe（捭阖）明言「装载不入账，手里有物不罚」——它管的是物的**出境**，装载是被它显式豁免的；
- lunshi（论世）管的是输入内容的**发令资格**（注入），不管内容敏不敏感；
- youya（有涯）记装载是为了抓**重读之费**，shenqu（审曲）称装载的**残全**——都不问「该不该看」。

「入目之禁」全仓无账。这四个字就是本层的全部立足点：**已交付的 24 层里没有任何一层在称这件事，且其中一层（捭阖）在自己的边界行里显式把它让了出来。**

## 价值与意义

1. **transcript 的可认证性**。会话记录日益成为交付物（贴 issue、进归档、跨团队复盘）。「本会话未装载任何未登记密物——渊值 0，澄」是一句今天任何工具都开不出的证明。
2. **把「看」变成可治理的量**。装载入账后，密物暴露从「事后追忆有没有看过 .env」变成一行可 grep 的账：径、形、案别、指纹。
3. **近泄露的确定性证据链**。转运判定（密值在后续写入/命令词面逐字重现）把「密物进了上下文」升级为「密物流进了交付物」——这是可以拿给任何安全复盘会看的硬证据，带指纹不带原文。
4. **给下一个会话干净的现场**。鉴牌块在接缝处公示视账，接手者不必通读 transcript 就知道上一双手看过哪些暗处。

## 伪需求自检

- **「agent 看了 .env 又怎样，模型商反正看得到代码」**——不成立：装载与否是量的差别（密钥明文进 transcript/归档/分享件 vs 代码库里没有的密物根本无从出现），且本层不拦不判罪，只让这一眼留痕有价。
- **「gitleaks 已经做了」**——不成立：gitleaks 扫的是**仓库入库**，本层审的是**会话装载**；一个在 git 侧，一个在会话侧，对象、时点、出口都不同。
- **「拦住不就行了吗」**——不成立：拦是 zhizhi 的地盘且已被占；账与闸分治是全仓既立的结构性共识（审批制之外开备案制），本层延续之——看就看了，留痕、计分、过门。
- **「等等语义判断会更准」**——拒绝：词形显式可配、零 LLM 是全仓红线；词法可欺但骗一次留一次形。
