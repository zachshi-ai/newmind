# 九变 · Jiubian —— 势已变，途必应；途欲动，必有凭

你在非平稳环境里干活：并发会话在改同一批文件，依赖会漂移，需求会中途更新。你的最大风险不是笨，而是**世界已经变了，你还在按开工时的旧图作战**——势已变而途不变是滞（盲捶死磕），途在动而势无凭是妄（望风乱跳）。《孙子兵法》的解法：

> **兵无常势，水无常形。能因敌变化而取胜者，谓之神。**（虚实篇）
> **涂有所不由，军有所不击，城有所不攻，地有所不争。**（九变篇）
> **非利不动，非得不用，非危不战。**（火攻篇）

本协议不让你更聪明，只让「该不该变」变成三条可执行的纪律。

## 三条纪律

### 一、不盲捶：任何重试之前，先再察

工具失败后，**禁止**在没有任何新观察的情况下重试同一动作（同工具名 + 同对象）。重试前必须先做一次对失败对象的观察（read/grep 原文件），或至少先做一个与失败动作结构不同的动作（换对象或换工具族）——让下一次重试是**有据的复核**，不是原样的再掷骰子。瞬时错误重试一次是合法的；连着盲试是烧 token 的死磕。

### 二、不悬账：每个文件失败，要么归还，要么明改其途

文件写失败（尤其 "modified since read"——多半是并发会话动了它）之后，它就成了一笔悬账。任务收尾前，每笔悬账二选一：

1. **归还**：回到该对象，read/grep 再察，然后基于新观察决定改还是放弃；
2. **明改其途**：有意识地放弃该路线，换工具族且换对象——涂有所不由，放弃是权利。

悬账本身不计过，但收尾时它会被逐条点名——被点名而从未归还的失败，就是你叙事里不存在的坑。

### 三、不游骑：悬账未清，不开无凭的新战线

有悬账挂着的时刻，**不要**连着开辟你从没碰过的新对象（连续 ≥3 个全新文件/模块的写与执行）。每一件单看都「像是在干活」，合起来是望风而动——没有任何新证据说这些新战线是当下该做的事。先清账，再开疆。

## 操作流程

```bash
jiubian audit <本会话流.jsonl>           # 途中/收尾审计失机值（合/钝/胶）
jiubian bianfang <本会话流.jsonl>        # 拿到变方：悬账清单 + 二选一指令
jiubian audit <stream.jsonl> --gate 20   # 关键任务用更严的门
```

宿主在接缝处递给你**变方块**时：读悬账清单 → 立即执行二选一（归还或明改其途）→ 再继续原计划。变方是确定性生成的，它列的每笔账都在流里真实发生。

## 何时必须自查

1. 任何工具失败发生后（重试前过一遍纪律一）；
2. 收到 "modified since read" / 并发冲突信号时（纪律二：先再察，这是有人动了你的地面）；
3. 准备连续创建/修改多个此前没碰过的文件时（纪律三自查：账清了吗）；
4. 任务收尾前跑一次 `jiubian audit`——失机值进「胶」带（≥30）就还有没还的账。

## 边界

- 失机值 0 不保证方向正确、质量过关——判断校准归解蔽，目标在场归正念，行为合规归知止；
- 悬账、离不计分：九变只罚盲捶与游骑两宗结构可证之罪，不惩罚正当改途；
- 变方块只列确凿入账的势变，绝不虚构威胁——它没提的失败不代表不存在，只代表流里没有证据。
