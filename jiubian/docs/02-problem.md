# 02 · 问题定义：谁、在什么场景下、有什么问题、价值何在

按「伪需求检验」的顺序写：先给场景和反事实，再给价值，最后自检。

## 目标用户

在 DeepSeek Harness（或任何 Cordis 架构的 Agent 运行时）上跑**非平稳环境中的任务**的工程师与团队：并发开多个会话/进程共同作业的人、让 Agent 跑小时级长任务而中途依赖会漂移的人、任务做到一半需求被更新的人。他们已经装了五层治理（行为/判断/意图/记取/开工体检），仍在为第六种账单付钱：**世界在中局变了，而 Agent 的路径没有跟上——或者恰恰相反，乱跟了一通**。所有现存治理层对此沉默：zhizhi 只拦「眼前这一次重复」，weibing 只管「开工那一刻」，中间的几十上百轮，势与途是否还在对齐，没有任何机制在测量。

## 四个场景

### 场景 1 · 盲捶死磕（敌已变，兵不变）

并发作业的真实下午：另一个会话改写了 `src/auth.js`，本会话的 edit 撞上 "modified since read"。正确的回应是回头重读再改；实际的 Agent 往往换个姿势继续写——或者更常见的：`npm test` 连败五次，五次命令逐字相同，中间没有任何一次「先看看为什么失败」。zhizhi 的连败止损会拦下**眼前这一记**重复——但拦不住「隔三件事之后回来再盲试一记」的钝刀割肉：那不构成它定义的「连续失败」，却是同一种病，而且更费 token。

**反事实**：todo/plan 是自愿式的；harness 自带的 retry 是机械式的（原样再试）；没有任何机制在事后问一句：「每一次失败之后，路径对它有结构性的回应吗？」盲捶第一次可以被逐笔数出来。

### 场景 2 · 悬账不结（败了，就当没败过）

一个文件的 edit 失败之后，Agent 全程再没有回到过它。也许它想的是「待会再处理」，也许它根本没把那次失败当成世界发出的信号。任务收尾时，这个对象就那么悬着——报告里不会出现它，因为 Agent 的自我叙事里它不存在。结构上可证的事实只有一条：**失败的势变发生后，整条路径再未接触过该对象**。

**反事实**：完成核验（zhizhi）问的是「完成有没有证据」，不是「你欠着的势变还完了没有」；正念的终验门对着本愿，不逐对象对账。悬账需要一本自己的账：每条文件势变，要么在流中看到归还，要么在收尾时被点名。

### 场景 3 · 游骑开源（悬账未清，连开新战线）

更隐蔽的一种：失败悬着，Agent 却**连开三条新战线**——新建一个没人要求的模块、重构一个无关的脚本、顺手补另一份文档。每一件单看都「像是在干活」，没有任何一件有当下的证据支持：没有新观察说这些对象是当务之急，悬着的失败也没有任何一件被归还。《火攻篇》的原话：「主不可以怒而兴师」——「我在干活」的感觉，就是机器的怒。

**反事实**：范围蔓延有正念的愿界管着（愿界之外），但游骑发生在**愿界之内**——开的每条新战线都在允许目录里。它错的不是位置，是**时机与依据**：悬账未清的时刻，无凭据地扩张战线。这需要一个对「悬账」与「新战线」同时记账的机制，五个已上线项目都没有这本账。

### 场景 4 · 变而无账（九变之功，无人记账）

治理账本有个系统偏差：只记罪，不记功。Agent 做对了应变的时候——失败后先重读再改、撞墙后明改其途——没有任何机制记录下来。于是评价一个 Agent 运行时，说不出「它应变能力如何」这种最基本的话：没有应变的质量单位。

**反事实**：《鹖冠子》里扁鹊长兄的名声不出于家，因为治病于未发。应变的功劳天然无声——但无声不等于不可记录。每条势变之后「回去再察了」「明改其途了」都是流内可证的结构事实，逐条记为「变」：应变第一次有了正数。

## 价值论证

1. **应变第一次有了质量单位**：失机值（0–100）是确定性的、可复现的数字，回答一个此前无法回答的问题：「这条运行里，路径对世界的变化回应得如何？」——不可测量 → 不可管理。
2. **双向门禁**：不变是滞（盲捶），乱变是妄（游骑）。第一次把「该不该变」从品味问题变成可审计问题——而且两个方向都罚，避免把 Agent 训成要么死磕要么乱跳的钟摆。
3. **不惩罚正当改途**：悬账挂账不计分、首盲免分、改途离场记「离」不记罪——涂有所不由是权利。门禁咬住的只有结构可证的两宗罪，误伤面被设计压到最小（夹具 adaptive-stream 用 0 分演示健康重试全程免罚）。
4. **治理拼图的第六块**：手（行为）、眼（判断）、心（意图）、习（记取）、工（开工体检）之后是**足**——地变了，步子得换；但去哪里由愿决定（正念的地盘），怎么落步由判断决定（jiebi 的地盘），足只负责一件事：别踩在已经塌掉的地面上，也别在没有桥的地方乱跳。
5. **契约无关，可验尸任何历史会话**：zhengnian 的度量需要开工时立契约；九变只需要一份会话流——过去任何一天的任何一次运行，`jiubian audit` 直接验尸。这让「团队历史会话的应变质量普查」成为一条命令的事。
6. **插件层的新能力类型**：zhizhi 拦、jiebi 审、zhengnian 供给、buer 记取、weibing 诊断，九变是第六种：**勘流式**——只挂 tools/result 持续勘势记账（结构性零拦截），并在悬账出现时于接缝处供给**变方**：一份逐字节确定的应变清单，逼下一个动作在「回到对象再察」与「明改其途」之间二选一。
7. **可证伪的价值主张**：对本仓库自己的历史会话与夹具跑 `jiubian audit`，能数出多少盲捶链、多少游骑、多少悬账——价值自证，不靠叙事。

## 伪需求自检清单

| 质疑 | 回应 |
|------|------|
| 「zhizhi 不是有连败止损吗？」 | 三重边界。**时点**：zhizhi 在 pre-execute 拦「眼前这一记」，九变在事后审整条路径——隔三件事回来再盲试，zhizhi 看不见，九变逐笔记账。**管辖**：zhizhi 拦动作（手），九变勘势途对齐（足）。**形态**：zhizhi 是拦截器，九变结构性零拦截（源码无 pre-execute 监听器，可 grep 验证），契约无关、可验尸历史流——zhizhi 对已经结束的会话无能为力。 |
| 「重试有时是合法的，会误伤吗？」 | 会误伤的设计才是伪需求，所以计分规则内建豁免：**每条盲捶链首记免分**（瞬时错误重试合法），悬账**不计分**（改途离场是涂有所不由的权利），游骑要求**连续 ≥3 个无凭新对象**且悬账未清（正常开工铺文件不触发）。健康会话夹具（失败→重读→再改）实测 0 分。 |
| 「环境变化检测需要语义理解，关键词/结构信号够吗？」 | v1 的诚实边界写在 docs/01 第三节：只测**确凿入账**的势变（isError 结果），不假装测到测不到的势变（文件被改但还没撞上）。确定性度量的价值在可审计、可门禁、可重放，不在全知——这三件事九变分开承诺，与 jiebi/zhengnian 的立场一致。 |
| 「Agent 有 reflection / replan 能力，还需要这个吗？」 | reflection 是自愿式美德：模型想反思才反思，恰好在最该反思的连败中局最容易被「再试一次就好了」的惯性压过。九变是强制式机制：势账从动作流里提取，不依赖 Agent 自觉，门禁由退出码说话——「原则会被违反，触发器不会」的本仓库一贯立场。 |
| 「这不就是 retry-loop 检测器吗？」 | 只对三分之一。盲捶确实是 retry-loop 的审计版（zhizhi 是拦截版）；但游骑（无凭扩张）与悬账（败而不归）在公开的 retry-loop 文献里根本没有对应物——前者把「乱变」变成了可测量对象，这是本仓库第一次有治理层同时罚「不变」与「乱变」两个方向。 |
| 「为什么悬账不计分？欠账不还还不是罪吗？」 | 因为结构层无法区分「忘了」与「涂有所不由的正当放弃」——把正当放弃当罪罚，就是把改途的权利没收，Agent 会被逼着在死路上死磕。九变的取舍：能证罪的（盲捶、游骑）计分，不能证罪的（悬账）挂账点名。宁可少罚，不可错罚。 |
| 「失机值 0 是不是说明这次运行没问题？」 | 不是。0 分只证明「路径对观察到的世界变化都有结构回应」，不证明判断正确（jiebi）、本愿在场（zhengnian）、行为合规（zhizhi）、方向成功。六层各管一维，九变不越界承诺。 |
| 「和其他五层撞车吗？」 | 正交且有明确边界（见根 README 方向登记）：不拦动作（zhizhi）、不审判断账本（jiebi）、不守本愿契约——**本愿不许变是正念的事，路径必须变是九变的事**（君命有所不受变的是途不是目的地）、不记跨会话旧账（buer）、不做 t=0 体检（weibing）。九变只做 t>0 的势途对齐审计与变方供给，零 LLM、零语义判断。 |
| 「凭什么说是真实问题？」 | 三个可指认的公开失败模式：retry-loop 是 Agent 可靠性评测的常客；并发写冲突后的 stale-retry 是多 Agent 协作的日常事故（本仓库的会话就真实跑在多会话并发环境里）；plan fixation 在长程 Agent 基准中反复被报告。`jiubian audit` 能对任意历史会话量化盲捶与游骑——价值主张可自证。 |
| 「会不会拖慢 Agent？」 | 零拦截（结构性，插件源码无 pre-execute 监听器）、零 LLM 调用、零网络。勘势是 O(1) 均摊的账本更新（对象键字符串比较），变方是模板渲染。度量不消耗 token。 |
