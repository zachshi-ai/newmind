# 名实 · Mingshi — Agent 协作协议

> **夫名，实谓也。**——《公孙龙子·名实论》
>
> 你写下的每个名字都是承诺：import 的模块径、安装的包名。本协议不限制你引新装新——它只要求每一名在收工时**有名副之实**：要么在实册（任务方登记的树界与包册），要么在本流内生实（成功写过/读过之径、装成之包），要么是内建。

## 给委派任务的工程师

```bash
cd your-repo
mingshi register --root 'src/**' --root 'test/**' --pkgfile package.json   # 开工立册（实册=.mingshi.json）
# ……Agent 作业……
mingshi audit session.jsonl --file .mingshi.json                           # 收工核名（exit 码可进 CI）
mingshi block --file .mingshi.json                                         # 名册块（可注入收尾上下文）
```

- **无册不判**：没立实册，审计不会冤枉任何一笔写——先立册，再 audit；
- **册要立全**：roots 是你对整棵树的作保，漏声明的目录会把既有之名记成妄；
- **依赖要收紧时**：`mingshi register --strict-deps`——此后册外装成记犯装 +30；
- **门禁**：名值 ≥ 30（默认门）即红，单幻包即红。

## 给 Agent

1. **不谓不在之名**（名实论：「知此之不在此也，明其不彼也，则不谓也」）：不确定 `./utils/date.js` 在不在，先 `read`/`glob` 证它，再写 import——你的成功读写本身就是它的生实凭据；
2. **引新先装、装新留痕**：新依赖先 `npm install`（装成即生实），册外之装会以新装留痕——这是合法通道，别绕（bash heredoc 之写是黑盒，黑盒救不了你，构建会炸）；
3. **测试先行无罪**：先写测试引模块、后建模块，收工总核时生实先后皆采——TDD 天然清白；
4. **看见「幻包 ×N」不要狡辩**：那是结构事实（册外且全流无装成），唯一的出路是装成它或删掉它——改审计报告不在任何通道里；
5. **读名册块**：接缝处收到的【名实 · 名册】是逐字节确定的实册公示，用它对齐「哪些名字有保」。

## 案由速查

| 案由 | 分 | 语义 | 出路 |
|---|---|---|---|
| 幻包 | +30/名（cap 60） | 册外且全流无装成的包名 | 装成它 / 换成实名 / 删掉引用 |
| 幻径 | +15/名（cap 30） | 册外且全流无读写的相对径 | 建出它 / 证它（读写一次） / 删掉引用 |
| 新装 | +6/次（cap 30） | 册外装成（宽态）——合法，必须留痕 | 让任务方登记入册 |
| 犯装 | +30/次（cap 60） | 册外装成（strictDeps 执法态） | 先经任务方入册再装 |
| 试装 | 0 | 装而未成——不生实、不计分、只点名 | 修令重试，别改名重装幻觉 |
| 实名 | 0 | 册内 ∪ 生实 ∪ 内建 | 无需动作 |

分带：**正 0–14 / 疑 15–29 / 妄 ≥30**；门默认 30。
