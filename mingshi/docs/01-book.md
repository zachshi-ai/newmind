# 01 · 选书：《公孙龙子》——夫名实谓也，知其不在则不谓

## 为什么是《公孙龙子》

给「Agent 名实错位」找思想源头，先排掉已被本仓占用的书：道德经（zhizhi）、荀子（jiebi）、六祖坛经（zhengnian）、黄帝内经（weibing）、孙子兵法（jiubian）、庄子养生主（youya）、孟子（lunshi）、商君书（dingfen）、鬼谷子（baihe）、墨子（fayi）、春秋（zhibi）、中庸（yuli）、礼记（duzhi）、韩非子（erbing）、大学（zhongshi）、论衡（xiaoyan）；论语（buer，在途）、周易（licheng，在途）。名家的书一部未用，而「名与实的关系」恰恰是本仓十八层治理从未设防的一条通道。

《公孙龙子》不只是「白马非马」的诡辩集——它是先秦名家对**名实关系**最精确的解剖。它给**名的本体论地位**（夫名，实谓也：名是实的称谓，名不携实即是空言）、给**实与位的定义**（物以物其所物而不过焉，实也；实以实其所实而不旷焉，位也：有物可指为实，实安其所为位）、给**正名的操作序**（其正者，正其所实也；正其所实者，正其名也：先核其有没有实，再问名正不正）、给**名的专指律**（其名正，则唯乎其彼此焉：一个正名只指它所指的那一个东西）、还给**禁言的判据**（知此之非此也，知此之不在此也，明其不彼也，则不谓也：明知它不是它、明知它不在这里，就不许说出口）。这五件事恰好是名实核验的五个设计支柱，且《公孙龙子》未被本仓任何项目使用。

需要诚实处理的气质问题：《公孙龙子》常被读作诡辩书，「白马非马」两千年来毁誉参半。本层只取其**名实之正**——公孙龙本人恰是「防止名脱离实」的第一人：白马论是在切割名与名的混淆，名实论是在钉死名与实的绑定。把它用于「Agent 写下的名必须有名副之实」，是正用而非术用。

## 原典条款 → Agent 病 → 机制：逐条映射

| 《公孙龙子》原文 | Agent 的病 | 名实的机制 |
|---|---|---|
| 名实论：**夫名，实谓也** | 名不携实：Agent 写下 `import parse from 'json-parser-pro'`——这个包名在环境里没有对应的实，import 语句是纯空言；装下册外的包，编译前人人绿灯 | **名账**：对每笔写的内容提取其名（import/require/export-from 之名，安装令之包名），逐名问一句：实安在？ |
| 名实论：**物以物其所物而不过焉，实也；实以实其所实而不旷焉，位也** | 「实」没有清单：哪些模块径、哪些包名是真实存在的，从未被登记；Agent 脑中的世界与磁盘上的世界从第 0 轮起就在漂移 | **实册**：模块树之界（roots）与在册包表（packages）显式登记——册内之名 presumed real，声明权在任务方 |
| 名实论：**知此之非此也，知此之不在此也，明其不彼也，则不谓也** | 知其不在而言其为在：幻觉包名（slopsquatting 的靶子——攻击者预先抢注模型常幻觉的名字，一装即中毒）与幻径 import（构建必炸的死名）都被写进了交付物 | **妄引**：册外且全流无实之名（幻包 +30/名、幻径 +15/名）——明知不在，谓了就要上账 |
| 名实论：**位其所位焉，正也；出其所位，非位** | 名不在其位：包没进过实册、没在流里装成过，就被 import 了——位无所位 | **账内生实**：流里成功读写过的径、成功装过的包，其名自此为实（生实免罪，先后皆采——先写测试后建模块的 TDD 天然无罪） |
| 名实论：**其正者，正其所实也；正其所实者，正其名也** | 正名的顺序被倒置：先有实后有名（装成过才能引、建成过才能 import）是工程的本分；Agent 常先出名后找实，找不到就把名字留在代码里 | **名实对账**：收工总核——每一名都要在「册内 ∪ 流内生实 ∪ 内建豁免」三处之一找到其实，找不到即妄 |
| 白马论：**马者，所以命形也；白者，所以命色也。命色者非命形也** | 名与名之辨被抹平：装过的包与没装过的包、册内的依赖与册外的依赖，在 Agent 的输出里同形同权——没有一个机制区分「此名有实」与「彼名无实」 | **名分三案**：实名（册内/生实/内建，免咎）、新装（册外而装成，+6/次记账——依赖变更必须可见）、妄装（strictDeps 之下册外装成，+30/次——供应链收紧时的执法态） |

## 与管理学互证

- **依赖白名单（Dependency Allowlist）**：现代供应链安全（SLSA、npm provenance）的底线控制——新增依赖须过审批。实册就是白名单的登记态，新装就是变更的显式通道。
- **Slopsquatting 防御**：2023 年起安全界证实 LLM 幻觉包名可被攻击者批量抢注（slopsquatting）；对 Agent 写出的每个册外包名记账并门禁，是这一攻击面在 harness 层的结构性防御。
- **配置即事实（Configuration as Ground Truth）**：管理学口径下「库存清单必须与实物对账」；实册与名账的对账就是依赖库存的账实相符。

## 与相邻思想的分工

- fayi（墨子·法仪）审的是**尺被改**（验收器自污染：改测试转绿）；名实审的是**名无实**（写下的名字在环境里没有对应物）。尺直而名妄，绿灯照样建立在空言上——两层互补，不越界。
- weibing（黄帝内经）在 t=0 体检**任务书**里引用的命令与文件在不在（活体环境探查）；名实在 t>0 核**Agent 自产之名**（离线流 + 实册对账，不触碰文件系统）。时点、对象、证据源三重不同。
- jiebi（荀子·解蔽）审**判断的账实**（宣称的证据真不真）；名实审**名字的账实**（写下的名有没有物）。判断之名与物之名，两本账。
- lunshi（孟子）审**输入渠道的权威**（谁有资格发令）；名实审**输出名字的实在**（说出的名有没有实）。一进一出，各守一界。
- youya（庄子）记**见闻**（读过什么跑过什么）；名实把「成功读写的径、装成的包」升格为**生实**——youya 的账在这里被借作实据，但判定权独立（youya 不判名，名实不记复见）。

## 诚实边界（我们不假装的事）

1. v1 只认 JS/TS 生态：import/require/export-from 之名、npm/pnpm/yarn 安装之包；Python/Cargo 等留待扩充——宁缺毋滥。
2. 路径别名（`@/x`、tsconfig paths）、monorepo workspace 协议（`workspace:*`）不解析——别名之名不判（宁可放过，不可错罚）。
3. 幻觉包名若被攻击者抢注，安装会**成功**——成功的装在默认态只记新装（+6）；要拦，开 strictDeps 执法态（+30）。名实不假装能区分「真包」与「抢注的幻包」，那是注册表的职责；名实的职责是让每个册外之名**必须留痕**。
4. 无实册不判——声明权在任务方；roots 声明过窄会把既有之名误记为妄，登记表提示 owner 声明全树。
5. 动态名（变量拼 import、运行时 require）不可提取——词表之外皆黑盒。
