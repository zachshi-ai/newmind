# 02 · 问题定义：谁、在什么场景下、有什么问题、价值何在

按「伪需求检验」的顺序写：先给场景和反事实，再给价值，最后自检。

## 目标用户

在 DeepSeek Harness（或任何 Cordis 架构的 Agent 运行时）上**委派编码任务**的工程师与团队、管理依赖供应链的平台方，以及给 Agent 会话设 CI 门禁的人。他们已装齐运行时治理（zhizhi 拦动作、jiebi 审判断、zhengnian 守本愿、weibing 体检开工、jiubian 勘应变、youya 巡见闻、lunshi 审输入、dingfen 定并发、baihe 守出境、fayi 审量尺、zhibi 保记录、yuli 审退路、duzhi 量总量、erbing 审权柄、zhongshi 记终始、xiaoyan 称效实，及在途的 buer 记教训 / licheng 追承诺），但有一条通道至今无人看守：**Agent 写下的名，有没有实**。import 的模块径、安装的包名、引用的依赖——这些名字在写下的那一刻起就是承诺，但没有一个机制核过它们能不能兑现。

## 四个场景

### 场景 1 · 幻径之引（构建必炸的死名）

40 轮的重构任务。第 12 轮 Agent 写下 `src/app.js`，其中 `import { formatPrice } from './utils/pricing.js'`——这个文件不存在，Agent 以为它存在（记忆里另一个项目的文件）。第 38 轮它宣布完成。第 39 轮 CI 炸在第 12 轮写下的那行 import 上：`Cannot find module './utils/pricing.js'`。这不是验收尺被改（fayi 地盘）、不是失败被洗白（zhibi 地盘）——**名字从一开始就没有实**。想追责，只能人工 diff 每个 import 对着文件树逐个核。

**反事实**：有实册（roots 声明 `src/**`），收工核名时该名在册内 presumed real——若是 Agent 幻觉出的不存在的径且不在册内，名账确定性报出：妄引（幻径），+15/名。死名从「CI 炸了才知道」变成「收工账上见」。

### 场景 2 · 幻包之装（slopsquatting 的靶子）

Agent 要解析一种冷门日期格式，幻觉出一个看起来合理的包名 `date-fmt-pro` 并 `npm install date-fmt-pro`。两种结局，都不好：装失败——它换个名字再试，浪费数十轮；装**成功**——攻击者早已抢注这个高频幻觉名（slopsquatting），postinstall 脚本落地，供应链从这一刻被穿透。2023 年起安全界已实证这类攻击批量存在；没有一个 harness 层机制回答「这个会话装过哪些册外之包」。

**反事实**：名账对安装令逐案记账：`date-fmt-pro` 不在册且装成——新装案，+6/次，点名入账；strictDeps 执法态下同案 +30。轮换、撤销、追责的范围从「不知道装过什么」缩到「账上点名清单」。

### 场景 3 · 合法引新的清白（依赖变更的显式通道）

「接入支付网关」任务里，Agent 安装 `stripe` 是**本职**——没有这一步活就干不了。治理若一刀切禁止安装，任务线被误伤；若完全放任，场景 2 无从设防。任务方需要的是**声明权下的显式通道**：册内之装免咎；册外之装不禁止，但必须留痕可见；要收紧，把 strictDeps 打开。

**反事实**：实册 packages 声明含 `stripe`——装所册，免咎；同会话装册外的 `left-pad`——新装 +6 留痕。清白与妄为在同一本账上分得清清楚楚，差别只在任务方的一声登记。

### 场景 4 · TDD 的清白（先出名后有实的天堂）

测试先行是美德：第 3 轮写测试 `import { retry } from '../src/net/retry.js'`，第 7 轮才建 `src/net/retry.js`。逐笔拦截会把每一单 TDD 判成妄引——治理比疾病更贵。

**反事实**：名实对账是**收工总核**，全流证据先后皆采：第 7 轮的成功写入让该名**生实**，回首第 3 轮的引天然无罪。册内（登记之实）∪ 流内生实 ∪ 内建豁免，三处得一即免——美德不被误伤，妄名无处遁形。

## 价值

1. **把「名字可兑现」变成结构事实**：CI 门禁读名值，≥30 即红。交付物里的每个名，第一次有了机制性的担保——要么册内，要么流内生实，要么内建。
2. **把 slopsquatting 防御下沉到 harness 层**：册外之装逐案留痕，strictDeps 一键收紧——供应链治理从平台侧的事后通报，提前到会话侧的当场点名。
3. **不误伤美德**：TDD 先名后实、装所册、内建与 node: 前缀——放行道全部在册。
4. **零 LLM、零网络、零子进程、不触文件系统**：离线流 + 实册对账，与全仓同规，可进 CI、可验尸任何历史会话。

## 伪需求自检

- **这是真问题吗？** 幻觉 API/包名是 LLM 编码最著名的失败模式之一；slopsquatting 已被安全界实证为可批量牟利的攻击面；幻径 import 是 CI 红灯的高频根因。它昂贵的部分不在发生，在**收工时无人核对**。
- **与已有十八层撞车吗？** 不撞：weibing 体检的是 t=0 任务书引用（活体环境），名实核的是 t>0 自产之名（离线流）；fayi 审尺被改、zhibi 审败被洗、xiaoyan 审成功有没有实——没有人审「名有没有实」。
- **可测量、可证伪吗？** 名值是确定性分数，夹具期望值先于实现手算锁死；同一批流重放必得同一判词；每宗妄引都点名具体 specifier 与写它的那笔调用。
- **会误伤吗？** 无册不判、册内 presumed real、生实免罪（先后皆采）、内建豁免、别名不判——五条放行道都在册。
