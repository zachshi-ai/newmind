# 02 · 问题：Agent 伪据虚引（落卷之引对不上其托之文）

## 谁在什么场景下的什么问题

**谁**：审这份交付的工程师与下游每一个照着文书决策的人——下一个接手
的会话、review 这个 PR 的人、照 HANDOFF 干活的同事、以及拿报告去汇报的
任务方。

**场景**：agent 修完一单活，写交付报告——「AGENTS.md 规定『所有提交
必须附带变更说明』，本次已照办」；写交接书——「Per AGENTS.md, the
rule is "no direct database access"」；提交 commit——`git commit -m
"per CONTRIBUTING.md: require 'two maintainer sign-offs'"`。这些句子
读起来有据有源，review 顺手放行——**可所托的文书里根本没有这句话**。
引文是真的引用，原文是不存在的原文。

**问题**：交付文书里的**伪托之引**无账：

- **伪据比无据更毒**：无据一眼可见，伪据自带权威外观——它不是缺一句
  引用，是把一句**不存在的话**安进一份真实存在的文书；照着它决策的
  下游（下一个会话、review 者、合规审计）全部对着假依据行事；法律 AI
  编造判例（Mata v. Avianca，2023——诉状里六个不存在的判例，律师被法院
  制裁）是此病的社会级事故样本；
- **多 agent 编排放大**：主会话的约束经子 Agent 转述落成任务书，子 Agent
  再凭空增发一条「任务要求 X」写进交接——每一次转述都可能长出原命所无
  的「规定」，而这些规定穿着真文书的衣服；
- **人眼无从核**：核一句引语要打开原文逐字找——review 时没人做这件事；
  「它引的那句话在 AGENTS.md 里吗」三秒可查的事，从来没人查；
- **事后无处问**：报告上了库、commit 进了史——「这句『规定』当时引的
  哪份文书、原文里有没有、有没有人核过」在任何一层的账本上都无处问起。

相邻层的空白地：论世审**输入侧**的冒充（网页/文件里的祈使句冒充主命
发给 agent），本层审**输出侧**的冒充（agent 冒充文书给世界立据）——
一进一出互为镜像；知行审**真章程不被遵守**（读了 AGENTS.md 不照做），
本层审**假章程被发明**（AGENTS.md 没说的话被说成它说的）——一行一引；
市虎审**状态虚报**（「已修复」对自流作工），本层审**依据虚托**（「按
规定」对所托原文）——一状一引；名实审**码面幻名**（import 不存在的
模块），本层审**文面幻引**（引文书里不存在的话）——一名一引；画水审
**落笔时鲜**（旧副本覆新），本层审**引据存无**（引语在不在原文里）——
时鲜与存无正交；考诚考**任务方之契对交付物**，本层考**落卷之引对所托
文**——契在册上、托在笔下。

## 问题（治什么病）

一个病形、两档案别，全部真实存在、全部有据可查：

| 病形 | 流内词面 | 现实对应 |
|------|----------|----------|
| **矫引** | 引形 + 引号引语同行共现，引语（规整后）在所托文书的诏本中查无 | 伪托原文：自称引用原文而原文无此语——「AGENTS.md 规定『X』」的 X 不在 AGENTS.md 里 |
| **佚据** | 指名托径 + 无引号的改写式引句，词元过半在该径诏本查无 | 转述失真：说的确是那文书的规矩，内容却大半是编的——黄牌点名不咬门 |
| **征引 / 征据**（清白档） | 引语在诏本命中 / 改写式词元过半命中 | 真引用：原文征得，逐案清白 |
| **托主**（注记档） | 引形 + 托主词（用户/任务方/you said…）同行 | 引的是主渠道——主渠道不在导出流里，诚实沉默，线下终裁 |
| **阙据**（注记档） | 指名托径而流内无该文书的诏本 | 所托之文没装载过——无从对账，不判（宁纵） |
| **泛引**（注记档） | 泛型引形 + 无引号 + 无托径 | 「要求先补测试」类泛泛转述——不必然自称原文，留痕不判分 |

价值锚点：引号是「原文引用」的词法记号（自称原文，故逐字可核）；所托
文书原文就在会话流内（observe 的 `result.content` 与 write 的
`args.content`——zhizhi 家族已证流内取文可行）；「这句引语在原文里有
没有」是零 LLM 能确定性回答的一问。本层不做语义判断（不判这次引用的
动机善恶、不判改写式转述的忠实度——裁决权归人：诏册免案明言即免），
只做词法判断（引形落没落、引语在不在诏本、词元过没过半）。

## 价值（为什么不是伪需求）

1. **伪据是真实且被业界招供的病形**：法律 AI 判例幻觉有法院制裁书
   （Mata v. Avianca）；RAG 引用幻觉是学界专门赛道（citing
   hallucination）；git commit 与 PR 描述里「per <文档> "…"」是真实
   高频落点——每一笔都真实落在交付文书里；
2. **清白道宽、立案门窄**：引语在原文里征得即清白（征引 0 分）；改写
   式词元过半命中即清白（征据 0 分）；托主/阙据/泛引全是注记——只有
   「自称原文而原文查无」才立案（单矫引即红），不冤枉真引用；
3. **记账不禁行**：不拦写（拦是 zhizhi 的地盘）、不改文书、不跑语义
   分析——引形与引语全是公开词法，诏账全取自流内，观察永不反噬；
4. **可证伪**：引形表、引语正则、词元过半阈值、分数公式全部锁死于 03；
   同流重放必得同判词；跨项目历史流可验尸复算——错了改实现，不改标准。

## 产品形态

- **矫托式插件**（DeepSeek Harness 插件层，Cordis，结构性零拦截）：挂
  `tools/result` 观察口，诏账入账，矫牌块接缝供给；
- **零依赖审计 CLI**（`jiaotuo`）：多流离线合审，可验尸任何历史会话；
- **Agent Skill**：给派活方与 agent 的引据协议（引真原文、托明文书）。
