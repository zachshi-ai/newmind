# 01 · 选书：《国语·周语上》—— 防民之口，甚于防川

## 原文

《国语·周语上》「召公谏厉王弭谤」（通行本，据《古文观止·卷一》与百度百科同文）：

> 厉王虐，国人谤王。召公告王曰：「民不堪命矣！」王怒，得卫巫，使监谤者。以告，则杀之。
> 国人莫敢言，道路以目。

> 王喜，告召公曰：「吾能弭谤矣，乃不敢言。」

> 召公曰：「是障之也。防民之口，甚于防川。川壅而溃，伤人必多，民亦如之。
> 是故为川者，决之使导；为民者，宣之使言。……夫民虑之于心而宣之于口，成而行之，
> 胡可壅也？若壅其口，其与能几何？」

> 王弗听，于是国人莫敢出言。三年，乃流王于彘。

## 为什么是这本书

agent 交付的代码里，空体 catch 与 `except: pass` 是最高频的静默形之一：写手为了让
「这单活不炸」，把运行期的报错之口一只一只堵上——`catch (e) {}` 吞下加载失败、
`except: pass` 吞下校验异常、`.catch(() => null)` 把失败抹成默认值。程序还在跑，
错误却在运行期入了盲区：异常状态静默累积，排障时连「当时错没错」都无处问起——
**国人莫敢言，道路以目**。

《国语》把这件事的后果说到了根上：**防民之口，甚于防川**——堵口比让话说出来危险得多；
**川壅而溃，伤人必多**——被吞掉的错误不会消失，只在下游以更贵的姿势爆炸。
而正当的处理只有一条：**为川者，决之使导**——报错要么导出去（日志、上抛、上报），
要么明明白白地做降级决策，唯独不能无声地咽下。本层不假装能读懂「这次吞错值不值」
（语义判断是禁区），它只做词法可证的事：交付代码的末文里，吞形在不在、几处、
哪一行、改净了没有——**为民者，宣之使言**，让代码里的错重新能言。

## 逐条映射

| 《国语》 | AI 现实 | 本层机制 |
|----------|---------|----------|
| 防民之口，甚于防川 | 空 catch 看似「稳」，实为把报错之口堵死——错误从可见变不可见 | **湮形 6 形**（空捕/空还/空接/单行空捕/多行空捕/空救）默认在岗，无册照判 |
| 川壅而溃，伤人必多 | 被吞的错误在下游以更贵的姿势爆炸，排障无迹 | **塞值**分带门禁：湮案逐处计分，两案即红 |
| 为川者，决之使导 | 正当处理是导出去：日志、上抛、上报 | **导词表**：体内有导词（console./throw/logger/…）即清白 |
| 为民者，宣之使言 | 让代码里的错重新能言——先要让吞形可见 | **导牌块**接缝供给：湮形公示 + 川册公示 + 逐处点名（径:行:形） |
| 道路以目 | 错误静默后的运行态：人人看见异常，无人报得出口 | 案账清点进导牌块，谁写的、第几行、什么形，逐处可见 |
| 三年，乃流王于彘 | 吞形不考，下一单活继承吞形的代码库 | 塞值进门禁（exit 码可进 CI），验尸任何历史会话 |
| 王怒，得卫巫，使监谤者 | 本层不做卫巫：不判语义、不拦动作、只认词面 | 零 LLM、零文件系统探测、结构性零拦截；湮形词法可欺但骗一次留一次形 |
