# 考诚 · Kaocheng — Agent 协作协议

> **「物勒工名，以考其诚；工有不当，必行其罪，以穷其情。」——《吕氏春秋·孟冬纪》**
>
> 器物不勒工名，考核就是空谈。本协议不限制你怎么干活（拦是知止的地盘），
> 它要求：任务方立的交付契约必须逐条被考——契上要的物要在场、要成形、要对得上条款；
> 完成不是对着自选的证据自封的，是对着契册考出来的。

## 何时用此 Skill

- 工程师给 agent 派活时想把验收条款结构化（哪个文件、什么格式、必含哪些字段），收工自动逐条核；
- CI 需要一道「交付契约全过」门禁（诚值 ≥ 30 即红）；
- Agent 需要自查：这一单活，契上的物我交付齐了没有。

## 给派活的工程师

```bash
cd your-repo
kaocheng register --name 报告 --path docs/report.md --min-lines 3 --words 结论
kaocheng register --name 结果 --path out/result.json --form json --fields summary,count
# ……Agent 作业……
kaocheng audit session.jsonl --file .kaocheng.json   # 收工考物（exit 码可进 CI）
kaocheng block --file .kaocheng.json                 # 考牌块：契册公示 + 物账清点
```

- **契约要趁开工立**：径/结形/域/词/卷五条，立得越早，agent 心里的「完成」越不容易走样；
- **无册不判**：不立册出不了红——契约是任务方的意图，引擎无从代拟，但也无从替你把关；
- **门禁**：诚值 ≥ 30 即红——单幽物/灭物/畸物即红，单壳物（20）黄牌点名不咬门。

## 给 Agent 的五条纪律

1. **契上之物，件件在场**（「契上之物，全流无工」即幽物）：任务书立了册，收工前逐件核——没写的先写；
2. **形要成得起**：声明 json 就交付可解析的 json、声明的域一个不能缺、声明的词一个不能少——
   畸物与疵物都写在末据上，骗不过 `JSON.parse`；
3. **交付物不是草稿**：写完之后别顺手删、别拿重构覆盖——末笔之后的毁灭叫灭物，单案即红；
4. **生成走词法可见的道**：用重定向、`cp`、`tee` 落契上之物（工见从宽不罚）；`npm run build`
   静默产出的交付物，考诚看不见，会判幽物——要么换成可见的落法，要么写一笔；
5. **完成对着契册宣布**：绿命令不是完成，契上件件「诚物」才是完成（「物皆诚 ×N —— 必功致为上」）。

## 判定语义速查

| 案 | 对象 | 判定 | 分值 |
|---|---|---|---|
| 幽物 | 契上之物全流无工（无成功写 ∧ 无 exec 工见） | 契约无人应工 | +30/件（单案即红） |
| 灭物 | 末笔写之后遭 rm 词族毁 | 工成而毁，物终不存 | +30/件（单案即红） |
| 畸物 | 声明 json 而末据不可解析 | 以形许人而形不成 | +30/件（单案即红） |
| 壳物 | 末据空白 | 有其名无其实 | +20/件（黄牌） |
| 疵物 | 域/词/卷条款有缺 | 功有不当 | 缺域 +10/域、缺词 +5/词、短卷 +10/件 |
| 工见未考 | exec 生产词法命中、末态黑盒 | 注记不计分，结形沉默 | 0 |
| 账上无末态 | 有成功写而流内无 content（老流） | 诚实沉默 | 0 |
| 诚物 | 全条款过 | 必功致为上 | 0 |

分带：**诚 0–14 / 欠 15–29 / 欺 ≥30**；门默认 30。边界：终始记众事的行程、考诚考物之末据（一程一物）；
效验称成功信号的成色、考诚考交付物的结形（一报一物）；法仪审验收器的曲直、考诚审物对契约（一尺一物）；
舍筏审落物的归宿、考诚审契上物的在场与成形（一散一缺）。观察不是工：读取成功不豁免契约；
失败之写非工：契约考果不考勉。
