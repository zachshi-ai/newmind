# 指瑕 · Zhixia — Agent 卷面自洽协议

> **「慮動難圓，鮮無瑕病。」**
> **「應劭釋疋，或量首數蹄……辭賦近事，而千里致差。」**
> **「若能櫽括於一朝，可以無慚於千載也。」——《文心雕龙·指瑕第四十一》**

你写下的每一份交付文书，都在替你向世界陈述事实——「共 5 项」「合计
100」「2026-09-10 至 2026-09-05」。数目是决策的把手：reviewer 照它核验、
下游会话照它排程、任务方照它汇报。言与列、总与分、起与止分处稿面两头，
逐句生成的你没人回头对——而读者会信一个自洽外观下的假数。本协议不限制
你落笔（拦是知止的地盘），它要求：**言必有列、总必可加、期必不倒**——
卷面自洽是交付的本份，不是审稿人的恩赐。

## 何时用此 Skill

- 工程师想防住「agent 交付报告/交接书/汇总表内部数目自相矛盾」——
  言五列三、总百和九十、起后止前的日常作业形态；
- CI 需要一道卷面自洽门禁（瑕值 ≥ 30 即红——单乖列即红、单乖总即红、
  双倒期即红）；
- 多 agent 编排里，主会话要防子 Agent 的交接书数目漂移；
- Agent 需要自查：我声明的数，和稿面里当众可数的东西，对得上吗？

## 给派活的工程师

```bash
cd your-repo
zhixia register --path "docs/reports/*"            # 免审径（模板文书等），先立瑕册
zhixia audit session.jsonl --file .zhixia.json     # 收工审稿（exit 码可进 CI）
zhixia block --file .zhixia.json                   # 瑕牌块：瑕册与词法公示
```

- **无册照判**：数言三形开箱在岗——不立册也审，册只管免审一侧；
- **试场天然豁免**：tests/specs/fixtures/mocks 等名段不审——演武之地的
  失应文书是道具；正当之免审必须明言立册；
- **门禁**：瑕值 ≥ 30 即红——单乖列即红、单乖总即红、双倒期即红、
  单倒期黄牌不咬门；
- **以末稿为准**：agent 先交瑕稿后改净，只留已磨注记 0 分——鼓励改，
  不冤改过的手。

## 给 Agent 的五条纪律

1. **言必有列**：写「共 N 项/条/步」之前，先数一遍身后的清单——声明的
   数与枚举的实不敷是乖列案（+30，单案即红）；没有清单就不要报数；
2. **总必可加**：表里放「合计」行之前，把该列整数加一遍——合计与整数
   列不敷是乖总案（+30，单案即红）；带小数的占比列注定对不齐，干脆
   不要写合计；
3. **期必不倒**：写「A 至 B」之前，比一比起止——起日在止日之后是倒期案
   （+15，双处即红）；表格里分列起止时也要亲眼对一遍；
4. **改净即白**：发现早稿有瑕，重写整稿再交——末稿立撤，先瑕后磨只留
   注记不计分（櫽括一朝，无惭千载）；带着瑕交出去，斯言一玷，留痕入账；
5. **词法可欺但骗一次留一次形**：改措辞躲词表、拆清单避块窗——改得掉
   一次判词，改不掉档案上的形；卷面自洽是本份，不是审计的博弈。

## 判定语义速查

| 案 | 对象 | 判定 | 分值 |
|---|---|---|---|
| 乖列 | 数言（方向词×量词，N≥2）+ 言后 gap≤2 列块/表块，M ≠ N | 言列不敷 | +30/案（单案即红） |
| 乖总 | 单合计行 × 纯整数列，Σ ≠ 合计 | 总分不敷 | +30/案（单案即红） |
| 倒期 | ISO 日期对起 > 止 | 起止倒置 | +15/处（双处即红，单处黄牌） |
| 阙列 | 数言无近列 | 言而无列 | 注记 0 分 |
| 已磨 | 先瑕之径新稿净 | 櫽括一朝 | 注记 0 分 |

三形并行、案案独立；判词与瑕牌永不携带行原文（只载 径:行:案别:数据:指纹）。

## 一句话

三十八层审的是文书对世界——状态对作工、引语对原文、物对契约；**指瑕审
的是文书对自己**：读者会原谅一份粗陋的稿子，不会原谅一份自己打自己架的
稿子。
