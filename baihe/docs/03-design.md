# 03 · 设计：阖籍、境账、溃值与阖门块

## 总览

```
Agent 出境调用 ──▶ tools/result ──▶ 境账（唯一写入口，观察式步进）
                    （捭阖不在此接缝拦截——零拦截是结构性的）
                        │
        ┌───────────────┼────────────────┐
        ▼               ▼                ▼
    出境判定         阖籍称量          域别裁决
  （参数含 URL）   （默认形表 ∪ 显式）  （回环/白名单 → 内域）
        │               │                │
        └───────┬───────┴────────────────┘
                ▼
   案别：泄物（外域·成功·命中）/ 试出（失败·点名不计分）
         / 内域档（白名单·本职不计分）/ 合法出境（无物·0 分）
                │
                ▼
   溃值 = min(60, 25 × 外域泄案数)   分带：密(0–14)/疏(15–29)/溃(≥30)  门默认 30
                │
宿主在接缝调用 ctx.baihe.hemen() ──▶ 阖门块（逐字节确定，注入与否由宿主决定）
```

## 四件

### 一、阖籍（物的清单）

物只在**出境侧**称量：手里有物不罚（装载是域内合法行为），物出境才罚。

- **默认形表**（7 形，内置，与显式登记取并集；显式登记只能增不能删——与论世的越词表同一家法）：

| 形 id | 名 | 确定性规则 |
|---|---|---|
| `sk` | sk 密钥形 | `/sk-[A-Za-z0-9_-]{20,}/` |
| `vcs` | 代码仓令牌形 | `/ghp_[A-Za-z0-9]{30,}|github_pat_[A-Za-z0-9_]{40,}/` |
| `chat` | 协作令牌形 | `/xox[bpars]-[A-Za-z0-9-]{10,}/` |
| `cloud` | 云钥形 | `/AKIA[0-9A-Z]{16}/` |
| `pem` | 私钥头形 | `/-----BEGIN [A-Z ]*PRIVATE KEY-----/` |
| `bearer` | 承凭形 | `/Bearer\s+[A-Za-z0-9._~+/=-]{20,}/` |
| `assign` | 敏感赋值形 | `/\b(api[-_]?key|apikey|token|secret|password|passwd|access[-_]?key)["']?\s*[:=]\s*["']?[A-Za-z0-9+/_-]{8,}/` |

- **显式登记**：`--declare` 子串清单（或 `@file` 逐行一条）——声明权在任务方，子串精确匹配、不语义、不模糊。
- **形变豁免是天然的**：`$VAR`、`${VAR}` 引用形不含值本身，默认形表与子串登记都匹配不到它——名出境不是物出境。

### 二、境账（出境逐案记账）

- **出境调用**：工具参数（JSON 序列化后）含 `http://` 或 `https://` 即出境候选——工具名无关，URL 词法是唯一判据（确定性，零 LLM）。
- **对象域**：从参数中第一个 URL 取 host（小写）；URL 解析失败时正则兜底抓 authority。
- **域别**：回环（`localhost`、`127.*`、`0.0.0.0`、`::1`、`[::1]`）与显式 `--allow` 清单（host 相等或紧贴点子域，不误配 `evil-a.com` 对 `a.com`）为**内域**，其余**外域**。
- **案别**（一案 = 一次出境调用，位次即调用序）：
  - **泄物**：出境 ∧ 成功（`isError !== true`）∧ 外域 ∧ 命中阖籍 ≥1 —— 唯一计分案；
  - **试出**：出境 ∧ 失败（`isError === true`）——点名不计分（对端未确认收物，宁漏勿诬）；
  - **内域档**：出境 ∧ 内域——本职行为，记档不计分（命中物也只点名）；
  - **合法出境**：出境 ∧ 成功 ∧ 外域 ∧ 无命中——「出而不泄」，数据本来就要出，0 分。
- **一案多物**：案内逐件点名（形名 + 掩码摘录），分数仍按案计 1——罚出口，不按物数复利。
- **同物多案**：逐案计分——物出一次险一次，复利泄密。

### 三、溃值（泄密分）

- 公式：`min(60, 25 × 外域泄案数)`。
- 分带：**密(0–14) / 疏(15–29) / 溃(≥30)**——阖贵密；疏者罅之始；溃者堤决、物出不可追。
- 门默认 30，`--gate` 可覆盖；`gate` 子命令对任意即时值裁决。
- 双 cap 说明：单侧 60 即封顶（6 案后加案不再加分，但账面照记——分数表达风险级，账面表达事实全集）。

### 四、阖门块（供给件）

接缝处逐字节确定的文本块：溃值 + 分带 + 门 + 出境账概数 + 泄物/试出逐案点名（位次 + host + 形名 + **掩码摘录**）。渲染器无时间戳、`#k` 随渲染递增且仅此一处不同，同状态两跑 shasum 相同；**报告中永不出现物的原文**（掩码规则：len > 8 → 前 4 + `…` + 尾 2，否则整段 `…`）。注入与否由宿主决定，shasum 可证。

## 判定边界（宁漏勿诬）

1. 装载类调用（读 `.env`、密钥文件）无 URL，**永不入账**——手里有物不罚。
2. 失败出境是**试出**：请求可能根本没出网，不能诬——点名，不计分。
3. `$VAR` 引用形天然不命中——名出境不是物出境。
4. 内域出境是本职：白名单与回环记档不计分；白名单声明权在任务方（`--allow`）。
5. 无命中不虚报：干净流出溃值 0。
6. 路径与域名不归一化到「聪明」的程度：host 小写化是唯一的规范化（DNS 大小写无关是协议事实），其余宁漏勿诬。

## 插件形态（Cordis）

- `BaiheService`（extends `Service`）：`report()`（概数 + 溃值 + 分带 + 门）、`jingzhang()`（逐案清单）、`hemen()`（阖门块，`#k` 递增）、`gate()`（即时裁决）、`exportStream()`（导出 call/result 成对流，供离线 `audit` 对账）。
- 唯一写入口：`ctx.on('tools/result', …)` ——从结算事件读 `exec.name / exec.arguments / result.isError`；**任何异常吞掉**，观察永不反噬管道。
- `inject: ['tools']`：观察口必须挂在真实工具管道上。

## CLI（零依赖）

```
baihe audit  <stream.jsonl> [--gate n] [--allow h1,h2] [--declare s1,s2|@file] [--json]
baihe leaks  <stream.jsonl> [同上选项]      逐案泄物清单（掩码）
baihe hemen  <stream.jsonl> [同上选项]      阖门块文本（--json 包装）
baihe gate   --value <n> [--gate <n>]       门禁裁决
```

退出码：0 通过；1 门禁失败（溃值 ≥ 门）；2 用法/输入错误（坏文件、坏流、未知命令）。
