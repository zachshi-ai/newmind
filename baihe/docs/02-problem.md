# 02 · 问题定义：谁、在什么场景下、有什么问题、价值何在

按「伪需求检验」的顺序写：先给场景和反事实，再给价值，最后自检。

## 目标用户

在 DeepSeek Harness（或任何 Cordis 架构的 Agent 运行时）上**委派长任务**的工程师与安全负责人，以及给 Agent 会话设 CI 门禁的平台方。他们已装齐十层治理（zhizhi 拦动作、jiebi 审判断、zhengnian 守本愿、weibing 诊开工、buer 记教训〔在途〕、jiubian 勘应变、youya 巡见闻、lunshi 审输入、dingfen 定并发〔在途〕、licheng 结承诺〔在途〕），但有一个通道至今无人看守：**参数出境的那条单向门**。Agent 装载进来的密钥与敏感数据，在出境类调用里原样发往外部——没有机制看见，没有账可查，没有分可计。

## 四个场景

### 场景 1 · 密钥随行出境（机关一开，物不可追）

40 轮的联调任务。第 3 轮 Agent 为了调试读了 `.env`（域内行为，完全合法）；第 20 轮它把第三方 API 接入调通，`curl https://api.vendor.ai/v1?token=sk-live-8f3k…` ——密钥**原样出境**。对端日志、网关缓存、链路探测，物到了就是到了。用户事后最贵的处置是「轮换全部密钥」，因为没人说得清：泄了几处、泄到哪几个域、是哪几轮出的手。想自己查，只能通读全量 transcript 逐个翻参数。

**反事实**：有境账，第 20 轮的出境当场成为账面一案：外域泄物，掩码点名 `sk-l…8f`，溃值 +25。会话结束 CI 门禁红灯——轮换范围从「全部」缩到「点名清单所列」，处置成本从不可核算变成逐案可核。

### 场景 2 · 数据静默出域（内部之物，给错了人）

Agent 把内部代码片段、客户样例数据发给第三方「翻译 / 格式化 / 摘要」API——工具调用看起来人畜无害，参数里出境的是内部之物。这不是幻觉（jiebi 地盘）、不是注入（lunshi 地盘：那些是「进来的内容冒充发令」）、也不是动作失控（zhizhi 地盘：调用本身完全合法）——**是出域方向的权界失守**：物是好的，出口是错的。

**反事实**：阖籍显式登记「客户样例数据」的物征后，每次含它的出境都在账面逐案点名；外域出境与内域出境分账，谁把内部之物给错了域，一目了然。

### 场景 3 · 分域无据（对阳言与对阴言，一个规矩）

同一个凭据，发给自家网关（`api.internal.corp`——本职，合法）与发给陌生域名（事故），在今天的审计里毫无区别。平台方想给「内域出境放行、外域出境断言」设 CI 门禁，连表达这件事的字段都没有。

**反事实**：域别是境账的一等字段——回环与白名单内域出境记档不计分（声明权在任务方），外域泄物才计分门禁。「对内依本职，对外依权界」从口头规矩变成逐案可查的账。

### 场景 4 · 历史不可验尸（反以观往，无往可观）

合规审查问：「上季度跑过的所有会话里，有没有密钥发到过第三方？」——今天的答案是「不知道」，因为出境从来不是账面事件。

**反事实**：捭阖的 CLI 契约无关、可验尸任何历史会话流：`baihe audit stream.jsonl` 对离线流逐案重放，与在线账本逐字对账——「反以观往，覆以验来」。

## 价值

1. **泄密从「无人看见」变成「账上见」**：出境逐案入账，溃值 0–60 分带门禁（密 / 疏 / 溃），CI 可断言。
2. **处置从「全部轮换」变成「点名轮换」**：阖门块逐案点名（位次 + host + 形名 + 掩码摘录），物不可追，但账可追。
3. **权界从「口头规矩」变成「域别字段」**：内域本职、外域断言，声明权在任务方。
4. **与 lunshi 合拢成权界闭环**：输入侧「物不僭主」、输出侧「物不轻出」——渠道权界与出域权界一起，才是完整的「口之门户」治理。

## 伪需求自检

- **谁在付代价？**密钥出境的轮换成本、数据出域的合规风险、事故后的排查人时——全部真实发生在委派 Agent 的团队身上。
- **不做会怎样？**出境永远是无账面的暗事件；OWASP LLM06 长期靠「希望它别发生」来治理。
- **为什么现在做不了别的层？**lunshi 的世牌打在**进来的内容**上，zhizhi 的拦截针对**动作危险本身**；「参数里的敏感物流向了哪个域」这个方向性的事实，十层里没有任何一层的账本有字段承载它。
- **可证伪吗？**三夹具期望值先于实现手算；泄物判定逐案可逐字复核（形表是公开的显式清单）；门禁是退出码。
