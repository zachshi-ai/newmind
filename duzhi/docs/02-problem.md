# 02 · 问题定义：谁、在什么场景下、有什么问题、价值何在

按「伪需求检验」的顺序写：先给场景和反事实，再给价值，最后自检。

## 目标用户

在 DeepSeek Harness（或任何 Cordis 架构的 Agent 运行时）上**委派长任务**的工程师与团队、给 Agent 任务设预算与门禁的平台方、以及需要对「Agent 到底花了多少」做 showback 的组织。他们已装齐十余层治理（zhizhi 拦动作、jiebi 审判断、zhengnian 守本愿、weibing 体检开工、jiubian 勘应变、youya 守记忆、lunshi 审输入、dingfen 封写域、baihe 守出境、zhibi 保记录〔在途〕、buer 记教训〔在途〕、licheng 追承诺〔在途〕、fayi 审量尺〔在途〕、yuli 审退路〔在途〕），但有一件东西至今无人记账：**这一任花掉的总量**。每一次工具调用都是一次真实的支出（模型回合、时延、风险面），时长一分一秒都在走表——而「花了多少」没有任何一层的账本有字段承载。

## 四个场景

### 场景 1 · 跑穿（无线可越，故无越可言）

一个「改个登录 bug」的任务。Agent 第 1 轮读文件、第 40 轮还在重构不相干的工具函数、第 180 轮在为一个断言反复跑全量测试——过夜跑穿，烧掉的调用与钟点无人知晓。知止数行为：没有死循环（每一步都不同）；九变勘应变：没有失败在先，谈不上盲捶；有涯巡记忆：没有原样重读。**每一层都干净，因为每一层都只看单案的性质**——而「这单活花了 214 次调用、3 小时 40 分钟」这件事，任何一层的账本上都无处安放，灾后只能全量翻 transcript 人肉数数。更根本的：**从来没有人说过这单活值多少**——无线可越，所以「越线」这个词根本无从谈起。

**反事实**：若度支在册，制册声明 `maxCalls: 60 / maxMinutes: 45`，则第 61 次调用起每一案记逾案 +6，门禁红灯亮在**第 63 次调用**（越线 3 案 = 18 → 急；越线 5 案 = 30 → 非）——「花穿了」从灾后印象变成账面上带序号与时刻的硬数字。

### 场景 2 · 有线无账（写了白写）

任务书明明写了「控制在 100 次调用以内」。但没有任何东西**对账**：Agent 第 101 次调用发生时无人在场、无物亮灯；收工报告「任务完成」，写了白写。治未病望诊看得出任务书**有没有**止法条款（在场性），但「止法有没有被执行」是 t>0 的数值问题——体检层与运行层之间，缺的正是对账层。

**反事实**：制册即任务书的机器可读形态：`duzhi audit 完工流.jsonl --register .duzhi.json` 一次审计，越线与否、越线几案、每案在第几次调用、当时时程几许——全部逐案点名。

### 场景 3 · 并行烧穿（分了地，没分钱包）

四会话并行作业（dingfen 分册定界，写域各安其分）。但写域不等于钱包：四个会话各烧各的，总量无人知道——直到月账单来。组织想回答「上周边改登录这个任务群花了多少」，仍然只能全量翻流。

**反事实**：每流一份用账（`duzhi audit` 逐流离线可跑），任务群的总量是四份报告的和——showback 的前提第一次成立。

### 场景 4 · 对照——有制不逾、贴线、追认、无时皆有其判

- **有制不逾**：制册在线内走完 → 制值 0（足），门禁绿灯——本层不冤枉守界的花销；
- **贴线告急**：越线 1–2 案（6–12）→ 足带黄灯不门禁；越线 3–4 案（18–24）→ 急带黄牌——蓄薄有刻度，不是只有红绿两态；
- **追认验尸**：历史流当时无册 → 无制 40（非，诚实报告「从未受量纲约束」）；审计者追认 `--max-calls 30` → 重放立见越线几案——补线不伪，越线是硬数字；
- **无时不判**：老流没有 `at` → 时长维度诚实退化（spanMs null、时程逾案不判），调用维度照判——宁可漏判，不可妄断。

## 价值

1. **把「烧穿」从印象变成账面事实**：越线有案、有序号、有时刻、有经由（调用过线 / 时程过线），门禁可断言（≥30 退出码 1），CI 可拦截；
2. **把「预算」从纪律变成制册**：线由任务方先立（声明权在冢宰），Agent 无从自我发额度——写了就不再白写；
3. **运行中可见余量**：余量块在接缝处供给蓄支图（入 / 出 / 蓄 / 带 / 逾点名，逐字节确定）——Agent 与宿主第一次能看见「还剩多少」；
4. **历史流可验尸可追认**：契约无关——任何历史会话流离线可审；无册诚实报无制，补线立见越线；
5. **零 LLM、零拦截**：纯确定性对账，结构性零拦截——账与闸分治（闸是知止的地盘），挂上即用。

## 伪需求自检

- **反事实存在吗**：存在——灾后只能全量人肉翻 transcript 数调用；且「这单活该花多少」从未被任何人声明，三问（花多少/该多少/何时越线）在现有十余层账本上无一有字段承载；
- **可测量吗**：调用数在流里逐案可数；时程由 `at` 逐案可导——两个量纲全程确定性，零语义、零 LLM；
- **可证伪吗**：追认一条线，越线案数是硬数字，复现命令一键可跑；夹具期望值先于实现手算锁死；
- **是不是别层已做的**：十三层 + 在途五层全部审**单案性质**（行为/判断/意图/体检/应变/记忆/渠道/写域/出境/记录/教训/承诺/量尺/退路），无一审**总量对账**——量纲维度是空位；
- **是不是真痛**：Agent 跑穿是部署侧最常见的事故形态之一；FinOps 已成云支出标准学科而 Agent 侧无对应物——量入为出缺的不是概念，是落到会话流上的账。
