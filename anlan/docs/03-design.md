# 03 · 设计：安澜 · anlan —— DeepSeek Harness 的响应性施治治理（安澜式插件）

> 本文锁死全部判定语义；实现与本文冲突时改实现，不改本文与 04 的手算期望。

## 1. 能力类型与接缝

新能力类型：**安澜式插件**（第四十六个）。jiubian 证明败后行为可勘（势
账——失败侧的重复），huiji 证明言面对账本极性可审（愈对红）——安澜证
明插件可以审**同一对象胜负序列对搅动序列的净效果**：每一帧施治皆有据，
序列上叠三搅二即荡。诊断（验证胜负）在流里，搅动（成功之写）在流里，
两处皆流内事件、逐字可数——**波不皆信号，治必对波**。

```
tools/result   emit   波账收全流（exec 成败旗标 × 诊形 + write 搅迹），
（无 pre-execute）     judge 时按当时全流现算 —— 零拦截是结构性的
```

设计约束（与全仓同规）：模型无关（零 LLM、零提示词注入、零网络、零子进
程、零文件系统探测——波、搅全取自流内词面与事件）；观察永不反噬（监听
器异常吞掉，管道照常）；澜册持久化归 CLI（register/revoke），插件只吃
注入的 book 对象；单会话视图的案与值只采本会话（跨会话波账归并归离线合
并审计）。

## 2. 对象与通道（通道锁死）

对象键与工具族同全仓（object.js 同规：`p:` 文件 / `c:` 命令 / `n:`
不透明；observe/write/exec/other 四族——write 族含 edit/patch/apply 等
改动类工具）。径规整同全仓（反斜杠归正斜杠、剥 `./` 前缀、剥尾 `/`）。

**波账收全流，胜负只认 exec，搅动只认成功之写**：

- **exec 族**是状态笔的唯一通道（§4）——跑出胜负的命令才记波；
- **write 族**（成功）是搅笔的唯一通道（§5）——落盘的改动才算搅；
- observe/other 永不生状态笔、永不生搅笔（读取不记波、不动手不算搅
  ——看见失败输出不算自己的诊，同 huiji 先例）；
- 本层**零稿面**：无愈形、无判形、无径门——全流 exec/write 皆入账，
  豁免在对象（澜册 spare，§8）。与 huiji/kuijing/zizhao 的稿面行级词法
  是结构性区别：本层审动作与胜负的序列，不审一句话。

## 3. 诊形（验证命令词法，默认内置，零 LLM）

exec 族调用，命令原文小写化后子串命中任一诊形 → 该次 exec 是一次验证
之诊（一次落点）。诊形是公开验证命令词族（与 huiji 检形同族谱不同账：
huiji 记单帧胜负挂疾痊，本层记状态排序列），默认 44 形，册 `forms` 增
形、`noDefaults` 可关：

npm test、npm run test、npm run check、npm run lint、npm run build、
pnpm test、pnpm lint、yarn test、yarn lint、bun test、vitest、jest、
mocha、karma、cypress run、playwright test、pytest、py.test、tox、
go test、go vet、cargo test、cargo check、cargo clippy、gradle test、
gradlew test、mvn test、phpunit、dotnet test、deno test、mix test、
rake test、swift test、make test、make check、make lint、tsc、eslint、
ruff、flake8、pylint、rubocop、golangci、shellcheck（44 形）

非诊形 exec 永不入波账（`node gen.js`、`terraform apply`、`npm publish`
皆非验证之诊——成功失败都不记）。

## 4. 状态笔（波账的流内事件）

**顺笔**（绿）：exec 族 ∧ `isError === false` ∧ 命中诊形。
**逆笔**（红）：exec 族 ∧ `isError === true` ∧ 命中诊形。
`isError === null`（老流）不记笔（成败未知不诬波——诚实退化，同 huiji
既知代价）。

**对象归属**（逐笔，按序）：

1. **点笔**：命令原文 ∪ 结果 content 含某对象词元（ASCII 切词见 §6）→
   该对象记一笔此极性（`npm test -- auth` 红了，auth 翻逆）；
2. **全科笔**：命令剥去诊形命中片段后，余文 ASCII 词元只剩旗标词
   （`-` 开头）∪ 脚手架词（npx/node/yarn/pnpm/npm/make/run）——全量形
   （`npm test` 裸跑）：
   - 顺笔 → **全部在场对象**（此前波账中已有状态笔者）各记一笔顺（全科
     复验通过——从宽方向，同 huiji 扫痊）；
   - 逆笔 → 只记输出词元命中者（红不诬未点名对象——**无矢之红不挂**，
     宁纵；输出空则无对象挂账）；
3. 两不沾（点笔无词元命中 ∧ 非全量形）→ 该笔不挂任何对象（既知漏判，
   宁纵）。

（「在场」以状态笔为准——只被搅过、从未被诊过的对象不在场。全科顺笔给
在场对象记顺，不给空气立对象。）

## 5. 搅笔（施治形迹的流内事件）

**搅笔**：write 族 ∧ `isError !== true` ∧（径原文 ∪ `args.content`）
含某对象词元 → 该对象一笔搅笔。isError === true 之写不入（没落盘不算
搅）；isError 未知（null，老流）按已发生；无 content 之写径命中亦搅
（径本身可搅——改名/触写也是搅）；observe/other 永不搅。

搅笔不问极性不问动机（词法不辨「为修而改」与「顺手而改」——既知代价，
§13）；搅笔只在与状态笔同对象时对账（搅 cache 不入 auth 的搅窗）。

## 6. 对象词元（ASCII 路 only，同全仓规）

exec/write 的词法面（命令原文 ∪ content ∪ 径）按 `[A-Za-z0-9_\-./@]+`
切词，剥尾部句点；过滤：停词 37（the a an of and or is was are were be
to for in on with that this it not when but as at by from ∪ no never
cannot without will would should plan we our us，大小写不敏感全等）、纯
数字、长度 <2 且不含 `./_\-@`（普通词元须 ≥3）；路径形 token
（src/auth.js）保留。CJK 词元不参与对账（「登录模块」无机器名可对——
宁纵，同全仓既知代价）。

**词元匹配从宽**：对象词元 t 与搅笔词法面 w——w 含 t 子串即认（auth ⊂
src/auth.js）；状态笔同法（命令 ∪ content 含 t 子串）。

## 7. 判定序（每对象锁死）

对每对象 t，取其状态笔序列 S（流序，含全科笔衍生），与搅笔集 J：

- |S| < 2 → 静默（无波可言——单帧无所谓振荡，无诊之对象更不判）；
- **叠数** = |{ i : S[i+1] 极性 ≠ S[i] 极性 }|（相邻异极对数）；
- **搅窗** = J 中落在状态笔区间内的笔数——搅笔笔序严格大于首状态笔、
  严格小于末状态笔（夹在胜负之间才算搅进这局波；首笔前是未验先改、末笔
  后是波定之后，皆不入窗——既知代价 §13）；
- **叠数 ≥3 ∧ 搅窗 ≥2 → 荡案**（+30/案，dang 计数，单案即红）——漏斗
  规则二/三：三叠两搅，逐帧互拆；
- **叠数 ≥3 ∧ 搅窗 <2 → 风浪注记**（0 分，fl 计数）——红珠实验：波自
  翻转而手未动它，环境之波非人祸；
- **叠数 ≤2 → 静默**（单轮修复/单次回归——守准之德不入罪；「治了又坏
  一轮」的最小嫌疑形叠 2 搅 2 亦让渡不判，宁纵 §13）；
- 案序：对象键字典序；一对象至多一案（本层审对象全史，对象级立案——非
  行级，与稿面层结构不同）。

## 8. 澜册与豁免

册形 `{ "version": 1, "forms": ["mvn verify"], "noDefaults": false,
"spare": ["auth"] }`。**spare 豁对象**：对象词元（小写全等）在册者，其
波账不判不记案（名分在册——任务方明言「此对象波动已知」，flaky 之名的
正式归宿）；**无册照判**（凡荡必审——波动之验不挑对象，豁免授权只能来
自册）。forms 增诊形；noDefaults 关默认诊形表。register/revoke 归
CLI；插件只吃注入的 book 对象。本层无稿面豁免、无名段静养（零稿面——
豁免唯对象一途）。

**合审序（CLI 多流）**：全 at 有数 → `(at, 流序, 流内序)` 稳定排序；
否则参序拼接（审计方须自证流序）。单会话运行时视图同法自洽。

## 9. 判定序（全流锁死）

1. **逐笔记账**（recordCall 只记账）：exec 族判状态笔挂对象；write 族
   成功记搅笔挂对象；observe/other 不入；
2. **澜册前置**：spare 命中对象的时间线整线免审（不判不记案，静默）；
3. **逐对象判定**（对象键字典序）：按 §7 锁死序判荡案/风浪/静默；
4. **judge 幂等**：判词在 judge 时按当时全流现算，同流重放必得同判词；
5. 案排序锁死：对象键字典序。

## 10. 荡值门禁

```
dang值 = min(60, 30 × dang)
total  = min(100, dang值)
```

分带：**平 0–14 / 漾 15–29 / 荡 ≥30**；门默认 30——**单荡案即红**（三
叠两搅就够）。counts：`dang` 荡案 / `feng` 风浪，附审计透明量
`zhen` 顺笔 / `ni` 逆笔 / `jiao` 搅笔（全流计数，不入分）。

## 12. 边界（与相邻各层）

- **zhizhi**：一据一澜。它数 turn 级验证性证据之有无（对象盲——跑过即
  有据），拦重复失败死循环（失败侧的动作节制）；本层审胜负序列的净效果
  （对象×叠数×搅窗）。它问「验过没有」，本层问「翻了几叠、动了几次手」。
- **jiubian**：一败一澜。它勘失败后的行为重复（盲捶=无再察的同一失败再
  捶——**失败侧通道**）；本层审的乒乓每一帧都**成功绿过**（施治后是绿
  的），盲捶结构性看不见。又捶又荡的会话两边各立案（失败再捶归它、绿后
  互拆归本层）。
- **huiji**：一愈一澜。它审稿面愈言对流内未决红（言面对账——本场景末
  帧绿、无红可盖，愈形不适用）；本层零稿面，审动作序列对胜负序列（搅对
  波）。言与行两账。
- **zhizu**：一量一澜。它量单次写入规模（巨写=一次大手术）；本层审 N 次
  小刀的序列净效果（每刀皆小、序列成荡）。一次手术与十次小刀两账并行。
- **xiaoyan**：一报一澜。它称成功信号的成色（空言/回令）；本层只记极性
  不问成色（断言恒真的绿也是绿——虚器归 fayi 它处，本层信旗标同 huiji）。
- **fayi**：一尺一澜。它审尺本身弯没弯（改测试放行、纯器写独占窗）；本
  层审被测物的序列（改的是实现不是尺）。器写与搅笔若同窗同物，两堂并行
  ——它审尺污、本审荡。
- **shihu**：一状一澜。它审交接径完成态声明对作工面（言面对作工）；本
  层零言面（无声明可审）。状与波两账。
- **licheng**：一诺一澜。它结话语承诺（未来时之诺）；本层零话语。诺与
  搅两账。
- **shenqu**：一卷一澜。它审动刀前读据残全（取窗即动）；本层审动刀后胜
  负翻没翻。前视与后视两账。
- **kuijing**：一句一澜。它审两句话对彼此（立场翻转——稿面对稿面）；本
  层零稿面（动作对胜负）。句与序列两账。
- **zizhao**：一弃一澜。它审弃责宣告对红账（言面）；本层零言面。
- **suliu/chachu/zhixia/jiaotuo**：归因、立言、自洽、虚引皆稿面或言面
  判定；本层零稿面——正交。
- **youya**（复见/复命——重复读、重复跑）：它审「世未变而它忘了」（成
  功基线 + 其间无写 → 同串重跑是浪费）；本层审「波在翻而它在搅」（胜负
  交替 + 搅动成荡是拆台）。同串复命与三叠两搅不同形：复命是同串重复，荡
  案是极性交替——两账并行。
- **yuli/yidao/xiangxiao/hengfa/fangchuan/pingzhun/baihe/yuanyu/
  shuitu/shefa/saowu/huashui/yuefa/duzhi/erbing/dingfen/lunshi/
  chengshi/weibing/jiebi/zhengnian/zhongshi/kaocheng/zhixing** 诸层各
  守行前退路、守门开关、批评通道、规矩源、吞错入码、依赖籍面、出境、入
  目、常驻境变、落物归宿、调试残垢、落笔时鲜、公面、花销、权柄、写域、
  渠道权威、已遂重施、开工体检、判断校准、本愿在场、任务项终始、交付契
  约、知行合行——与胜负序列的净效果账正交。
- **buer**：跨会话教训归它，合审波账互认只是离线重放归并，本层不做任何
  跨会话学习。

## 13. 既知代价（宁漏勿诬的让渡，逐条登记）

- **叠 2 搅 2 不判**：「红→搅→绿→搅→红」一轮嫌疑（治了又坏）与单轮修
  复的边界在词法上不可分——v1 宁纵，既知最大漏判登记；
- **搅笔从宽**：词法不辨动机——改 auth 文档、改 auth 注释都算搅 auth
  （词面不可分意图）；搅窗内任何搅笔计入，不辨是否「针对上红的修复」
  ——从宽方向是案多，澜册 spare 是任务方的救济之途；
- **全科顺笔从宽**：全量绿给在场对象记顺——其他对象随之记顺（据多则案
  少）；全科逆笔只记输出词元（裸跑红输出空=无矢不挂——既知漏判）；
- **旗标信流**：流被洗白（`\|\| true` 归 zhibi 讳笔、断言恒真归 fayi
  虚器）时波账随之失真——本层只记旗标胜负，信流同 huiji 检形先例；
- **isError null 老流不记**（成败未知——诚实退化）；无 content 且命令
  无词元的诊形 exec 不挂对象；
- **首笔前/末笔后的搅笔不入窗**（未验先改与波定后改不参与本局对账——
  既知代价；「波定后的改」若引发下一局波，自见天日）；
- **CJK 词元不入对账**（「登录模块」无机器名可对——宁纵）；词元匹配子
  串从宽（auth ⊂ auth_spec 误挂同窗——既知代价）；
- **一对象一案**：对象全史合判，不逐笔翻案——中途曾收敛不撤案（序列罪
  以全史为凭，同 kuijing 判账历史全保之理）；风浪与荡案不并立（同一对
  象叠三后按搅窗归档）；
- 非诊形 exec 不入（`npm publish`、`terraform apply` 皆非验证——宁
  纵）；诊形从宽（命令含形即认——`cat jest.config.js` 之败可误挂既知
  代价，同 huiji 检形）；时序以流序为准（缺 at 照判）；零 LLM。
