# 02 · 问题：Agent 响应性施治（逐帧皆真的修复乒乓——单帧皆真，序列皆妄）

## 谁在什么场景下的什么问题

**谁**：任务方与每一个照交付决策的人与会话——照「测试全绿」签收发版的
项目方、照「修复完成」合并 PR 的 reviewer、接手下一单的会话；以及 agent
自己——每一次搅动注入的改动面，最后都要有人来背。

**场景**：agent 修一单活。`npm test -- auth` 红了（真回归或环境抖动，
agent 分不清，谁在单帧里都分不清）→ 改 `src/auth.js` → 复跑绿了 → 几步
之后又红 → 又改一笔 → 又绿……交付时 `npm test` 全绿，报告写「修复完成，
验证通过」——**每一帧都经得起现有全部相邻层的审计**：上帧确实红（有
据）、这一改确实落盘成功（有作工）、末帧确实绿（无红可盖）、单刀确实不
巨（量出无碍）。但序列上：auth 翻了三叠、它搅了三次——净效果趋零，改动
却是真实注入。另一种更常见的形：红的其实是 flaky，agent 逐帧响应，为噪
声注入了五处真实改动——每一处都是新的风险面。

**问题**：响应性施治**无账**：

- **单帧皆真**：每次施治都有充分理由（上帧确实红了），任何单帧审计都看
  不见罪——理由在上一帧，罪在序列里；
- **序列皆妄**：叠三搅二的序列在结构上就是乒乓——戴明用漏斗实验四十年
  前就证明了对稳定散布做响应性调整只会放大变异，agent 每一次都把这个实
  验重演一遍；
- **波与治混同**：flaky（环境波动）与乒乓（施治振荡）在单帧里完全同形
  ——只有「交替之间动没动它」能把两者分开，而动与不动只存在于流内时序
  里；
- **净效果无人审**：改了五次、代码回到近似原样、改动面净增——这个三段
  式结论只存在于序列里，而全部相邻层都只审一帧（证据有无、作工有无、成
  色如何、量出几何），没有一层审「同一对象验证态的翻转史对搅动史」。

相邻层的空白地：zhizhi 数 turn 级证据之有无（跑过即有据——**对象盲**，
不问翻了几叠）；jiubian 勘失败后的行为重复（盲捶=「无再察的同一失败再
捶」——乒乓的每一帧都**成功绿过**，失败侧通道结构性看不见）；huiji 审
痊愈宣称对未决红（本场景末帧是绿的——**无红可盖，稿面通道不适用**）；
zhizu 量单次写入规模（巨写是一次大手术——**N 次小刀的序列净效果非其
对象**）；shenqu 审读据残全（动刀前的全貌——**不问动刀之后翻没翻**）；
kuijing 审两句话对彼此（立场对立场——**本层无一句话，只有动作与胜负**）
——**每层都审一句话或一帧对世界；没有一层审同一对象的胜负序列对搅动序
列**：波账 (−)(+)(−)(+) × 搅窗有迹。本层审**序列对序列**——每层都审一
帧，本层是第一层审净效果。

## 问题（治什么病）

一个病根、三档判别，全部真实存在、全部当众可验：

| 档 | 卷面形迹 | 现实对应 |
|------|----------|----------|
| **荡案**（立案档 +30/案） | 同一验证对象的胜负序列叠数 ≥3，且翻转区间内该对象的搅动形迹 ≥2 笔 | 红→改→绿→改→红→改→绿——每帧皆真、逐帧互拆的乒乓（漏斗规则二/三） |
| **风浪**（注记档 0 分） | 同一对象叠数 ≥3，而搅窗 <2 笔（一次没动它，波自翻转） | flaky/网络抖动——环境之波非人祸（红珠实验：波动来自系统），留痕给任务方摘噪声 |
| **静默**（清白档） | 叠数 ≤2（单轮修复/单次回归/单帧验证） | 红→改→绿收工——漏斗规则一的守准之德，本层为它留名不入罪 |

价值锚点：「这串红绿交替的账上，它动了几次手、净效果是治病还是翻波」
是**零 LLM 能确定性回答的一问**——胜负笔是流内 exec 的成败旗标 × 诊形
词面，对象词元是 ASCII 切片，搅笔是 write 族成功之写的径与文切词，叠数
与搅窗是流内序列的逐字节可复算计数；不需要稿外之物（不读文件系统、不装
语料、不跑模型）。本层不做语义判断（不判那一红是不是真回归、那一改是不
是「好的修复」——裁决权归人），只做序列结构判断（波必有对象、对象必有
诊、叠必过三、叠间必有搅、搅必过二、过则立案）。

## 价值（为什么不是伪需求）

1. **修复乒乓是真实且高价的病形**：agentic coding 的高频抱怨就是
   churn——为 flaky 抖动逐帧改代码、修 A 拆 B 的来回横跳、交付时全绿而
   改动面净增；基准评测的回归项与业界「agent 改动需人工逐笔复核」的共
   识都是此病的结构性招供；修复乒乓正是这一族病的**最小可判定内核**
   （胜负叠三 × 搅动过二 × 同一对象）；
2. **清白道宽、立案门窄**：叠 ≤2 静默（单轮修复是最健康的循环，本层为
   它留名）、无搅之风浪 0 分注记（环境之波不入罪，flaky 顺手检出）、无
   诊之对象不判（从未验过就无所谓振荡——那是 zhizhi 的证据账）、澜册
   spare 名分在册免审（任务方明言「此对象波动已知」）——只有「胜负叠三
   ∧ 交替确搅」才立案，不冤守准者；
3. **记账不禁言**：不拦写、不改流、不跑语义分析——胜负与搅动全是公开
   词法与流内事件比对，观察式插件结构性零拦截，观察永不反噬；
4. **守准有奖、噪声有主**：单轮收敛不判——本层结构性地奖励「看准再动
   手、一次治好」；风浪注记把 flaky 从乒乓里摘出来交还任务方（环境之波
   是系统之责，不是 agent 之罪，更不该由 agent 用真实改动去「治」）；
5. **与相邻各层谓词正交而非重叠**：zhizhi 数证据有无（turn 级、对象
   盲）、jiubian 勘败后行为重复（失败侧——乒乓每帧皆绿）、huiji 审稿面
   痊愈宣称（本层零稿面）、zhizu 量单次写入（一次大手术 vs N 次小刀序
   列）、shihu 审状词对作工（言面）、xiaoyan 称成功信号成色（单帧成
   色）——本层审**胜负序列 × 搅动序列**，两账皆流内事件，序列级审计全
   仓真空由本层接住；
6. **可证伪**：诊形、状态笔、搅笔、叠数、搅窗、荡案、风浪全部锁死于
   03；同流重放必得同判词；跨项目历史流可验尸复算——错了改实现，不改
   标准。

## 产品形态

- **安澜式插件**（DeepSeek Harness 插件层，Cordis，结构性零拦截）：挂
  `tools/result` 观察口，波账收全流（exec 成败旗标 × 诊形 × 对象词元 +
  write 搅迹），judge 时按当时全流现算，荡牌块接缝供给；
- **零依赖审计 CLI**（`anlan`）：多流离线合审（跨会话波账归并），可验
  尸任何历史会话；
- **Agent Skill**：给派活方与 agent 的息浪协议（波不皆信号、治必对波、
  单轮守准、叠三搅二即荡、风浪还给系统）。
