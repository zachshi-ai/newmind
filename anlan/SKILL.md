# 安澜 · Anlan — Agent 息浪协议

> **「若过程处于稳定状态，对它做出响应性调整，只会使变异越来越大。」
> ——戴明《转危为安》漏斗实验（据通行中译本转述）**

你每一次改动都有充分理由——上一帧确实红了。但拉通看：红→改→绿→改→
红→改→绿，叠了三次、搅了三次，净效果趋零，而每次搅动注入的都是实打实
的新改动、新风险面。漏斗实验四十年前就证明了：对稳定散布做响应性调整，
每一步都「正确」，序列上放大变异。失败的红未必是信号——flaky、网络、
缓存抖出的红，你逐帧去「治」，就是在为噪声注入真实改动。本协议不限制你
动手（拦是知止的地盘），它要求：**波不皆信号、治必对波、一次治好**——
单轮收敛是有账之治；叠三搅二，当众留痕。

## 何时用此 Skill

- 工程师想防住「agent 修 A 拆 B 的乒乓修复 / 为 flaky 逐帧改代码」
  ——churn 是 agentic coding 的高频抱怨（改动面净增而净效果趋零）；
- CI 需要一道振荡门禁（荡值 ≥ 30 即红——单荡案即红）；
- 团队想要一个 flaky 检出器——风浪注记把「波自翻转而手未动」的对象摘
  出来交还任务方（环境之波是系统之责，不该由 agent 用真实改动去治）；
- Agent 需要自查：我动这几刀，是把病治了，还是把水搅浑了？红了先复跑
  一次再动手——复跑还红才是信号，复跑绿了是波动。

## 给派活的工程师

1. **装机**：把 `anlan` 插件挂上 Cordis 管道（`tools/result` 观察口，
   结构性零拦截——它只记账，永不拦工具）；CI 里跑 `anlan audit`：
   荡值 ≥ 30 退出码 1，门禁即红；
2. **立册（可选）**：`anlan register --spare auth` 声明豁免对象（「此
   对象波动已知、勿审」——flaky 之名的正式归宿；波动之验不挑对象——
   豁免授权只能来自你的册，agent 无从自免）；
3. **读案卷**：`anlan block` 出荡牌块（澜册公示 + 词法公示 + 逐案点名
   `对象词元:案别:指纹`——永不携带命令/输出/搅笔原文，掩码是结构性的）；
4. **验尸任何历史会话**：`anlan audit <session.jsonl>` 离线重放，跨会
   话波账归并（甲会话的红绿与乙会话的搅动同一时间线排序，at 归并合审）。

## 给 Agent 自己

- **先复跑再动手**：红了别急着改——复跑一次还红才是信号，复跑绿了是
  波动；对波动施治就是在替系统打针，越治越荡；
- **一次治好**：单轮修复收敛（红→改→绿收工）是守准之德，本层不入罪
  ——漏斗规则一；叠三搅二的乒乓（规则二/三）才是荡案；
- **动它才算搅**：你的改动是否入账，看词面是否点到该对象（径与文命中
  对象词元）；改无关文件不洗振荡——序列罪以全史为凭，中途收敛不撤案；
- **风浪不是你的罪**：波自翻转而你没动它——风浪注记 0 分留痕，那是环
  境之波（红珠实验），报告给任务方而不是动手去「修」它；
- **无诊不判**：没跑过验证就无所谓振荡——但别以为看不见就是清白，证
  据之无是 zhizhi 的账，红上宣称绿是 huiji 的账。

## 判定序（每对象锁死）

状态笔序列（诊形 exec 红绿，null 不记）→ 叠数（相邻异极对数）→ 搅窗
（夹于首末状态笔之间的该对象搅笔数）→ 叠 ≥3 ∧ 搅窗 ≥2 = **荡案 +30**
/ 叠 ≥3 ∧ 搅窗 <2 = **风浪注记 0 分** / 叠 ≤2 = 静默。澜册 spare 整线
免审，无册照判。荡值 min(60, 30×荡案)，门默认 30——单荡案即红。
