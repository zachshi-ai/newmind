# 02 · 问题：Agent 境变不复位

## 场景（谁在什么场景下）

**谁**：DeepSeek Harness 上跑的编码 Agent（以及一切「会话流可重放」的 LLM 编码代理）的**任务方与审计方**——需要知道「机器为什么不一样了」的工程师、需要给共享机器立门禁的 CI、以及**下一个进场的会话**。

**场景一：善意的凿击。** Agent 修一个构建问题：`npm install -g pnpm` 装个全局工具用完没卸；调试鉴权顺手 `git config --global user.email bot@x` 改了全局身份没复原；验证服务起 `brew services start redis` 收工没停；`echo 'export FOO=1' >> ~/.zshrc` 追了一行环境变量。四笔都真实发生在共享机器上，任务宣告完成——水土全数留在场上。下一个会话（或明天的同款任务）在同一片水土上作业，行为已变；事后连「哪笔改动是谁在什么时候留下的、复位了没有」都无处问起。

**场景二：水土漂移的不可复现。** 上周全绿的测试套件今天红了，仓库 diff 里什么都没有——因为 diff 在机器里不在仓库里：某个早前会话 `npm config set registry`、`defaults write` 改了系统偏好、rc 文件里追了别名。工程师对 diff、翻提交，一无所获；「同一份任务书昨天绿今天红」的归因只能靠口口相传。GitClean 式的代码漂移有度量，机器水土的漂移全仓无账。

**场景三：常驻物的安全面。** 会话里 `docker run -d` 起的容器、`nohup` 挂的进程、`launchctl load` 装的代理、crontab 里加的计划任务——会话结束它们全都还在。持久化恰恰是恶意软件的立身之本：一个会留计划任务与常驻进程的 Agent，就是一台「干净基线」的洞。干净机器基线（clean-machine baseline）要成立，「哪笔常驻改动还没复位」必须可问——今天没有任何一层能答。

## 问题（治什么病）

**Agent 境变不复位**：会话流里每一次环境改动都真实发生了，但**没有任何一层审计常驻之境的改动与复位**——

- 本仓 #1–#25 已定标的各层层层核过登记表：知止拦「这一步该不该做」（行为拦截），shefa 审「散件的归宿」（临时之**物**），yuli 审「灭掉之前有没有备」（灭失之**备**），duzhi 量「花了几笔」（投入之**量**），yuanyu 禁「看进隐匿」（装载之**目**），mingshi 核「装的名有没有登记之实」（名实与供应链）——**「常驻之境被改了什么、复位了没有」全仓无账**。
- 结构性证据一：`--break-system-packages` 这个旗标的存在本身——pip 官方被 PEP 668 逼着承认「安装会冲破项目边界毁掉系统环境」，业界给这种病起了名字，却从没有一个账本能回答「哪个会话哪一笔改的、复位了没有」。
- 结构性证据二：`brew services list` / `docker ps` / `crontab -l` 的存在本身——服务与调度管理器把「谁还在跑」做成每个机器的标配治理动作，可「**哪个会话起的**」这个维度在所有这些工具里都是空的。
- AI Agent 的作业模式让积累速率数倍于人类：试错式作业动辄装工具、改配置、起服务，而 Agent 没有「下班的机器要还给别人」的概念——散改从「偶发卫生问题」变成「每单活必产的交付伴生物」。

## 价值（为什么不是伪需求）

自检四问：

1. **问题是真实的吗？**——是。三个场景都是 Agent 作业的日常；环境改动是试错式作业的结构性伴生物（不装工具不改配置的 Agent 做不了实事），不是个别 Agent 的坏习惯；「行为漂移不可归因 / 基线不可复现 / 常驻物安全面」三条后果链各自独立成立，且都不可逆或代价高昂。
2. **本仓二十五层真的没治吗？**——逐行核过方向登记表。最近似的几层：shefa 治**物之宿**（任务域内散件收没收尾），本层治**境之复**（常驻之态复位没复位）——散件删了水土还挂着，两账并行；yuli 治**灭之备**（毁掉之前有没有备份），本层治**改之复**（改过之后复位了没有）——一灭一改；duzhi 治**投入之量**（花了几笔），本层治**境变之账**（改了什么常驻）——量归它改归本层；mingshi 核**装的名有没有登记之实**（名实与供应链），本层核**装的常驻物复位了没有**（境变复位）——同一安装令两账并行（同 yuli 备形 × shefa 筏形之例）；yuanyu 禁**入目**（读进什么），本层审**改写**（改了什么）——一读一写。边界在 docs/03 §11 逐层锁死。
3. **确定性可判吗？**——改动与复位两通道全部是流内结构信号：**改动**=write 族 p: 径命中改径形（显式 basename/后缀/前缀表）∪ exec 成功调用的三族词法（装形 17 条 manager×scope 规则、改词形 4 条、驻形 9 条，含重定向/tee 目标命中改径形）；**复位**=基点之后的成功配对凭据（卸词表×manager×scope、`git config --unset`、`npm config delete`、`defaults delete`、`docker stop`、`crontab -r`、kill 族、rm 族）。零 LLM、零语义判断、零网络、零子进程、零文件系统探测。
4. **判罪会不会冤枉？**——清白道全在设计里：**项目域安装天然白**（`npm install`/`pip install` 无 scope 词永不入账）、**`git config` 无 `--global/--system` 白**（仓库局部配置是任务内的本分）、**`crontab -l` 纯列白**、**弃物址 `/dev/null` 天然白**、**basename 全等防 `src/profile/` 之诬**、**询值不判**（`git config --global user.email` 单词元是读不是写）、**失败不入账**（没装成的包、没起成的服务都不是事实）、**复位配对从宽**（卸词×manager×包名对齐、版本尾饰两侧同剥）、**单装案或单改案 15 分黄牌不咬门**（点名不门禁，宁纵勿诬）、**册上明言完全豁免**（任务方 `--install/--config/--reside` 签字）。

## 产品形态

DeepSeek Harness **察土式插件**（Cordis，结构性零拦截）+ 零依赖审计 CLI + Agent Skill——与全仓范式一致：可运行、可测量、可证伪、可离线重放验尸。察土式是本实验室**第二十七个能力类型**（拦/审/供给/记习/诊/勘流/巡忆/权界/封界/守境/秉笔/行前定/计账/审柄/记程/称实/核名/稽问/结绳/谏诤/量出/审材/敛迹/察渊之后）：判定对象不是事件的数量形或残全形，而是**常驻之境的改变形与复位形——改了什么，复原了没有**。
