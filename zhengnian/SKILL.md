# 正念 · Zhengnian —— 本愿必须一直在场

你在长任务里的最大风险不是笨、不是停不下来，而是**忘了自己来干什么**：本愿只在
第 0 轮出现一次，此后被几百轮工具噪音稀释（lost in the middle），写着写着就越出了
范围，最后对着一个自己顺手挑的检查宣布"完成"。《坛经》的解法是神秀的偈：
**时时勤拂拭，勿使惹尘埃**——尘埃必然落下，勤拂拭是纪律，"时时"是频率要求。

本协议不让你更聪明，只让本愿**有形状、有度量、有门禁**。

## 何时必须立契约

任务满足任一条，就在**动工之前**产出本愿契约并校验：

1. 预期 ≥ 20 次工具调用的长任务（修复、迁移、调研、批处理）；
2. 任务书里有明确的"完成判据"（测试、构建、产出文件）；
3. 写入范围理应有限（不该碰的目录存在）。

短小的问答、纯阅读任务不需要契约。

## 操作流程

```bash
zhengnian template > wish.json                    # 1. 拿契约骨架
# 2. 填写（见下方四要素），锚点由任务方语义决定，不是你挑顺手的词
zhengnian contract wish.json                      # 3. schema 校验，退出码 0 才算立住
zhengnian audit wish.json <本会话流.jsonl>          # 4. 途中/收尾审计尘值
zhengnian audit wish.json <本会话流.jsonl> --acceptance   # 5. 完成前过终验门
```

## 契约四要素（填写时逐条自问）

- **本愿 `wish`**：一句话写"要办成什么"，不写步骤。写不出一句话 = 任务还没理解；
- **锚点 `anchors`**：本愿词汇（模块名、错误名、领域词）与主战场路径。失念度的
  是"动作里还有没有这些痕迹"——锚点必须诚实反映本愿词汇，塞进无关高频词等于自欺；
- **愿界 `scope`**：允许写入的根目录。`allowAll:true` 是显式的"此愿无界"，
  攀缘之门对无界之愿保持沉默——别用它逃避划界；
- **终验 `acceptance`**：完成必须对着的证据（终验命令或产出工件）。**没有终验的本愿
  没有形状**——它让你无法区分"完成了"和"说完了"。

## 尘值与三门

`zhengnian audit` 给出一个 0–100 的尘值（0–14 净 / 15–29 浮 / ≥30 蒙，门默认 30）：

- **失念**（+8/次，cap 40）：最近 10 次动作与本愿锚点零交集。看到它亮起，先回到
  锚点附近做一次本愿内的动作，再决定下一步——**不怕念起，只怕觉迟**；
- **攀缘**（+12/次，cap 40）：写入落在愿界之外。越界的手缩回来；确需扩界，
  回头改契约并说明理由——契约可以修，但不能悄悄烂掉；
- **息尘**（+10/段，cap 20）：超过 30 次调用没有拂拭。装了插件的宿主会在接缝
  给你拂拭块；没装时自己执行第 4 步，把尘值当成回头的镜子。

终验门（`--acceptance`）：契约里的终验没有在会话流里真实发生 → 红灯。
**口念心不行，如幻如化；口念心行，则心口相应。** 不要用顺手挑的轻量检查
冒充本愿的终验——对谁负责，是被机器检查的。

## 诚实边界

尘值 0 不等于任务正确：它只保证动作还在锚点附近、没伸出愿界、拂拭没断顿、
终验真发生过。这四件事让你的漂移**可被发现、可被修正**——这就是全部，也不少了。
