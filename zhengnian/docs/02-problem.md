# 02 · 问题定义：谁、在什么场景下、有什么问题、价值何在

按「伪需求检验」的顺序写：先给场景和反事实，再给价值，最后自检。

## 目标用户

在 DeepSeek Harness（或任何 Cordis 架构的 Agent 运行时）上跑**小时级长任务**的工程师与团队：让 Agent 自主完成跨几十上百轮的修复、迁移、调研、批处理的人。他们已经接受了 Agent 能干活（zhizhi 治理行为）、也装上了判断校准（jiebi 治理判断），正在为第三种账单付钱：**任务做到第 90 轮时，Agent 已经不在原来的地方了**——而所有现存治理层都对此沉默，因为行为与判断各自局部合规。

## 四个场景

### 场景 1 · 本愿稀释（失念——尘埃落满了镜台）

小时级修复任务："修复 payments 模块的重复扣款"。第 0 轮任务书赫然在目；第 40 轮，上下文里已经隔了几百条工具输出，任务书成为 lost-in-the-middle 的最早受害者；Agent 开始顺手修 lint、补注释、升级依赖——**每一件都局部合理，每一件都不是本愿**。没有任何机制问一句："最近 10 次动作里，还有没有本愿的痕迹？"

**反事实**：todo 列表与 plan 文件是自愿式的——恰恰在上下文最长、稀释最深的时候最先被丢弃。只有**契约度量**（"最近 N 次动作与本愿锚点零交集 → 失念分上升 → 审计红灯"）不可协商，因为度量读的是动作流，不是 Agent 的自觉。

### 场景 2 · 范围蔓延（攀缘——手伸出了愿界）

迁移任务：把 `src/v1/` 迁到 `src/v2/`。第 30 轮起，Agent 开始修改 `docs/` 下的接口文档、`scripts/ci.sh` 的部署脚本——都"与迁移有关"，都越出了愿界。事后人眼 diff 才发现：**范围蠕变是渐进的，每一单步都不可反驳，加起来已经不是原来的任务**。

**反事实**：zhizhi 的先读后写管的是"写之前读没读过"（行为安全），不管"写的地方在不在愿内"（意图忠诚）。范围必须有**契约边界**（allowRoots）与确定性判定（路径前缀匹配），越界写入逐笔计分——攀缘第一次有了账。

### 场景 3 · 代偿完成（口念心不行——对着自选检查宣布完成）

调研任务书要求"结论须附可复现的基准数据"。Agent 在第 200 轮宣布完成，引用的证据是它自己挑的一次顺手跑的单测。本愿自己的终验（基准脚本）从未被执行。zhizhi 的完成核验会问"**有没有**验证证据？"——有，单测跑过，绿灯。它不会问"**证据是不是对着本愿的**？"——代偿完成在 zhizhi 眼里完全合规。

**反事实**：《坛经》"口念心行，则心口相应"。终验必须在本愿契约里**声明一次**，完成必须对着契约里的终验对账（`--acceptance`）：流里没有终验的行为痕迹 → 门禁红灯。对谁负责，第一次被机器检查。

### 场景 4 · 拂拭缺席（"时时"没有频率下限）

团队知道要重注入目标（compaction 后补一段目标摘要），但没有频率约定、没有确定性产物、没有可审计的记录：什么时候拂的、拂的哪段原文、拂完尘值降没降——全不可考。所谓"提醒"，多数时候是某次重写 prompt 时顺手加的一句话，下个版本就没了。

**反事实**：拂拭必须是**确定性产物**（同一契约 + 同一状态 → 逐字节相同的块）、有**频率下限**（maxStale：超过 N 次调用没有拂拭 → 息尘计分）、有**记录**（reanchor 事件入流，可离线重放）。"时时"从修辞变成条款。

## 价值论证

1. **意图第一次有了质量单位**：尘值（dust score，0–100）是一个确定性的、可复现的数字，回答一个此前无法回答的问题："此刻的动作流离本愿有多远？"——不可测量 → 不可管理。
2. **治理拼图的第三块**：zhizhi 治**手**（动作前拦截），jiebi 治**眼**（判断后校验），正念治**心**（本愿的持续在场）。行为合规 + 判断合规 ≠ 还在干原来的事——三层合起来，长任务的"人在哪里、看什么、干什么"才闭环。
3. **插件层的新能力类型**：zhizhi 证明插件可以**拦**（pre-execute 否决），jiebi 证明插件可以**审**（观察式对账），正念证明插件可以**供给**——`ctx.zhengnian.reanchor()` 在接缝处产出逐字节稳定的上下文块，供宿主注入。"Cordis 生态里治理类插件能做什么"的第三个种类：上下文供给式插件。
4. **零 Agent 产物的度量**：jiebi 的蔽值依赖 Agent 写账本（产物可伪造，故有 reconcile）；正念的尘值**不要求 Agent 写任何东西**——只要求开工时一份契约，此后全是对原始动作流的确定性测量。度量的对象越少经手 Agent 的笔，越难被自我叙事污染。
5. **可证伪的价值主张**：对团队自己的历史长会话跑 `zhengnian audit`，能数出多少失念窗口、多少越界写入、多少次"终验缺席的完成"——价值可以自证，不靠叙事。

## 伪需求自检清单

| 质疑 | 回应 |
|------|------|
| "上下文窗口越来越大，还会丢目标吗？" | 窗口再大，位置衰减与噪声掩蔽不消失（lost in the middle 是位置曲线，不是容量曲线）；时程越长偏离越显著是长时程评测的普遍发现（METR 2025）。更大的窗口只是让尘埃落得慢一点——"时时勤拂拭"照样成立。 |
| "todo 列表 / plan 文件不就够了吗？" | 它们是自愿式的：依赖模型自觉维护，恰好在稀释最深时最先被丢弃；且没有度量、没有门禁、没有对原愿的对账。正念的三件套——契约（形状）、尘值（数字）、拂拭（确定性供给）——把它们从好习惯变成可审计的机制。 |
| "压缩（compaction）时保留目标不就行了？" | 那正是拂拭的一种——但今天它既无频率下限、也无确定性产物、也无事后可审计的记录（场景 4）。正念把这件事从"各家 harness 的内部手艺"变成带条款的协议：maxStale 是频率条款，reanchor 事件是账，尘值是门禁。 |
| "关键词匹配太粗糙，聪明的 Agent 会把关键词塞进无关动作来骗过它？" | 会——正如账本会被伪登记骗过。正念的诚实边界写死在文档里（docs/01-book.md 第五节）：锚点声明权收归契约（开工时由任务方定，不是 Agent 自己挑），终验必须对账，尘值 0 不保证正确、只保证"此刻的动作还在锚点附近"。确定性度量的价值在于可审计、可门禁、可重放，不在于不可欺骗——这两件事正念分开承诺。 |
| "这不就是给 Agent 装 background 任务描述吗？" | 任务描述是"写一遍"，正念是"度量 + 供给 + 门禁"三件事：契约只是数据，尘值是持续测量，拂拭块是逐字节稳定的供给物，终验门是 CI 可用的退出码。没有度量与门的任务描述，是纸。 |
| "会不会把 Agent 拖慢？" | 零拦截（结构性，插件里没有 pre-execute 监听器）、零 LLM 调用；尘值是 O(窗口) 的字符串匹配，拂拭块是模板渲染。度量不消耗 token，供给块只占几行上下文。 |
| "和 zhizhi / jiebi 撞车吗？" | 正交且有明确边界（见根 README 方向登记）：zhizhi 在 pre-execute 拦**动作**（手），jiebi 校验**判断账本**（眼），正念度量**意图在场**并供给上下文（心）；正念同样是结构性零拦截，不做动作治理，不做判断校验，不做语义判断（锚点是显式声明的词与径，不是 NLP）。 |
| "凭什么说是真实问题？" | 四个场景各对应一类可指认的公开失败模式（长上下文位置衰减、范围蠕变、代偿完成、无频率约定的重注入），且业界 todo/plan/compaction 的普及是问题的行为学证据；`zhengnian audit` 能对自己的历史会话量化失念窗口与越界写入——价值主张可自证。 |
