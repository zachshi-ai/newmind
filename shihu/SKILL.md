# 市虎 · Shihu — Agent 协作协议

> **「夫市之无虎明矣，然而三人言而成虎。」——《战国策·魏策二》**
>
> 你写下的每一条「已完成」，下一个会话都会当成事实来用。本协议不限制你
> 写交接书（拦是知止的地盘），它要求：写状必有据——声明的对象，你自己的
> 流里动过手；转述上游的活要署名；虚报的每一条都在状牌上点名。

## 何时用此 Skill

- 工程师跑多 agent 编排，想防住「交接书虚报、下游按假状态决策」；
- 会话接力前想审「上一棒的 HANDOFF 有几条对得上它自己的流」；
- CI 需要一道状态陈报门禁（虎值 ≥ 30 即红——单虚功条即红）；
- Agent 需要自查：这条「已完成」，我动过手没有？

## 给派活的工程师

```bash
cd your-repo
shihu register --path "archive/*"                  # 归档类交接书先免对账
shihu audit session.jsonl --file .shihu.json       # 收工审状（exit 码可进 CI）
shihu audit handoff-a.jsonl handoff-b.jsonl --json # 多会话合审（按会话分账对账）
shihu block --file .shihu.json                     # 状牌块：状册与案账公示
```

- **无册全账**：不立册也审——交接语境的陈报是公共事实，豁免只能来自册；
- **豁免是授权**：明知是模板/归档的交接径，开工时把径列进状册；
- **门禁**：虎值 ≥ 30 即红——单虚功条即红（一份虚报就足以污染下游决策）。

## 给 Agent 的五条纪律

1. **写「已完成」之前，看一眼自己的手**：声明的对象词元必须在你的流里
   有作工之迹（跑过的命令、写过的径、读过的径）——没碰过就别写「已修复」；
2. **转述要署名**：上游会话做的活，写「上游会话已完成 X」——引用词同行
   即掠据白 0 分；把别人的活写成自己的完成，账照样记；
3. **成没成与动没动是两本账**：试过但失败了（失败命令也在流里）在本层
   是有据——但「全绿」这类成色声明归效验对账，别拿「动过手」当「做成了」；
4. **交接径有形状**：HANDOFF.md/名含 handoff/交接——把状态写进这些径，
   让账认得你的文书；写进 README 的状态不在对账范围（也别拿它传状态）；
5. **词法可欺但骗一次留一次形**：改成将来时、藏进非交接径可移形——骗一次
   留一次形，状牌在账。

## 判定语义速查

| 案 | 对象 | 判定 | 分值 |
|---|---|---|---|
| 虚功 | 声明对象词元在自流作工面全部查无 | 无据之状 | +30/条 cap60（单条即红） |
| 掠据 | 声明行含引用词（上游/来自/by @…） | 署名的转述 | 0（点名） |
| 无键 | 剥状词后无对象词元 | 无从对账 | 0（注记） |
| 有据 | 状键任一词元命中自流作工面 | 过第一问 | 0（静默） |

- 虎值 = min(60, 30 × 虚功条)；分带 真 0–14 / 疑 15–29 / 虎 ≥30，门 30；
- 作工面 = 本会话 exec 命令原文（成败皆入——试错也是始）∪ 写径 ∪ 读径；
- 状形是显式词法（勾选形 ∪ 状词表 ∪ 里程碑形；未勾选与将来时不中）——
  词法可欺但骗一次留一次形。
