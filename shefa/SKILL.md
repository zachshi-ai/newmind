# 舍筏 · Shefa — Agent 协作协议

> **知我说法，如筏喻者，法尚应舍，何况非法。**——《金刚经》
>
> 调试脚本、`.bak` 副本、`/tmp` 探针、手工夹具——全是渡河之筏：任务（河）过了，筏的使命就完了。本协议不禁止你造筏（试错式作业本来就要探针与副本），它只要求每一件筏有归宿：要么**舍**（删掉）、要么**归**（收编进版本库）、要么被筏册明言豁免——无凭据的悬物一律上账。

## 何时用此 Skill

- 委派编码任务的工程师想在收工时审计 Agent 的作业遗物（临时文件/副本/探针有没有善后）；
- CI 需要一道「作业无痕」门禁（遗筏值 ≥ 30 即红）；
- Agent 需要在收尾自查：这一单活落下的筏，都舍了/归了没有。

## 给委派任务的工程师

```bash
cd your-repo
shefa register --keep dist/,package-lock.json   # 开工立筏册（交付径签字豁免；可附 --raft/--roots）
# ……Agent 作业……
shefa audit session.jsonl                       # 收工审筏（exit 码可进 CI；无册照判）
shefa block --file .shefa.json                  # 舍牌块（可注入收尾上下文）
```

- **无册照判**：默认筏形表 15 形（`tmp/`、`scratch/`、`.bak`、`backup`、`.old`……）开箱在岗；
- **豁免要趁早**：lockfile、dist、生成目录让任务方 `--keep` 签字——命中 keep 的径写前就是交付物；
- **门禁**：筏值 ≥ 30 即红——域外散件（`/tmp`、家目录）单件即红，域内遗两件即红；单件域内遗（15）黄牌点名不咬门。

## 给 Agent 的五条纪律

1. **过河即舍筏**（「法尚应舍，何况非法」）：调试用的复现脚本、手工探针、临时转储，收尾时 `rm` 删掉——一行命令就是账上的「舍」凭据；
2. **要留的筏就收编**（「登岸之筏，亦是器用」）：验证脚本、手工夹具若值得留，`git add` + `git commit` 收编——收编即白；
3. **副本是筏不是保险**：`cp x.js x.js.bak` 留退路可以，改完记得删——`.bak` 是本层头号筏源，也是下一个会话误读现场的头号来源；
4. **别把筏扔到河对岸**：`/tmp`、`/var`、家目录是任务域之外——域外散件一件即红；
5. **交付径先声明**：生成物（dist、vendor、lockfile）开工时让任务方 `shefa register --keep` 签字。

## 判定语义速查

| 案 | 对象 | 判定 | 分值 |
|---|---|---|---|
| 外逸 | 域外的悬筏 | 末落之后无舍无归凭据 | +30/案 cap 60（单案即红） |
| 遗筏 | 域内的悬筏 | 同上 | +15/案 cap 30（单案黄牌） |
| 舍 | rm / rmdir / unlink / git clean 在末落之后成功 | 销案 | 0 |
| 归 | git add 见证 + 更后 git commit | 销案 | 0 |
| 豁免 | keep 形命中 | 完全出账 | 0（注记） |

分带：**净 0–14 / 滞 15–29 / 积 ≥30**；门默认 30。边界：知足问「写的有多少」、本层问「写的物去哪了」；豫立审「毁掉之前有没有备」、本层审「留下之后有没有清」；捭阖管出境的物、本层管在场的物。
