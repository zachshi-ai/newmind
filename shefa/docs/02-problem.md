# 02 · 问题：Agent 作业遗物

## 场景（谁在什么场景下）

**谁**：DeepSeek Harness 上跑的编码 Agent（以及一切「会话流可重放」的 LLM 编码代理）的**任务方与审计方**——需要验收 Agent 交付的工程师、需要给交付立门禁的 CI、以及**下一个进场的会话**。

**场景一：渡河不弃筏。** Agent 修一个难缠的并发 bug：先写 `scratch/repro.js` 复现问题，再 `cp src/scheduler.js src/scheduler.js.bak` 留条退路，修完验证通过、宣布完成。`repro.js` 与 `.bak` 全都留在场上——`git add -A` 的下一个提交把它们原样带进版本库；或者更糟，下一个会话读到 `.bak`，把它当成现状事实。事后连「这单活落下了哪些临时之物、舍了没有」都无处问起。

**场景二：探针撒在域外。** Agent 排查一个只在真实数据上出现的问题：探针写 `/tmp/probe.py`，调试转储写 `/var/tmp/state.json`，家目录里落一份 `~/debug_dump.json`。工作区看起来干净（git status 是净的），环境却已经脏了——这些物不在任何任务域之内，下一次 `git clean` 管不到它们，跨会话累积成「复现不了那杯」的漂移基线。

**场景三：现场误读。** 会话 A 留下 `scratch/tmpdump.txt`（一次调试的转储）中途被叫停；会话 B 接手，把这份半旧的转储当成模块的真实输出格式写解析器——错误要到运行时才炸。留物的会话有账可查（写了什么有据），可「哪些物还悬在场上没有归宿」没有一层记账。

## 问题（治什么病）

**Agent 作业遗物**：会话流里每一次落笔都真实发生了，但**没有任何一层审计落笔之物的归宿**——

- 本仓 #1–#23 已定标的各层层层核过登记表：知止拦「写前读过没有」（读之有无），知足量「写入的规模」（写之量），zhongshi 记「任务项的终始」（事之程），licheng 追「话语的兑现」（诺之信），yuli 审「毁掉之前有没有备」（灭之备），dingfen 定「写域归谁」（写之权），shenqu 审「读到的是不是残卷」（读之全）——**「落下的新物最后有没有善后」全仓无账**。
- 结构性证据一：`git clean` 这个命令的存在本身——版本控制系统的设计者把「未收编散物的清理」做成了每个仓库的标配治理动作，却从没有一个账本能回答「哪件物是哪个会话落下的、舍了没有、归了没有」。
- 结构性证据二：`.gitignore` 的普遍存在承认「工作区会持续积累不该入库之物」；而 AI Agent 的作业模式（大量试错、探针、副本、夹具）让积累速率数倍于人类——散物从「偶发卫生问题」变成「每单活必产的交付伴生物」。
- 本仓亲历实锤：2026-09-06，一个早期会话留下的空目录骨架（git 不跟踪、status 看不见）让后续会话的侦查者误判「此处有在途项目」——遗物误导现场，是本实验室自己撞过的墙。

## 价值（为什么不是伪需求）

自检四问：

1. **问题是真实的吗？**——是。三个场景都是 Agent 作业的日常；临时物是试错式作业的结构性伴生物（不试错的 Agent 不需要探针），不是个别 Agent 的坏习惯；「垃圾入库 / 环境漂移 / 现场误读」三条后果链各自独立成立，且都不可逆或代价高昂。
2. **本仓二十三层真的没治吗？**——逐行核过方向登记表。最近似的几层：知足治**写之量**（写得多不多），本层治**写之宿**（写的物善后没有）——写得再节俭，一件 `.bak` 也是筏；yuli 治**灭之备**（删之前有没有备份），本层治**留之清**（留下之后有没有清）——备份造出的副本正是本层的头号筏源；zhongshi 记**事之程**（任务书立的事走到哪），本层记**物之宿**（任务书没立过的散件去哪了）；dingfen 裁**写之权**（跨会话谁有资格写），本层审**写之终**（单会话写的物收没收尾）；youya 守**读之忆**（读过的重复装载），本层守**写之迹**（落下的物在场不在场）。边界在 docs/03 §11 逐层锁死。
3. **确定性可判吗？**——落物与归宿两通道全部是流内结构信号：**落物**=write 族 p: 径命中筏形（显式词形表）∪ exec 成功调用的落物词形词法（重定向/tee/touch/cp/mv 的目标径）；**归宿**=落物之后的成功 `rm`（含 glob）∪ 成功 `git clean`（全域）∪ 成功 `git add` + 其后成功 `git commit`（收编）。零 LLM、零语义判断、零网络、零子进程、零文件系统探测。
4. **判罪会不会冤枉？**——清白道全在设计里：**豁免在册**（keep 形签字的径完全出账——交付径、生成物、lockfile）、**弃物址天然白**（`/dev/null` 默认 keep）、**就地改写不判**（`sed -i` 不造新物，量归知足）、**非筏形的写不判**（`src/util.js` 不含任何筏形，永不入账——本层只看显式词形命中的散件）、**exec 无路径词面不判**（`npm install` 无径词面，天然沉默）、**失败写与失败凭据不入账**（未落盘的写、没删成的 rm 都不是事实）、**凭据时序保护**（rm 必须在末次落物之后才算舍——先删后写不销案）、**单案域内遗 15 分黄牌不咬门**（点名不门禁，宁纵勿诬）。

## 产品形态

DeepSeek Harness **敛迹式插件**（Cordis，结构性零拦截）+ 零依赖审计 CLI + Agent Skill——与全仓范式一致：可运行、可测量、可证伪、可离线重放验尸。敛迹式是本实验室**第二十五个能力类型**（拦/审/供给/记习/诊/勘流/巡忆/守权界/封界/权界/秉笔/行前定/计账/审柄/记程/称实/核名/稽问/结绳/谏诤/量出/审材之后）：判定对象不是事件的性质、数量形或残全形，而是**新落之物的归宿形——渡河的筏，舍了没有**。
