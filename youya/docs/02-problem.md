# 02 · 问题定义：谁、在什么场景下、有什么问题、价值何在

按「伪需求检验」的顺序写：先给场景和反事实，再给价值，最后自检。

## 目标用户

在 DeepSeek Harness（或任何 Cordis 架构的 Agent 运行时）上**委派长任务**（几十轮以上工具调用）的工程师与团队，以及给会话设 CI 门禁的平台方。他们已装齐七层治理（知止拦动作、解蔽审判断、正念守本愿、治未病体检开工、不贰记跨会话教训〔在途〕、九变勘应变、立诚结承诺之账〔在途〕），但有一条通道至今无人看守：**它自己的见闻**。每一轮上下文重新生成，Agent 对自己见过什么、跑过什么没有任何机制性的账本——读过的文件可以原样再读一遍，跑过的命令可以原样再跑一遍，没有任何东西为此记账。

## 四个场景

### 场景 1 · 复见（读过的，没变，又读一遍）

60 轮的重构任务。第 3 轮读了 `docs/plan.md`，此后一直在改 `src/`——到第 40 轮，它又把 `docs/plan.md` 完整装载了一遍。文件在此期间**一次都没被写过**（账内可证），装载得到的是一字不差的内容：这一次装载没有带来任何新信息，只花了整文件的 token 和一轮延迟。更糟的是它是个**症状**：会做到第 40 轮还原样重读，说明第 3 轮那次见闻已经不在工作记忆里了——窗口在无声地漏。这不是判断失真（解蔽地盘）、不是目标漂移（正念地盘）、也不是失败后的死磕（九变地盘——这里没有任何失败）：**世界没变，它忘了**。

**反事实**：有涯在第二次未变之装载入账**复见一记**；相邻的原样连读并一案，隔着其他调用的再犯另立一案。殆值上升，要籍块在接缝处点名：`p:docs/plan.md ｜ 第3见 ｜ 其间无写——官知止`。遗忘从"感觉它变笨了"变成账上见。

### 场景 2 · 复命（跑过的，没变，又跑一遍）

第 10 轮跑了 `cat config.json` 确认了配置；第 30 轮——中间十几次调用、**账内无任何成功写入**——它又跑了一遍 `cat config.json`。世界没有任何变化，第二次执行在信息上是一次空转。轮询除外（诚实边界：等外部事件反复 `git status` 可能被误计，声明权在流），但主战场是真实的：长会话里"顺手再看一眼"的每一眼，都是已经付出过成本的见闻被再付出一次。

**反事实**：有涯按**同串命令、两次成功、其间账内无写**三条件确定性入账**复命一记**。注意与九变的判定边界：若两次之间夹有失败（同命令 `isError:true`），那是势变之地——失败后的重试归九变勘，有涯免记并重置。两宗罪在流里逐字可分。

### 场景 3 · 要籍缺席（接缝处没有一张自己的地图）

长会话中段，窗口里的早期内容已被压缩或挤到注意力谷底。此刻它面对每个熟悉路径只有两个选项：**凭走样的记忆动手**（风险），或**整文件重装载一遍**（成本）——而这两个选项的根源是同一个：没有一张"我见过什么、末次见闻在第几调用、隔了多远"的地图。人类工程师靠第二显示器旁的便签和自己的笔记解决这件事；Agent 没有任何机制给它这张便签。

**反事实**：要籍块在接缝处逐字节确定地供给这张地图：陈账点名（隔久未顾、其间无写的路径——复见之诱）、工作集计数（路径/命令/前科案数）、殆值与分带。宿主拿着拂拭块一样拿着它，注不注入由宿主决定。

### 场景 4 · 验尸（事后无人能回答"它忘了多少"）

一段已结束的历史会话（或第三方会话的导出流），想知道它的记忆质量：有没有大量复读？殆值几何？今天唯一的办法是人工通读 transcript 逐段比对——长会话根本做不到。

**反事实**：`youya audit <stream.jsonl>` 契约无关、零 LLM 地给出殆值、分带、逐案清单——任何历史会话流可直接验尸，与运行时账本逐字对账（前缀一致）。

## 价值

1. **把 context rot 从体感变成指标**：复见率/复命率是记忆衰减的直接行为学证据——零语义即可测量，每次复见都有可核算的成本（整文件装载 + 一轮延迟）。
2. **给窗口管理一个下账层**：工程界的 compaction / context editing 决定"丢什么"，有涯回答"丢了以后怎么看见"——账在，衰减才可见。
3. **要籍块是接缝处的免费便签**：与其让模型在"瞎写"与"重读"之间二选一，给它一张账内地图——官知止而神欲行。
4. **CI 门禁**：折带（≥30）的会话流在流水线上红灯，长任务的记忆质量进入可回归的验收。

## 伪需求自检

- **是真问题吗**：Lost in the Middle（TACL 2023）实证了位置衰减；各家运行时 2025 年起相继内置 compaction / context editing / memory tool，工程界已承认窗口必须主动管理——这是当下 AI 领域最热的问题之一，且本仓自己的多会话长任务开发中反复观察到"原样重读同一文件"（本轮开发即有实例）。非假问题。
- **是已有层的地盘吗**：与七层逐一对照过（见 docs/01 分工节与 docs/03 §9 边界表）——没有任何一层对"世未变而它忘了"记账。判定边界（有无失败介入）在流里逐字可证，不是话术划分。
- **可证伪吗**：殆值有公式、案有判定算法、夹具有手算期望值（见 fixtures/ 注释），任何人对同一会话流重放必得同一殆值；若你认为某案判错了，判定算法四条规则（docs/03 §4–§5）逐条对得上对不上，一眼可查。
- **产品形态可运行吗**：零依赖 CLI + 真实 Cordis 管道集成测试 + 验收表（A1–A11，全部绑定可复现命令），不是 PPT。
