# 03 · 设计：见闻账、殆值、要籍块

> 本节的判定规则与常数在实现前锁死；实现不得为缺口放宽（验收标准同理，见 docs/04）。

## §1 总览：巡忆式插件

有涯是 DeepSeek Harness 的**见闻记忆层**，第七个插件能力类型：**巡忆式**（拦/审/供给/记取/诊断/勘流之后）。巡忆 = 持续巡视结果流里的**见闻连续性**：世界没变而它忘了（复见/复命），逐案入账；接缝处供给**要籍块**（账内工作集地图，逐字节确定，注入与否由宿主决定）。

```
tools/result       emit    观察结果，见闻账步进一格（唯一写入口）
（无 pre-execute）          —— 零拦截是结构性的
```

设计约束（与前七层同款）：

- **模型无关**：零 LLM 调用、零提示词注入、零网络、零子进程；
- **契约无关**：不需要任何开工契约，挂上即巡——任何历史会话流可离线验尸；
- **观察永不反噬**：监听器里的任何异常都被吞掉，管道照常；
- **前缀一致**：运行时增量账本与离线重放在任何观察时刻分数一致（进行中已构成案的段也计入即时分数）。

## §2 对象键与工具族（沿用本仓显式字段惯例，零 NLP）

对象键（按序取第一个命中）：

- `args.path` / `args.file_path` / `args.notebook_path`（非空字符串）→ `p:<值>` 文件对象；
- `args.command`（非空字符串）→ `c:<trim>` 命令对象；
- 其余 → `n:<工具名>` 不透明对象。

工具族：`observe`（观察）/ `write`（写）/ `exec`（执行）/ `other`，词表沿用九变的 `familyOf` 惯例（同仓统一，跨项目夹具互认）。

有涯在 observe 族内再分一刀（这是与九变的关键差异——九变看"有没有再察"，有涯看"有没有重复装载"）：

- **装载类**（内容身份 = 路径）：`read` / `cat` / `view`（精确匹配）。装载拿到的是该路径的**全部内容**，两次装载之间路径未变 ⇒ 第二次零新信息。
- **检索类**（内容身份 ≠ 路径）：`grep` / `glob` / `ls` / `search` / `list` / `find`（子串匹配）。检索以**参数**为所问，同路径异参数是合法的再问——检索类永不入复见账，也不更新装载基线（宁漏勿诬）。

## §3 会话流的归并（与全仓共享格式一致）

每行一个 JSON 对象；`#` 与空行为注释；坏行报行号。calls 归并规则（与 zhengnian / jiubian 的解析器逐字一致，跨项目互审的前提）：

- 带 id：call 建档（id 首见为准），result 按 id 回填 `isError`；
- 无 id（zhizhi 旧格式）：result 并入紧邻其前的无 id call；
- 孤儿 result 独立建档——不丢任何一次真实执行。

每个 call 归一为 `{ ref, name, args, isError, at }`。`isError` 三态：`true`（失败，设瑕）、`false`（成功，可作基线与重置凭据）、`null`（无 result 回填的孤儿 call，未知）。有涯的判定里，"有效"只认 `isError === false`——**无凭不记功过**：`null` 的调用既不作基线也不作重置。

## §4 复见案（世未变的重复装载）

对每个文件对象 `p:X` 维护：`lastLoad`（末次**成功**装载的调用序号，初始无）、`taint`（末次失败装载的调用序号，初始 −1）。

在第 `i` 次调用为**装载类**调用、对象 `p:X`、`isError === false` 时，依次判定：

1. **设基线**：`lastLoad := i`（无论是否入罪，本次成功装载都是新基线）；
2. **入罪判定**：若存在先前的成功装载 `j = lastLoad(旧) > taint`，且 `(j, i)` 开区间内**无** `p:X` 上的成功写族调用 ⇒ 记**复见一记**（对象 `p:X`，位次 `i`）；
   - 若 `(j, i)` 内有 `p:X` 上的成功写入：不入罪（写后重读是**鲜**——正当刷新，是本层奖励的好行为）；
   - 若 `j ≤ taint`：不入罪（两次成功装载之间夹有失败装载——它正在**应对**什么，那可能是势变之地，归九变；有涯免记）。
3. **设瑕**：装载类调用 `isError === true` 时：`taint := i`（此后到下次成功装载前的复见一律免记——失败正在发生，它在应对）。

**并案规则**：复见各记按流序排列；**相邻两记**（其间无第三记）若属同一对象且前记所在调用与后记所在调用**紧邻**（中间零调用），并为一案；否则另立一案。即：连续的原样连读（read A, read A, read A）是一次遗忘发作（一案），散布在会话各处的再犯各是一案。

**`n:` 对象不入账**：不透明对象的 args 不受键约束，两次"同对象"调用可能所问全然不同——宁漏勿诬。

## §5 复命案（世未变的重复执行）

对每个命令对象 `c:K` 维护：`lastRun`（末次成功执行的调用序号）、`taint`（末次失败执行的调用序号）；另有**全库写位** `lastGlobalWrite`（任意对象上末次成功写族调用的序号）。

在第 `i` 次调用为 **exec 族**调用、对象 `c:K`、`isError === false` 时，依次判定：

1. **设基线**：`lastRun(K) := i`；
2. **入罪判定**：记 `j = lastRun(旧)`。若 `j` 存在、`j > taint(K)`，且 `(j, i)` 开区间内
   - 无**任意对象**上的成功写族调用（命令的世界是整个环境，任何写入都可能改变其行为 ⇒ 全库重置；这是文件对象（路径可寻址、只看己身）与命令对象（环境寻址、看全局）的不对称，有意的），且
   - 无 `c:K` 上的失败执行（夹有失败 = 势变之地，归九变；免记）；
   ⇒ 记**复命一记**；
3. **设瑕**：exec 族调用 `isError === true` 时：`taint(K) := i`。

**并案规则**：与复见同款——同对象紧邻记并案，否则另立。

## §6 殆值与分带（常数锁死）

```
殆值 = min(100, 复见分 + 复命分)
复见分 = min(60, 12 × 复见案数)          // FUJIAN_POINTS=12, FUJIAN_CAP=60
复命分 = min(40,  8 × 复命案数)          // FUMING_POINTS=8,  FUMING_CAP=40
分带：0–14 新硎 ｜ 15–29 割 ｜ ≥30 折     // 边界逐点可证（docs/04 A4）
门：默认 30（≥30 折即 fail）              // GATE_DEFAULT=30
```

`liveScore`（未收刀时的即时分数）：已闭合的案照算，**进行中的案也计入**——任何观察时刻的已见前缀都是完整事实，离线重放不得出现更小的数（前缀一致性）。

## §7 陈账与要籍块

**陈账**（要籍块的供给对象）：工作集内路径，其末次内容触碰（成功装载或成功写入取较晚者）距今 ≥ `CHEN_GAP = 40` 次调用。陈账是复见之诱的点名清单——这些见闻大概已经落出工作记忆。

**要籍块格式**（逐字锁死；同一账本状态渲染逐字节相同，`#k` 随渲染次数递增；无时间戳字段）：

```
【有涯 · 要籍】见闻账 #<k>
吾生也有涯，而知也无涯。已见未变之物，官知止而神欲行——不必复见。
陈账（隔久未顾——复见之诱，动手前先想是否真需要再装载）：
  1. p:docs/plan.md ｜ 末见闻第3调用 ｜ 已隔47调 ｜ 其间无写
（无陈账：见闻皆鲜，游刃有余。）
工作集：路径 3 ｜ 命令 2 ｜ 复见 2 案 ｜ 复命 1 案
殆值：<n>（<带>）｜ 门 <g>
—— 本块由确定性规则生成；重放同一流必得同一文本。
```

- 陈账按**账序**（末次触碰位次升序）排列、逐行编号；无陈账时输出括号行；
- 「其间无写」指该路径末次内容触碰之后无该路径成功写入（对文件对象恒真——有写则末次触碰即写，故此列只对装载触底的路径出现；写触底路径标「写后未再顾」）；
- 工作集计数：去重路径数 / 去重命令数 / 前科案数；
- 末行承诺逐字节可复现（shasum 可证）。

## §8 插件形状与服务 API

- `export const name = 'youya'`；`export const inject = ['tools']`；`export function apply(ctx, config)`；
- `ctx.on('tools/result', …)` 是唯一监听器（**结构性零拦截**：源码无 `tools/pre-execute` 监听）；
- `YouyaService extends Service`：
  - `report()`：观察数、复见/复命记数与案数、即时殆值、分带、门；
  - `jianwen()`：逐记清单（seq/ref/object/kind/位次）+ 分数；
  - `yaoji()`：要籍块（`{ valid, k, text, chen }`，`k` 渲染序号）；
  - `gate()`：`{ score, fujian, fuming, gate, verdict, ok }`；
  - `exportStream()`：call/result 成对导出，供 `youya audit` 离线重放对账（observe × audit 账实一致）；
- 引擎经闭包交付监听器（同九变：避免"注入自己提供的子服务"形成等待环）。

## §9 与七层的边界（结构性，不是纪律性）

| 层 | 地盘 | 有涯不越界的判定 |
|---|---|---|
| 知止 zhizhi | 动作拦截 | 有涯无 pre-execute 监听，一票不拦 |
| 解蔽 jiebi | 判断账本 | 有涯无 alternatives/disconfirming/verdict 字段 |
| 正念 zhengnian | 本愿契约 | 有涯无 wish/anchors/scope 契约字段；供给的是**发现**的工作集，不是**声明**的锚点 |
| 治未病 weibing | t=0 任务书体检 | 有涯全部工作在 t>0 的结果流上，无监听器之外的入口 |
| 不贰 buer | 跨会话错误账本 | 有涯账本会话内闭合，无跨会话状态 |
| 九变 jiubian | 势变应变 | 判定边界：夹有失败的重复（`isError:true` 介入）归九变（势已变），世未变的重复归有涯——流里逐字可分；有涯无 盲捶/悬账/游骑/失机值 字段 |
| 立诚 licheng | 承诺信用 | 有涯记账的是**见闻**不是**言语**：无 speech/绳账/咎值 字段 |

## §10 CLI

```
youya audit <stream.jsonl> [--gate n] [--json]   见闻账审计（殆值 + 分带 + 门禁）
youya yaoji <stream.jsonl> [--json]              要籍块（默认纯文本）
youya gate --value <n> [--gate <n>]              门禁裁决
youya --help | --version
```

退出码：0 通过；1 门禁失败（殆值 ≥ 门）；2 用法/输入错误。
