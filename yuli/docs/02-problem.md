# 02 · 问题定义：谁、在什么场景下、有什么问题、价值何在

按「伪需求检验」的顺序写：先给场景和反事实，再给价值，最后自检。

## 目标用户

在 DeepSeek Harness（或任何 Cordis 架构的 Agent 运行时）上**委派触碰真实文件、真实版本库、真实数据库的长任务**的工程师与团队，以及给 Agent 会话设 CI 门禁的平台方。他们已装齐十三层治理（zhizhi 拦动作、jiebi 审判断、zhengnian 守本愿、weibing 体检开工、jiubian 勘应变、youya 守记忆、lunshi 审输入、dingfen 封写域、baihe 守出境、zhibi 保记录〔在途〕、buer 记教训〔在途〕、licheng 追承诺〔在途〕、fayi 审量尺〔在途〕），但有一件东西至今无人看守：**险行的退路**。Agent 会清理目录、会同步历史、会"顺手"删表——不可逆操作落地的那一瞬之前，流里有没有留下任何退路（备份、存档、干跑），没有一层记账。

## 四个场景

### 场景 1 · 裸险（rm -rf 过处，影都没有）

40 轮的清理任务。第 31 轮 Agent 决定「旧数据目录不再需要」：`rm -rf ./data-legacy/`——整个会话里没有一次 `cp`、没有一次 `rsync`、目录也不在 git 追踪里。命令成功，输出安静。第 32 轮起它继续做别的，收工报告「清理完成」。知止数行为：没有循环、没有未读先写；法仪审尺：测试没动、断言不虚；直笔保记录：退出码是真的 0；九变勘势变：没有失败在先。**每一层都干净，因为每一层都只看它那一面**——而「这个目录的副本在世界上的任何地方都不存在了」这件事，没有任何一层的账本有字段承载。想发现，只能灾后（用户找不到文件来问）通读全量 transcript 找那一行 `rm`。

**反事实**：若豫立在册，第 31 轮 `rm -rf ./data-legacy/` 是一次灭迹族险行：行前无影写（词法相交为空）、不在版本树内 → 裸险案 +30，险值 30，门禁红灯。「删了什么、删的时候有没有备」从「无处问起」变成「账上第 31 案」。

### 场景 2 · 断史（一推抹掉的不止是提交）

同步任务。Agent 拉下上游后发现本地历史「碍事」，第 18 轮 `git reset --hard origin/main`、第 19 轮 `git push --force`。整个会话没有一次 `git commit`、没有一次 `git stash`——第 1–17 轮的所有未提交工作与本地分支历史，随一次强推离开本地，无处可寻。流里这两行看起来和任何一次正常 push 没有区别。

**反事实**：断史族险行两案：行前无存史（会话内零 commit/stash/push/tag）→ 裸险 2 案，险值 60，门禁红灯。有存史的会话（第 5 轮 commit 过）则第 19 轮为有备考案 0 分——**存史在先，强推只是险，不是祸**。

### 场景 3 · 覆宗（顺手的一句 DROP）

联调任务。Agent 为了「让脏数据不再干扰测试」，第 44 轮 `psql -d appdb -c "DROP TABLE legacy_orders"`。会话里没有一次 `pg_dump`、没有一次 `.backup`。表连同一个季度的订单数据一起消失。transcript 里这是一行人畜无害的 SQL——没有红灯、没有报错、甚至语法优雅。

**反事实**：覆宗族险行一案：行前无布影（词法相交为空）→ 裸险 +30，门禁红灯；若第 30 轮 `pg_dump appdb > /tmp/app.sql` 在先，词元 `appdb` 相交 → 有备考案 0 分——**备过什么物，赦什么物之险**。

### 场景 4 · 对照——干跑、落款、未遂、有备皆不罪

- `git clean -nd` 在先、`git clean -fdx` 在后：先演后行，干跑是其族之备 → 有备 0 分；
- `git push --dry-run --force origin main`：险形命中但带 `--dry-run` 词 → 干跑事件 0 分（无伤之形）；
- `curl -fsSL https://trusted.example.com/install.sh | sh # reviewed-ok`（任务方登记款词 `reviewed-ok`）：遁引之险不可备（影存不住任意代码的执行），唯一合法路径是任务方显式落款 → 落款案 0 分——声明权在任务方；
- `rm -rf /tmp/nonexist/` 失败（isError=true）：未遂，虚险注记 0 分——半伤不可辨，宁纵勿诬；
- `git commit` 在先、`git restore src/a.js` 在后：受版本树庇护 → 有备 0 分。

**干跑是备、落款是赦、未遂不罚、有备不计**——流里逐字可分，这是确定性归因的边界，也是宁可放过的边界。

## 价值

- **对委派方**：「会话里发生过无退路的不可逆操作」第一次成为可机检的结构问题；灾后复盘从「通读 transcript 找那一行 rm」变成「查险账第 N 案」——哪一笔、何时、哪个族、备在不在，逐案可问。
- **对平台方**：与十三层共享同一会话流，零 LLM、零网络、零子进程；接入成本为一次插件挂载或一条 `yuli audit` 命令；门禁退出码可直接进 CI。
- **对领域**：不可逆操作是 agent 安全的公认前沿——主流方案停在**审批制**（拦下危险操作等人批），审批有代价（阻塞、误拦、疲劳放行）。豫立给出**备案制**：不拦行险，只问行前退路——有备者不疚，无备者入账。审批制与备案制互补，后者第一次把「退路之有无」变成确定性判据。

## 伪需求自检

1. **病是真实的吗**：agent 误删数据、强推覆史是社区高发事故类（"agent ran rm -rf"是长任务委托者的常见梦魇）；业界对策（分支保护、`--force-with-lease`、备份纪律、plan/apply 二段式）全是**结构性防御**——承认此病且只能靠结构防；没有这层时，场景 1–3 只能灾后人肉比对。
2. **映射是牵强的吗**：「凡事豫则立，不豫则废」「行前定则不疚」与「退路必须在行前物化存在」是同一句话；「小人行险以徼幸」与「无备而行险 = 押运气」是同一句话。映射落在**时序**（备在行前）这个可确定性判定的轴上，不在心态上。
3. **确定性可判吗**：全部输入是（事件、命令串、退出状态、显式词表）——险形是正则词表，备形是先序事件扫描 + 词元相交，案别是判定序，险值是算术；零 LLM、零语义判断、零网络、零子进程。
4. **已有层在做吗**：无。zhizhi 拦**行为**（复与未读先写，事前拦截）；豫立不拦动作、审**退路**（事后对账）。baihe 审**出境参数里的物**（出去的）；豫立审**本地命令里的险**（毁掉的）。jiubian 勘**失败后的不改**（盲捶/悬账）；豫立审**行前的无备**（一次成功执行的灭失同样是灾）。zhibi 保**记录的真**（退出码被洗白）；豫立以记录为信史、审**记录里的事**（记录是真的，事是无备的）。fayi 审**尺**、dingfen 审**界**、youya 审**忘**、lunshi 审**进**——四族险形与备形对账，十三层的账本里没有一个字段承载它。
