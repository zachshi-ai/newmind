# 法仪 · 持尺协议

**天下从事者，不可以无法仪；无法仪而其事能成者，无有也。** 你既施工又持尺——测试是你写的、也是你改的、通过还是你宣布的。尺在手里弯了，绿就是假的。本协议不让你更聪明，只让「量尺本身」变成四条可执行的纪律。

## 四条纪律

### 一、开工认尺：先看册，再动手

开工先看器册（`fayi block`，或宿主供给的绳墨块）：**哪些径是持性器径（冻住的尺）、哪些是修性器径（本轮交付的尺）、验尺词是什么**。改代码前知道尺在哪里，才谈得上不碰尺。

- 持性器径：`test/**`、`*.test.js`、快照、CI 工作流……改它们 = 改尺；
- 修性器径：账方声明为本轮交付的验收路径——改它们合法；
- 验尺词：`npm test`、`make check`……只有这些命令算「验过尺」。

### 二、改尺先立案：动尺之前，先声明

任务**本要**改测试（补用例、迁测试框架、修 flaky）？开工就登记：

```bash
fayi enroll --amend 'test/**' --verify 'npm test'   # 并集只增不删
```

已立案的尺改动是**修器**（合法，账上点名）；未立案的尺改动若恰好落在**红转绿的窗口**里、且窗内没有代码改动——那就是**曲尺**：绿是尺变出来的，不是码变出来的，枉值 +30，门禁红灯。先红后绿的 TDD 天然无罪（器写在红之前，窗外）。

### 三、器不虚设：断言必须能输

绳量不出弯的绳不是绳。写测试时禁止三形虚器：

- **同字面比较**：`expect(id).toBe(id)`、`assert.equal(a, a)`、`assert x == x`——恒真；
- **恒真断言**：`assert(true)`、`assert.ok(true)`、`assert True`；
- **空体用例**：`it('works', () => {})`。

每件 +10，三件门禁红灯。断言够不够强法仪不判（那是语义），**恒不恒真**词表可证——先保证尺能输，再谈尺的锋利。

### 四、尺要照末：交付态必须被尺照过

最后一笔代码改动之后，**必须再跑一次验尺词**。绿验之后再改代码，旧绿就罩不住新状态——收工时账上就是**废尺**（+30，门禁红灯）。末验是红不是罪：尺新而话诚，红是任务的失败，不是尺的腐败——如实报红，比旧绿冒充新绿诚实一百倍。

## 何时不许改尺（速查）

| 你想做 | 合法路径 |
|---|---|
| 修 bug、重构实现 | 随便改，改完**再验一次尺** |
| 补新测试（TDD） | 先写测试看它红，再写实现看它绿 |
| 任务本要改测试/CI | `fayi enroll --amend <glob>` 立案后改 |
| 让红的套件变绿 | 改**代码**让它绿；改测试让它绿 = 曲尺，门禁红灯 |
| 验尺红了但任务是完成的 | 如实报红。不罚，但不得宣布完成 |

## 诚实边界

1. **流里没发生的，账上看不见**：带外改的尺，法仪无从知晓——这是流审计的共同边界；
2. **红不问因**：验尺失败就是红，环境失败与用例失败在账上同色——甄别红因是你的事；
3. **枉值 0 不是质量分**：只说明尺未弯、器未虚、照过末账——测试写得坏而不虚，法仪不管；
4. **存疑宁纵**：翻红窗里尺与码同改，绿不可归因——法仪不罚存疑，但你要知道存疑在账上点过名。
