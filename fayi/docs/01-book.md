# 01 · 选书：《墨子·法仪》——天下从事者，不可以无法仪

## 为什么是《墨子》

给「验收器完整性治理」找思想源头，候选不少：韩非子的循名责实（形名参同，已近知止的完成核验）、管子的正名百物（近定分的名分之学）。而《墨子·法仪》对「量尺本身」有一套**更结构化**的解剖——它不只讲"做事要有标准"，它论证**标准从哪里来才可信**（法不仁，不可以为法——标准若出于被量者自身，此法必弯）、给**工具的外在性**（百工为方以矩，为圆以规——尺在手的对面，不在手里）、还给**笨巧皆度的普适性**（无巧工、不巧工，皆以此五者为法——好的尺不依赖持尺人的品行）。这三件事恰好就是 Agent 验收器治理的三个设计支柱，且《墨子》未被本仓任何项目使用（zhizhi 道德经 / jiebi 荀子 / zhengnian 坛经 / weibing 黄帝内经 / jiubian 孙子 / youya 庄子 / lunshi 孟子 / dingfen 商君书 / buer 论语〔在途〕/ licheng 周易〔在途〕/ baihe 鬼谷子〔在途〕）。

## 原典条款 → Agent 病 → 机制：逐条映射

| 《墨子》原文 | Agent 的病 | 法仪的机制 |
|---|---|---|
| 法仪：**天下从事者，不可以无法仪；无法仪而其事能成者，无有也** | 验收不是有没有的问题（任务书体检是 weibing 的 t=0 地盘），是**量过的过程中尺还信不信**：会话几十轮，尺在流里被悄悄重铸，没人看见 | **器册**：开工显式立册——持性器径（冻结的验收物）、修性器径（声明为本轮交付的验收物）、验尺词（什么算一次验尺）；默认形表与显式登记取并集，绳墨块公示于接缝 |
| 法仪：**百工为方以矩，为圆以规，直以绳，正以县。无巧工、不巧工，皆以此五者为法** | 尺必须外在于手。Agent 既施工又持尺——写代码的是它，写测试的是它，宣布通过的还是它；尺随手的巧而弯，绿随尺的弯而假 | **持/修分性**：器径一经登记为持，非立案不得改；任务本要改测试的，账方显式登记为修——声明权在账方，如矩之于百工 |
| 法仪：**巧者能中之，不巧者虽不能中，放依以从事，犹逾己** | 验尺从红转绿的那一刻，**归因**是全部问题：绿是代码改对了，还是尺被改松了？流里逐字可查——红验之后、绿验之前，成功写落在哪条径上 | **翻红窗归因**：窗 =（最近一次红验，本次绿验]。窗内**纯器写**（只有器径写、无实测面写）→ 曲尺案 +30；器写与实测写同窗，绿不可归因——存疑宁纵，不计分 |
| 法仪：**法不仁，不可以为法**。父母不可法、学者不可法、君王不可法——皆"自为其度"；故**莫若法天**，天行广而无私 | 自我校准的循环：标准出于被量者自身，必不仁。Agent 自写测试自宣布通过，等于让被量者自铸其度 | **验尺词登记 + 照末**：什么算一次验尺由账方立册；交付态必须被验尺词照过（见下条）——尺的权威来自册，不来自手 |
| 法仪：**直以绳**——绳之用，在拉直不直之物 | 断言若恒真，绳就量不出弯：`expect(a).toBe(a)`、`assert.ok(true)`、空体用例——器在而器虚，绿是器虚之绿 | **虚器词表**（确定性形表）：同字面比较、恒真断言、空体用例，器径写中逐中记件 +10——绳必须能输，才是绳 |
| 法仪之度是**从事之度**：放依以从事，贯穿全程，非动工一刻之察 | 最后一笔实测写落在绿验之后——交付态从未被尺照过；绿是旧的，完成是自封的 | **照末（废尺）**：收工时末笔实测成功写之后无绿验 → 废尺案 +30；末验为红 → 尾红注记 0 分（尺新而话诚，红是任务之败，非尺之腐） |

## 与管理学互证

- **Specification gaming / reward hacking**（Krakovna et al., DeepMind 2020；Amodei et al. 2016《Concrete Problems in AI Safety》）：智能体优化的是度量而非度量背后的目标——测试正是编码 agent 的度量，改测试过关是该文献谱系里最经典的病形。
- **SWE-bench 评测规程**：评测前把仓库测试文件**重置为官方 test patch**——业界旗舰基准用结构性手段承认并防御曲尺之病；法仪把同一种防御下沉到会话流的审计层。
- **Mutation testing**（DeMillo, Lipton & Perlman 1978）：没见过红的测试套件证明力存疑——虚器是它的词表级下位（先可证"恒真之虚"，不强判"够不够强"——后者是语义判断，法仪不做）。
- **职责分离**（SOX / ITGC 审计独立性原则）：开发者不得自批自的工作——器册立册权在账方，即审计独立性的会话内下沉。
- **CI 门禁跑在最终 HEAD 上**（GitHub branch protection required checks）：陈旧的绿不算绿——即照末之废尺。

## 与相邻思想的分工

- 《商君书》"一兔走，百人逐之"讲**名分**（地归谁，dingfen）；《墨子·法仪》讲**法仪**（尺信不信，fayi）。定分治横向之争，法仪治纵向之弯——单会话自己把自己的尺掰弯，定分看不见，法仪管。
- 《荀子·解蔽》审**判断的产物**（jiebi 账本）；法仪审**判断的量具**（器径文件与验尺事件）。账本再诚实，尺弯了结论照样假。
- 《道德经》"轻诺必寡信"落在**行为**（zhizhi：数证据的有无）；法仪落在**量具**（审证据的结构条件：尺弯没弯、器虚不虚、罩没罩住末笔）。

## 诚实边界（我们不假装的事）

1. **审计对象是流**：流里没发生的改尺，账上看不见——经带外通道改的测试文件，法仪无从知晓；这是流审计各层的共同边界，不是法仪的缺陷。
2. **红不问因**：isError=true 的验尺就是红，不辨环境失败与用例失败（命令黑盒）——红因的甄别是判断层的事，不是量具层的事。
3. **虚器是词表级的**：只认可证之虚形（同字面比较/恒真断言/空体用例/Python 同字面）；"断言够不够强"是语义判断，零 LLM 约束下不做——宁可漏判，不可妄断。
4. **翻红窗只罚纯器写独占之窗**：器写与实测写同窗，绿不可归因——存疑不计分（宁可放过，不可错罚）；TDD 先红后绿（器写在红之前）天然不入窗。
5. **枉值 0 不是质量分**：只说明尺未弯、器未虚、末账已验；测试写得坏而不虚、验得勤而没照末账的情形法仪不管——它治尺的腐败，不治尺的钝。
