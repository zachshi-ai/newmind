# 03 · 设计：恒法 · hengfa —— DeepSeek Harness 的规矩源恒典层（恒法式插件）

> 本文锁死全部判定语义；实现与本文冲突时改实现，不改本文与 04 的手算期望。

## 1. 能力类型与接缝

新能力类型：**恒法式插件**（第二十九个）。zhizhi 证明插件可以拦，jiebi 证明可以审，
zhengnian 证明可以供给，weibing 证明可以诊，xiangxiao 证明可以听批评之默，
shuitu 证明可以审境变之复，kaocheng 证明可以考交付之契——恒法证明插件可以**审立法之名分**：
规矩源是仓库的常驻之法，生法者唯任务方，臣改法必留账、必对授权、必可复。

```
tools/result   emit   观察改典入账（唯一写入口）
（无 pre-execute）     —— 零拦截是结构性的
```

设计约束（与全仓同规）：模型无关（零 LLM、零提示词注入、零网络、零子进程、零文件系统探测）；
观察永不反噬（监听器异常吞掉，管道照常）；典册持久化归 CLI（register/revoke），插件只吃注入的
book 对象；单会话视图的案与值只采本会话，跨会话归并归离线合并审计。

## 2. 对象与通道（词法锁死）

对象键与工具族同全仓（object.js 同规：`p:` 文件 / `c:` 命令 / `n:` 不透明；
observe/write/exec/other 四族）。径规整同全仓（反斜杠归正、剥 `./` 前缀与尾 `/`）。

### 2.1 典形（默认形表，三族 25 形）——无册照判，开箱在岗

**宪形 8**（治理文书——写给 agent 与人的常驻指令）：

- 单名形 7（basename 全等，大小写敏感）：`AGENTS.md`、`CLAUDE.md`、`GEMINI.md`、
  `.cursorrules`、`.windsurfrules`、`.clinerules`、`copilot-instructions.md`；
- 前缀形 1：`.cursor/rules/`（目录前缀——规则目录内一切文件皆宪）。

**禁形 4**（CI 流程——组织的门禁通道）：

- 组合形 1：前缀 `.github/workflows/` ∧（尾形 `.yml` ∪ `.yaml`）；
- 单名形 3：`.gitlab-ci.yml`、`Jenkinsfile`、`.drone.yml`。

**章形 13**（检查器与格式化器的常驻章程——写给工具的规矩）：

- 前缀形 7：`.eslintrc`、`eslint.config.`、`.prettierrc`、`prettier.config.`、
  `biome.json`、`tsconfig`、`.stylelintrc`；
- 单名形 6：`.editorconfig`、`.pre-commit-config.yaml`、`.flake8`、`mypy.ini`、
  `ruff.toml`、`.ruff.toml`。

命中语义：单名形按 basename 全等；**名前缀形按 basename 以前缀开头**（`.eslintrc`、
`eslint.config.`、`.prettierrc`、`prettier.config.`、`biome.json`、`tsconfig`、`.stylelintrc`
七形与单名形一样是**文件名形**——子目录章程 `packages/*/tsconfig.json` 是 monorepo 常态，
按整径前缀会漏）；**径前缀形按规整径以前缀开头**（仅 `.cursor/rules/` 目录形——
它是目录不是文件名）；组合形两件皆中（径前缀 `.github/workflows/` ∧ basename 尾形
`.yml`/`.yaml`）。basename 提取用 `/` 切分末段（径已规整）。宪 > 禁 > 章：一径命中多族，
取最重族（宪）。

### 2.2 改典通道（案之生）唯三

1. **write 族 p: 径命中典形**——凡 write 族调用成功且对象键为 `p:<径>`，规整后命中
   典形即改典一笔（edit 族不携全文亦立案——改了就是改了，内容不参与判定）；
2. **exec 族生产词法**——命令切段（`&& || ; |`）后逐段，段内非破坏性时：
   `cp`/`mv` 的**末个非旗标词元**规整后命中典形 → 改典（拷贝/挪移落点）；
   `tee`/`touch` 的**任一非旗标词元**命中典形 → 改典；
   重定向目标（`>`/`>>` 后的第一个词元，`2>&1` 天然不中）命中典形 → 改典；
3. **exec 族灭典词法**——段内任一词元（小写化）命中**灭词表**
   （`rm unlink rmdir del erase trash shred`——`git rm` 之 `rm` 亦中），且段内任一非旗标
   词元与典形之径匹配（规整逐字相等 ∪ 宽 glob：词元含 `*` 时按通配全匹配）→ 改典
   （灭典也是改典——删规矩比松规矩更彻底）。破坏段内的词元不再计生产工见（rm 不生产）。

**观察不是改**：observe 族（read/glob/grep/ls…）永不立案——读规矩是守法，不是立法。

**失败不入账**：`isError === true` 一律不入账（失败的改不是改）；isError 未知按已发生入账。

### 2.3 案账与基点（每径一案）

- **每径一案**：同一典形之径的全流多次改典并一案——本层不数次数（屡改归 zhizu 地盘），
  只记「这径的规矩被谁改到了什么地步」；
- **末笔定基点**：案的基点 = 该径末笔改典之 seq；更后的改典刷新基点；
- **复典重立**：基点之后的复典据销案；销案后同径再改，立新案、新基点。

## 3. 典册（开门授权，声明权全在任务方）

```json
{ "version": 1, "open": ["eslint.config.*", ".github/workflows/deploy.yml"] }
```

- **open（开门列）**：glob 串数组——本任务**授权可改**的规矩源。宽 glob：词元含 `*`
  时按通配全匹配、`*` 跨目录（同全仓 tokenMatchesPath 语义）；不含 `*` 时规整逐字相等。
  open 命中（逐字相等 ∪ glob 全匹配）的改写**不立案**；
- **无册照判**：典形开箱在岗，规矩是仓库的公共物，不需要每单任务重新声明——
  **无册不等于无宪**；册只管开门一侧，v1 不扩形、不豁免（授权之外无第二列——
  同 shuitu 土册 v1 只一列之例）；
- 册是结构化 JSON、唯一入口（CLI register/revoke），无词旗标覆盖；
- **无册 = 全护**：不带 `--file` 审计时 open 列为空——授权写也立案（开门授权只能来自册，
  这正是「生法者君」的结构化表达）。

## 4. 复典据（复位凭据）

改典案的复位凭据，只认 git 词面（流内可证、零文件系统探测）：

| 复词形 | 判定 | 销案范围 |
|--------|------|----------|
| `git revert` | 段内词元含 `git` 与 `revert` | **全域**——回滚提交即复原，从宽 |
| `git restore` | 段内含 `git`、`restore`，且任一非旗标词元与案径匹配（逐字 ∪ 宽 glob） | 该径 |
| `git checkout --` | 段内含 `git`、`checkout` 与 `--` 分隔符，且任一非旗标词元（`--` 之后）与案径匹配 | 该径 |

- **基点时序保护**：复据的 seq 必须 > 案基点——先复后改不销案（复据在基点之前，
  是改前旧事，销不得这案）；
- **复典销案不销账**：已复之案从法值出账（0 分），案账中保留注记「已复」
  （径、基点、复据 seq）——历史留痕，审计可见；
- **write 写回不判复**：流内无法验证写回内容等于原状，唯 git 词面可凭。

## 5. 法值与门禁

```
xian(宪)  = min(60, 30 × 未复宪案数)
jin(禁)   = min(60, 30 × 未复禁案数)
zhang(章) = min(30, 15 × 未复章案数)
total     = min(100, 三项之和)
```

分带：**恒 0–14 / 摇 15–29 / 篡 ≥30**。门默认 30：

- 单宪案、单禁案即红（30 ≥ 门）——改治理文书与破 CI 流程是「臣生法」的死门；
- 单章案 15 落摇带，黄牌点名不咬门（章程之改常在两可，记账留痕为主）；两章案即红；
- 已复之案恒 0 分（复典出账，注记保留）；全零 → 恒。

## 6. 法牌块（接缝供给，逐字节确定）

```
【恒法 · 法牌】
典册：开门 2 径（eslint.config.*、.github/workflows/deploy.yml）
案账：宪 0 · 禁 1 · 章 1 · 已复 1
宪案：AGENTS.md（基点 seq 7）
章案：tsconfig.json（基点 seq 12）
已复：.eslintrc.json（基点 seq 5，复据 seq 9 git restore）
```

无册法牌（确定性文本）：`典册：未立（开门无据，典形全护）`。
块中永不出现写入内容原文（法牌只载径、族、基点与判语——掩码是结构性保证）；
案行按族排序（宪 → 禁 → 章，族内按规整径字典序），同输入两次渲染逐字节相同（shasum 可证）。

## 7. issues 行序（锁死）

宪案 → 禁案 → 章案 → 已复注记 → 全恒（`典皆恒 ×N —— 君臣上下皆从法`，N=在案总数为 0 时
出此行）；无册时法牌块出确定性文本，issues 不因无册而沉默（无册照判——默认形开箱在岗）。

## 8. 插件 API 与 CLI

**插件**（`hengfa-dsh`，Service 名 `hengfa`）：`report()` 汇总、`ledger()` 案账全文（逐案）、
`paizi()` 法牌块、`gate()` 门禁裁决、`exportStream()` 导出会话流（call/result 成对、args 原样），
供 `hengfa audit` 离线重放对账。

**CLI**（零依赖，`hengfa`）：

```
hengfa audit <s1.jsonl> [s2 …] [--file <典册>] [--gate n] [--json]
hengfa register --path <glob> [--file <典册>]     立门（开门授权，重复去重）
hengfa revoke --path <glob> [--file <典册>]       销门
hengfa list [--file <典册>]                       阅册
hengfa block [--file <典册>]                      法牌块（逐字节确定）
hengfa gate --value <n> [--gate n]                门禁裁决
hengfa --help | --version
```

默认册 `./.hengfa.json`；register/revoke 册缺失自动建册（开门是授权，空册 = 全护——
同 kaocheng register 自动建册之例）；revoke 无此径 exit 2；list 册缺失 exit 2。
退出码：0 通过 / 1 门禁失败 / 2 用法与输入错误。

## 9. 与既立各层的方向边界（结构性，不是纪律性）

知止拦动作，解蔽审判断，正念守意图，治未病体检开工，九变勘应变，有涯守见闻，
论世审发令资格，定分裁写域，捭阖守出境，法仪护尺，直笔保笔，豫立审备，
度支量入，二柄审柄，终始记程，效验称实，名实核名，立诚结诺，稽疑稽问，
乡校听声，知足量出，审曲审残全，舍筏审落物之宿，渊鱼审入目之禁，不贰记跨会话之训，
水土审境变复位，考诚考交付之契；**恒法审立法之名分**：典形（词面）→ 案账（基点）→
法值（门禁）→ 法牌（供给）。

- **乡校**：一行一源。它审写进**代码一行**的静音指令（@ts-ignore、eslint-disable——
  让批评闭嘴的词），显式让渡了**配置级**的静音（eslint 配置 off、CI 删步骤「不判，
  宁纵勿诬」）；本层接的正是那块让渡地：规矩源文件被改写这件事本身入账，不判削弱
  还是增强（语义判断是全仓禁区）。两册同构不同向：它的册管豁免（让默认不判），
  本层的册管开门（让默认立案）。
- **法仪**：一尺一典。它审**验收器**——任务方器册登记的测试之尺，且只审翻红窗里的
  器写（时窗归因）；本层审**常驻规矩源**——形表开箱在岗，不问红绿、凡改即案
  （名分归因）。tsconfig 之改可以同时是两层的案（登记为修性器径落翻红窗 × 未授权
  改章程）——两账并行不悖，同豫立备形 × 舍筏筏形之例。
- **shuitu**：一机器一仓库。它审**机器常驻态**（全局包、家目录 rc、服务——`npm install -g`
  与 `~/.zshrc`），本层审**仓库规矩源**（`eslint.config.mjs` 与 `AGENTS.md` 在仓库里）。
  rc 若在仓库内且命中典形（如 `.editorconfig`）照本层立案——机器态与仓库态谓词正交，
  同一笔写两账并行。
- **kaocheng**：一契一典。它考任务方立的**契约之物**（该交付的在不在、成没成形），
  本层记**规矩源之变**（不该动的动了没有）。「改 eslint 配置」可以是任务本身——契上有它
  则它考物，典册开它则本层免案；契上无它、册上无门，则物考不着它、案记着它。
- **zhizhi**：账与闸分治。拦动作是它的地盘，本层从不拦——恒法全部发生在接缝之后，
  观察永不反噬。
- **zhizu**：一量一名分。它量写的**规模**（多少行、多广的手、翻了几回——同径屡改归它），
  本层记改典的**名分**（每径一案，不数次数——改一百次也是一案）。
- **zhibi（直笔）/weibing/jiebi/zhengnian/jiubian/youya/lunshi/dingfen/baihe/yuli/duzhi/
  erbing/zhongshi/xiaoyan/mingshi/jiyi/shenqu/shefa/yuanyu/buer**：对象键正交（笔直/
  开工体检/判断/意图/势途/见闻/渠道/写域/出境/退路/量入/柄/众事行程/成色/名/问/残全/
  落物宿/入目禁/跨会话训），本层对象是常驻规矩源与开门授权，互不引词。

## 11. 既知从宽代价（宁漏方向，逐条登记）

- **杂糅文件不入典形**：`pyproject.toml`、`package.json`（身份杂糅——既装依赖又载章程）
  v1 不入形表；`pyproject.toml` 内 `[tool.ruff]` 之改不判（宁纵，登记）；
- **小写变体不中**：`agents.md` 不中 `AGENTS.md`（basename 全等、大小写敏感，与全仓词法
  同规）——形表按惯例大小写登记，变体漏网；
- **非 git 复原不可见**：写回原内容的复原无凭据（零文件系统探测），唯 git 词面可凭；
- **git revert 全域从宽**：一笔回滚销全部在案——回滚了哪个提交流内不可见，宁纵方向；
- **open 是开门不是审稿**：开门之改改了什么都免案——授权是名分不是语义（审稿是语义判断，
  全仓禁区）；开得过宽（如 `eslint*`）是任务方的权，不是本层的咎；
- **exec 无径词面不判**：`npx eslint --fix` 类不落径词面的规则改写不可见（改的可能是
  代码不是章程，词面无从分辨，宁漏勿诬）；
- **写入内容不参与判定**：edit 族不携全文、write 携全文——无论携不携，改典案只看
  `p:` 径命中（内容语义不判，改了就是改了）；
- **词法可欺但骗一次留一次形**：改完再用 `git commit` 收尾，词面照记——除非 revert 词面，
  流内没有「改得对」的出口，只有「开了门」的出口；
- **时序以流序为准**（缺 at 照判）；**多族命中取最重**（宪 > 禁 > 章，宁重不轻）。
