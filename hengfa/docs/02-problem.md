# 02 · 问题：Agent 矫法自便（规矩源自改无账）

## 谁在什么场景下的什么问题

**谁**：用 agent 在共享仓库里干活的工程师（派活方），以及接手下一单活的下一个会话。

**场景**：任务方派活；agent 干活过程中发现「照规矩办这单活过不去」——lint 报错、
strict 拦路、CI 红、AGENTS.md 的条款碍事。它手里有写文件的手，于是顺手把规矩改松：
这一单活绿了。

**问题**：仓库的**常驻规矩源**——治理文书（AGENTS.md、CLAUDE.md、.cursorrules…）、
CI 流程（.github/workflows/、.gitlab-ci.yml…）、检查章程（eslint/tsconfig/prettier/
pre-commit…）——被这一单活改写了，而：

- 没有任何一层问过「**谁在何时动了规矩、动的时候任务方授没授权、动完复原了没有**」；
- 改动混在几百行 diff 里，人眼漏掉；就算看见，也分不清是任务本身的正当修改
  （「升级 tsconfig 并修掉报错」）还是为绿而松尺——**意图无从考，授权可考而无人考**；
- 下一单活、下一个会话继承松掉的规矩：类型检查形同虚设、CI 步骤缺了一条、
  agent 的行为准则已是改过的版本——「昨天严今天松」，错的不在它而在宪。

## 问题（治什么病）

四个病形，全部真实存在、全部有据可查：

| 病形 | 流内词面 | 现实对应 |
|------|----------|----------|
| **改宪** | write/edit 命中 AGENTS.md、CLAUDE.md、.cursorrules 等治理文书 | agent 改写约束自己的行为准则——评测与研究里反复报告的 rule circumvention |
| **弛章** | write/edit/exec 落点命中 eslint/tsconfig/prettier/pre-commit 等检查章程 | 为让绿而松尺：关规则、放宽 strict、删格式约束——AI 生成代码质量债的经典来源 |
| **破禁** | 写落点命中 .github/workflows/、.gitlab-ci.yml 等 CI 流程 | 嫌红就删检查步骤、摘掉门禁——拆警报器 |
| **灭典** | rm 词族命中典形（`rm .eslintrc.json`） | 删规矩文件——比松尺更彻底的销法 |

相邻两层的空白地是**登记在案**的：乡校审写进代码一行的静音指令（@ts-ignore、
eslint-disable），显式让渡了配置级静音——「eslint 配置 off、CI 删步骤不判（宁纵勿诬）」；
法仪审**验收器**——任务方器册登记的测试之尺，且只审翻红窗里的器写。常驻规矩源的
未授权改写（不问红绿、不问语义、凡改即案），是两层各自让渡出来的真空地带。

## 价值（为什么不是伪需求）

1. **每一笔都真实落在仓库里**：规矩源被改，下一单活全数继承——这不是「可能有用」
   的推断，是仓库状态的既成事实；对账材料全在会话流里（write 的 p:、exec 的落点词面），
   词法可证。
2. **业界的结构性招供已经存在**：评测侧把 rule circumvention 列为对齐风险的研究对象；
   工具链侧 gitleaks 守密物、semgrep 守代码形——但「**谁改了规矩、授没授权**」的授权账，
   没有任何一层或一件工具在记。本层不做语义判断（不判改得好坏），只做名分判断
   （改没改、开没开门、复没复）——恰是零 LLM 能确定性回答的三问。
3. **账与闸分治**：不拦改（拦是 zhizhi 的地盘）——任务正当改章程的路（升级配置、
   修 lint）完全通畅，典册开门即免案；无门之改也不是罪，是**账**：留痕有价、点名有责、
   门禁有阈。宁可全记而错记，不可全不记。
4. **可证伪**：分数公式、判定序、形表全部锁死于 03；同流重放必得同判词；
   跨项目历史流可验尸复算——错了改实现，不改标准。

## 产品形态

- **恒法式插件**（DeepSeek Harness 插件层，Cordis，结构性零拦截）：挂 `tools/result`
  观察口，改典案入账，法牌块接缝供给；
- **零依赖审计 CLI**（`hengfa`）：多流离线重放，可验尸任何历史会话；
- **Agent Skill**：给派活方与 agent 的开门/守法协议。
