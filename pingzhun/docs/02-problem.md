# 02 · 问题：Agent 依赖面自便（命脉籍面改动无账）

## 谁在什么场景下的什么问题

**谁**：用 agent 写代码并交付上库的工程师，以及接手这个仓库供应链安全的
下一个人、下一个会话。

**场景**：agent 干活时被依赖问题卡住——装一个包报版本冲突、类型定义对不上、
某个模块缺失——于是它顺手解围：往 `package.json` 里添一个新包（每难必附）、
把 `"a": "1.2.3"` 改成 `"a": "^1.2.3"`（松锁过关）、在 requirements.txt 顶上加
一行 `-i https://某个镜像`（移源）、往 scripts 里埋一个 `"postinstall": "curl … | sh"`
（埋钩）。任务绿了，宣布完成，籍册上库。

**问题**：交付的**籍面**（依赖清单与锁文件）被这单活顺手改写，而改动无账：

- **供应链面静默扩大**：每一个新附名都是一条新的供给线。幻觉包名被抢注
  （slopsquatting——模型常幻觉的名字，攻击者批量注册守株待兔）之后，
  写进籍册的幻名不是装一次就完了——它次次 `npm install` 必装、上库后毒化
  每一个未来的协作者；install 钩子是装包即执行的代码，registry 重定向把
  供给线整条改道；
- **可复现性静默漂移**：精确版本松成范围，今天装的与下个月装的不再是同一
  棵依赖树，「昨天绿今天红」多了籍面这一个病源；
- **人眼漏掉**：籍面改动两三行，混在几百行 diff 里不起眼——但籍面是全仓库
  唯一「每行都授权一次代码执行」的文件；
- 就算看见，也分不清是「正当的依赖升级」还是「为解围而自便」——
  **意图无从考，词面可考而无人考**。

相邻层的空白地：恒法审**规矩源**（AGENTS.md/CI/检查章程）却显式让渡了
杂糅文件——「pyproject.toml/package.json 既装依赖又载章程，v1 宁纵登记」，
籍面正是那块让渡地；名实记**装成之包**的事件（幻包/新装），籍册上写着什么
不是它的对象——幻包装一次归它记案，幻名写进籍册则次次必装，那份**常驻的
授权文书**归本层；水土审**机器常驻态**（全局包/家目录 rc/服务），仓库内
籍面不是机器态；知足量**写之量**（行数/写域/屡改），两行的籍面改动在它的
账上不可见；考诚考**契上物**（无册不判），全籍面的内容判定无人做。

## 问题（治什么病）

四个病形，全部真实存在、全部有据可查：

| 病形 | 流内词面 | 现实对应 |
|------|----------|----------|
| **增附** | 旧本四节（dependencies/devDependencies/optionalDependencies/peerDependencies）皆无之名，末文有之 | 每难必附：供应链面静默扩大，幻名入籍则次次必装 |
| **去锁** | 同一附名，旧本精确版本（`1.2.3`）→ 末文范围（`^1.2.3`/`*`/`>=`）或脱钉 | 可复现性漂移：同一籍册今昨二树 |
| **越源** | requirements 行旗标 `-i`/`--index-url`/`--extra-index-url`/`--trusted-host`、package.json `publishConfig.registry`、pyproject `[[tool.uv.index]]`/`[tool.poetry.source]`、Gemfile `source`——宿主非默认域 | 供给线整条改道：registry 重定向是供应链攻击的正面 |
| **钩入** | package.json `scripts` 新增 `preinstall`/`install`/`postinstall`/`prepare` | 装包即执行：install 钩子驮 malware 的正面通道 |

价值锚点：每一笔都真实落在交付的籍面里，下一单活与每一个协作者全数继承；
对账材料全在会话流里（write 的 `args.content` 是末文，先前之写与成功读取的
`result.content` 是旧本——zhixing 已证「知面取文于流」可行），词法可证；
工具链侧 Renovate/Dependabot/lockfile-lint 守仓库现状，但「**谁在何时添了
哪个附、松了哪把锁、移了哪个源、埋了哪只钩、任务方授没授权**」的流内账，
没有任何一层在记。本层不做语义判断（不判这次添附值不值——正当升级与
解围自便在词面上同形，裁决权归人），只做词法判断（添没添、松没松、源在
不在、钩新不新）——恰是零 LLM 能确定性回答的四问。

## 价值（为什么不是伪需求）

1. **每一笔都真实落在仓库里**：籍面是全仓库唯一每行都授权代码执行的文件，
   改动是交付状态的既成事实，不是「可能有用」的推断；
2. **意图可豁免而词面须留痕**：依赖升级确实是正当工作——命籍（任务方声明
   的纳籍）开门即免案；无籍之案也不是罪，是**账**：留痕有价、点名有责、
   门禁有阈；
3. **记账不禁行**（平准的非开利孔条款）：不拦写（拦是 zhizhi 的地盘）、
   不改籍册、不跑语义分析——扫描全部发生在流内词面上，观察永不反噬；
   「与民争利」的恶税吏不是本层的姿态；
4. **可证伪**：四案词法、判定序、分数公式全部锁死于 03；同流重放必得
   同判词；跨项目历史流可验尸复算——错了改实现，不改标准。

## 产品形态

- **平准式插件**（DeepSeek Harness 插件层，Cordis，结构性零拦截）：挂
  `tools/result` 观察口，籍账入账，准牌块接缝供给；
- **零依赖审计 CLI**（`pingzhun`）：多流离线重放，可验尸任何历史会话；
- **Agent Skill**：给派活方与 agent 的开籍/纳籍协议。
