# 02 · 问题：Agent 知行断层（知而不行无处对）

## 谁在什么场景下的什么问题

**谁**：任何给 DeepSeek Harness agent 立过章程的人（在 AGENTS.md / CLAUDE.md 里写下戒条与
必行事项的工程师、任务方），以及事后要为「章程为什么没被遵守」负责的复审同事与 CI。

**场景一：违知（禁了却做）。** 仓库章程写明「禁止 git push --force」。agent 开工第 2 步
成功读入了 AGENTS.md（知已入账），第 27 步与远端冲突时顺手执行 `git push --force origin main`
——成功落地。事后问起：账上有「读过章程」的记录（稽疑记它「已问」，0 分），行为账本干净
（知止绿），没有任何一层能回答「章程里的戒条为什么没有约束住这一步」。

**场景二：违知·亲命（令出即悖）。** 任务方在册上直书戒词（`bans: ["TODO_FIXME"]`——
不许交付带这个标记的代码），agent 从未读过任何章程，写出的文件内容里赫然是
`// TODO_FIXME`。直令之知不需要装载仪式——令出之刻即是知入之刻，撞了就是悖，
今天没有任何机制把这道直令对到每一笔写上。

**场景三：缺行（令了不做）。** 章程写明「交付前必须先跑 npm run lint」。agent 修完代码、
测试绿了、宣布完成——全流从头到尾没有一笔 lint。稽疑审首动之前问没问（它问过了——
章程读在第 2 步），知止数证据（它的绿命令都有证据），终始记立了的事做没做
（没人把「跑 lint」立进事册，无册不判）——「章程里那道必行令执行没有」全仓无账。

**场景四：复审无处问起。** CI 门禁要回答「这一单活，章程的戒条条条守了没有、必行令件件
跑了没有」，只能人工通读 transcript：找出装载点、逐条抄下戒条、再对着几百条工具调用
人工比对。会话流里明明带着全部证据（装载的内容与每一次执行的命令原文都在流内），
却没有一张账把「知面 × 行面」对起来。

## 问题（治什么病）

**Agent 知行断层**：章程被成功装载之刻，其戒条已发动为行为义务（一念发动处便即是行）；
但装载模块与执行模块是解耦的——**知入了，行悖了，中间没有对账**：

- **稽疑（jiyi）**审**首动之前问没问**（读没读章程——行之始），问凭据通道一成立即 0 分；
  此后行为与所问凭据矛盾，它无案别可记——断层恰在它的下一格；
- **恒法（hengfa）**审**立法之名分**（谁有资格改章程文书——改典入账），章程被**改**它记账；
  章程被**无视**（不改你，但不照你做）它无从看起——一改一行，两不越界；
- **知止（zhizhi）**拦**行为失控的形**（重复失败死循环、未读先写），不做行为对章程的
  逐条对账——它拦的是失控，不审悖知；
- **考诚（kaocheng）**考**立下之契对物之末据**（交付物在不在、成不成形），契约考的是物；
  章程约束的是**全程的行为**（每一步命令与每一笔写），一行一物，两不越界；
- **终始（zhongshi）**记**事册之行程**（立了的事做没做——无册不判），章程里的必行令
  没被立进事册时，缺行无处可记——知行以章程装载为账基，不依赖事册。

结构性证据：agent 框架普遍把章程文件读入 system prompt / 上下文窗口即视为「已遵守」，
业界对 prompt 遵从度没有确定性度量——「读了」被当成「照做了」，正是王阳明解剖的
知行分立之患：**世人以为知行是两件事，先知后行；殊不知知而不行，只是未知。**

## 价值（为什么不是伪需求）

自检四问：

1. **问题是真实的吗？**——是。「agent 读过章程/规则但行为不照做」是 agent 协作最高频的
   失败形态之一：戒条（禁 force 推送、禁动目录、禁提交某类物）与必行令（先跑 lint、
   先跑测试再交付）写在章程里，装载即忘；后果真实落地（force 推送覆写远端、
   未 lint 的代码进主干），而事后复审连「章程哪一条在哪一步被违背」都无处问起。
2. **本仓已定标的二十九层真的没治吗？**——逐行核过方向登记表。稽疑问**始**（读没读）、
   恒法审**改**（法之名分）、知止拦**形**（行为失控）、考诚考**物**（契对末据）、
   终始记**册**（事册行程）——「已装载章程与实际行为的逐条对账」全仓无账。
   本层与五层两两并行：一始一行、一改一行、一拦一考、一物一行、一册一行
   （边界在 docs/03 §11 逐层锁死）。
3. **确定性可判吗？**——知面（成功装载的章程径与内容）、行面（exec 命令串原文 ∪ write
   落径 ∪ write 内容）、戒形（11 句式词法提取 ∪ 显式登记）、必行词（只认显式登记）——
   全部词法与结构可判：装载时序比 at、子串与词元匹配纯字符串运算。
   零 LLM、零语义判断、零网络、零子进程、零文件系统探测——**知面取文于流**
   （装载内容的证据在流内 result），全账内生。
4. **判罪会不会冤枉？**——清白道全在设计里：**试违不罪**（isError=true 的执行不入行面
   ——失败之试宁纵）；**先悖不溯**（装载之前的行为不溯既往——不知者无罪，且装载前的
   「问没问」归稽疑审谋）；**戒形只生自知面**（章程未被装载则无戒形可撞——化知道
   结构性排除「不知之罪」）；**必行只认亲命**（缺行只判显式登记的必行词——默认提取
   不生必行令，缺席定罪宁纵勿诬）；**宥词在册**（任务方显式豁免的行不计案）；
   **老流降级**（装载记录无 content 则化知道诚实沉默，只注记）；**逐案点名**
   （每案可对到章程径、装载时刻与行为时刻）。

## 产品形态

DeepSeek Harness **知行式插件**（Cordis，结构性零拦截）+ 零依赖审计 CLI + Agent Skill——
与全仓范式一致：可运行、可测量、可证伪、可离线重放验尸。
知行式是本实验室**第三十个能力类型**（拦/审/供给/记习/诊/勘流/巡忆/权界/封界/守境/
持尺/秉笔/行前定/计账/审柄/记程/称实/核名/结绳/稽问/谏诤/量出/审材/敛迹/察渊/察土/
考诚/恒法之后）：判定对象不是动作的节制形（知止）、问没问的谋值形（稽疑）、
改典之名分形（恒法）或契上物之末据形（考诚），而是**已装载之知对流中行为——
禁了却做即违知，令了不做即缺行**。
