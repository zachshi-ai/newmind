# 03 · 设计：事册 / 程账 / 案别 / 先后账 / 程值 / 程账块

> 本篇实现**前**定稿；词法、判定序、分值、模板一经定稿不得为实现缺口事后删改。

## §1 总览

```
开工立事册（zhongshi enroll / .zhongshi.json）     账方：items ∪ order（声明权全在任务方，无册不判）
        │
会话流（tool_call/tool_result，可多流按参序拼接）    插件 tools/result 观察（结构性零拦截）
        │
   ┌────┴──────────────────────────────────┐
   │ 作工面：observe ∪ write ∪ exec 族       │ ← 同仓工具族表；todo 族显式排除（见 §3）
   │ 逐调用逐项分类：弃形 > 终形 > 作工       │    argsText 词面子串（大小写归一）
   └────┬──────────────────────────────────┘
        │
 程账：逐项事件序列（W/T/A，seq=全流调用序）
   案别（末笔定）：幽项（无迹）／半途（末为 W）／有终（末为 T）／有弃（末为 A）
   空终案：其后复有作工之终言，逐案计
        │
 先后账：order [A,B] —— B 之始早于 A 之终 → 失序案（A 无终不判）
        │
 程值 = min(100, min(60,30×幽) + min(30,15×半) + min(40,20×空终) + min(30,10×失序))
        → 分带（近道/鲜终/无终）→ 门禁（默认 30）
        │
 程账块（接缝处供给：逐事行程图 = 中断续跑的交接班记录，逐字节确定）
```

## §2 会话流与调用归并

与 zhizhi/jiebi/zhengnian/weibing/jiubian/youya/lunshi/dingfen/baihe/zhibi/yuli/duzhi/erbing 同规（互审前提）：每行一个 JSON；`#` 与空行为注释；坏行报行号；带 id 的 call/result 按 id 首见配对；无 id 旧格式 result 并入紧邻其前的 call；孤儿 result 独立建档（isError=null）；`turn_*` 等非工具事件跳过。`at` 原样保留，缺时记 null。**时序以流序为准**（calls 数组序），`at` 仅供展示——缺 at 不影响任何判定。

**多流拼接**：CLI 审计可取多个流文件，按参数顺序拼接为一个调用序列，seq 全局递增——这是中断续跑的审计形状：`zhongshi audit part1.jsonl part2.jsonl` 审的是两班合计的账。

## §3 工具族与作工面

- familyOf 逐字沿用同仓惯例（观察/写/执行/其他，精确表 ∪ 包含表，youya/jiubian 同表）；
- **作工面 = observe ∪ write ∪ exec 族**：读一个路径含项词的文件是开工之迹（查即始），写是施工，exec 是运斤——三族全记；
- **todo 族显式排除**：调用名（小写）精确命中 `todo_write` / `todowrite` / `todo` 者按 other 处理——todo 工具的参数里天然全是项词，若计作工则立册即全始、幽项永不可判。这是本层对同仓表的唯一收窄（只收本层审计面，不改共享表本身）；
- 其余 other 族不入账；
- **文本串**：`argsText(args)` = 递归收集 args 里全部字符串值（数组入列、对象取值），以空格连接（baihe 同款，不经 JSON 序列化）。

## §4 事册（register）

```json
{
  "version": 1,
  "items": [
    { "id": "T1", "name": "重复扣款修复", "aliases": ["dedupe"],
      "terminal": ["test dedupe"], "abandon": ["放弃扣款"] }
  ],
  "order": [["T1", "T2"]]
}
```

- `items[].id` 必填且全册唯一；`name` 缺省时以 id 兼作项词与显示名；`aliases` 可缺省；**项词集 = [name, ...aliases]**；
- `terminal` 终形 / `abandon` 弃形：可缺省——未宣终形之项不得认终（无凭之终不认），未宣弃形之弃不入账（无声地不做了，账上是半途）；
- `order`：先后立序对 `[A, B]` 语义为「A 之终须先于 B 之始」；可缺省；引用不存在的 id → 坏册（exit 2）；
- **声明权全在任务方**：事册无默认表（立什么事、怎样算完、何时可弃，只有任务方知道）；
- CLI `--register` 缺省载入 `./.zhongshi.json`（存在时）；`audit` 无册可用 → **无册不判**（exit 2，治理边界：册外之事不审，攀缘归正念）；
- `enroll --item '<json>'` 按 id 并集去重、只增不删地写册（既有 id 原样保留，新 id 追加）。

## §5 词法与逐调用分类

- **词命中**：`argsText(call).toLowerCase().includes(word.toLowerCase())`——大小写归一的字面子串，零正则零 NLP；
- **判定序锁死**（同一调用对同一项多形命中取高者）：**弃形 > 终形 > 作工**——显式的言永远压过隐默的迹；
- 一调用可推进多项（`npm run full-regression` 同时命中多项的终形 = 并行结账，合法）；
- **失败调用（isError=true）亦是作工之迹**——试错也是始（宁纵方向：少记幽项，不错杀真开工的事）；孤儿（isError=null）照成功侧口径；
- 逐调用产出事件序列（每项独立）：`W`（作工）/ `T`（终言）/ `A`（弃言），seq = 全流调用序（1 起）。

## §6 程账与案别

程账 = 逐项的事件序列。**末笔定案别**（审计时刻逐项看最后一个显著事件）：

| 案别 | 判定 | 分 |
|------|------|-----|
| **幽项** | 全流无任何事件 | +30/项，cap 60——立了的事全流无迹，最确定的没做 |
| **半途** | 末笔为 W | +15/项，cap 30——开了头没走完，也无弃言 |
| **有终** | 末笔为 T | 0——始末俱在，账平 |
| **有弃** | 末笔为 A | 0（点名）——显式弃，合法（弃形可落在提交信息等任何流中词面） |

- **空终案**：每个「其后复有作工之 W 的 T」各计一案（+20/案，cap 40）——终言被自己的手推翻，罪加一等（高于半途）：它还制造了一个误导下游的假「已完成」时刻。末态不影响空终计数（末态 W 的项同时背半途案与历史空终案）；
- **复活**：A 之后复有 W/T → 该 A 自然作废（末笔不再是 A，案别随之）——弃了又做不算弃；
- **未宣终形之项**：T 永不可能发生，至多记「行」（半途），程账块点名「未宣终形」——逼的不是 agent，是册方把「怎样算完」说出口。

## §7 先后账（知所先后）

- order 对 `[A, B]`：**失序案** ⟺ B 的首个 W 之 seq **早于** A 的首个 T 之 seq（两者皆存在）；
- **A 无终不判**（宁纵）：A 的事没走到终，它自己的幽项/半途已在案，不令 B 代 A 受罚——失序只判「两步都走完了却走反了」的硬证据；
- 一对至多一案（+10/处，cap 30）；多对逐对计。

## §8 程值与分带

```
幽项分 = min(60, 30 × 幽项数)
半途分 = min(30, 15 × 半途数)
空终分 = min(40, 20 × 空终案数)
失序分 = min(30, 10 × 失序处数)
程值 total = min(100, 幽项分 + 半途分 + 空终分 + 失序分)
分带：近道(0–14) / 鲜终(15–29) / 无终(≥30)   ——靡不有初，鲜克有终
门禁：默认 30，--gate 可覆盖；total ≥ gate → fail（退出码 1）
```

- **单幽项即红**（30 = 无终）：全流无迹是唯一不可能冤枉的罪名；单半途 15、单空终 20 皆过门——中道而废与终而复作常见于正常会话，记账不拦门；三条失序、两件半途亦足红；
- `liveScore`（在线）与离线重放对同流前缀逐字节一致：案别只依赖在先调用，天然满足。

## §9 程账块（接缝处供给，逐字节确定）

```
【终始 · 程账块 #k】
程值 T（带），门 gate，判 pass|fail
事账：立事 N 件；有终 a，有弃 d，半途 h，幽项 y；空终 c，失序 s
逐事（按册序）：
  T1 重复扣款修复｜有终｜始#2 终#4
  T2 账单导出｜幽项｜全流无作工
  T3 边界用例｜半途｜始#5 末作#9
  T4 旧列清理｜有弃｜弃#12
空终点名（按案序）：
  T1 用户表迁移｜终#14 后复作于#16
（无）
失序点名（按册序）：
  立序 T3→T4：T4 始#6 早于 T3 终#7
（无）
—— 本块由确定性规则生成；重放同一流必得同一文本。
```

- 无时间戳字段；逐事序 = 册序；案序 = calls 序；同一（册, 引擎态）两次渲染逐字节相同，#k 随渲染递增且仅此一处不同（shasum 可证）；
- 项的显示名 = name（缺省 id）；「未宣终形」之项在行尾点名；
- 块的用途即**续跑图**：新会话读此一表，知每事到哪——交接班记录从素养变成机制。

## §10 插件（Cordis，结构性零拦截）

- `ZhongshiService extends Service`，`inject: ['tools']`；`ctx.on('tools/result', …)` 为**唯一写入口** `step(engine, call)`（闭包交付引擎，同前层）；
- 观察异常一律吞掉（结构性：任何监听器内 throw 不冒泡，管道照常）；
- 配置：`{ gate?, items?, order? }`（事册随插件配置注入，与文件册同一形状）；
- 服务面：`report()`（立事数/案数/程值/带/门）、`chengzhang()`（逐事清单）、`chengkuai()`（程账块，#k 递增）、`gate()`、`exportStream()`（call/result 成对导出，与离线 `audit` 账实对账）；
- **源码无 pre-execute 监听器**——拦动作是 zhizhi 的地盘；本层只记账、供图、裁门。

## §11 CLI（零依赖，契约无关、可验尸任何历史会话）

```
zhongshi audit  <stream.jsonl>… [选项]   逐项审计（程值 + 分带 + 门禁；多流按参序拼接）
zhongshi ledger <stream.jsonl>… [选项]   逐事清单（案别/始末序号/空终/失序）
zhongshi kuai   <stream.jsonl>… [选项]   程账块（续跑图；--json 包装）
zhongshi gate   --value <n> [--gate n]   门禁裁决
zhongshi list   [选项]                   出册（items ∪ order 视图）
zhongshi enroll --item '<json>' [选项]   立事（按 id 并集去重，只增不删）
zhongshi --help | --version
选项：--gate <n>  --register <path>（缺省 ./.zhongshi.json，存在即载；audit 无册 → exit 2）
      --item '<json>'  --json  --value
退出码：0 通过；1 门禁失败；2 用法/输入错误（坏流/坏册/无册/未知命令/缺参数）
```
