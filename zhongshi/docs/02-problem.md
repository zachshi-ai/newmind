# 02 · 问题定义：谁、在什么场景下、有什么问题、价值何在

按「伪需求检验」的顺序写：先给场景和反事实，再给价值，最后自检。

## 目标用户

在 DeepSeek Harness（或任何 Cordis 架构的 Agent 运行时）上**委派多事项长任务**的工程师与团队，以及给 Agent 会话设 CI 门禁、需要中断续跑交接的平台方。他们已装齐十五层治理（zhizhi 拦动作、jiebi 审判断、zhengnian 守本愿、weibing 体检开工、jiubian 勘应变、youya 守记忆、lunshi 审输入、dingfen 封写域、baihe 守出境、zhibi 保记录、yuli 审退路、duzhi 量总量、erbing 审权柄，及在途的 buer 记教训 / licheng 追承诺 / fayi 审量尺），但有一张账至今无人记：**任务书里立的那几件事，各自走到哪了**。todo 列表是自愿式的，收工报告是自我叙事式的——「第 3 件事做完了吗、第 7 件事开过工吗」，在任何一层都无处问起。

## 四个场景

### 场景 1 · 静默漏项（幽项——立了的事全流无迹）

迁移任务书列了 12 件事：迁用户表、迁订单、清旧列、补索引、改文档、跑回归……Agent 埋头做了 7 件，第 200 轮收工报告整洁：「迁移完成」。剩下 5 件事在两万行 transcript 里**一次都没被碰过**——没有一条调用、一个路径、一段命令与它们相关。zhengnian 的终验对的是本愿的一纸凭据，不逐项点名；zhizhi 式的证据核对数的是「有没有证据」，不是「每件事各自的证据」；人想发现，只能对照任务书通读全流。**漏项不是漂移**（它一直在干本愿内的事）、**不是判断失真**（每个局部判断都对）——它是有初无终：事立了，账没记，事就静默地不存在了。

**反事实**：事册立事后，审计引擎在收工时刻确定性报出：5 项幽项（全流无作工之迹），程值 60 封顶，门禁红灯。漏项从「没人记得」变成「账上见」。

### 场景 2 · 半途而废（半途——末笔停在作工上）

补边界用例的事开过工：grep 过、建过 spec 文件、改到一半转去修别的事，之后再没回来。收工报告只字不提——不提「做完了」（它没做完），也不提「没做完」（没人问）。列清单的工具不会追问，承诺账本只追它自己说出口的话（这句它没说过）。**开工了没走完的事，在所有账上都隐了形**。

**反事实**：程账逐项看末笔——末笔是作工而非终形/弃形，即半途案，点名「始 #5 末作 #9」。半途从「无人知晓」变成「一行可查」。

### 场景 3 · 空终伪毕（终言被自己的手推翻）

第 20 轮 Agent 宣布「用户表迁移完成」，第 23 轮它又在 `--verify-only` 模式下跑迁移脚本改迁移代码。终言之后继以作工——那份「完成」被它自己的手推翻了，而流序里这明明白白，只是从未有机制把「终言之序」与「作工之序」比对过。这不是伪造证据（证据是真的：它真跑过那个终验命令），是**对终的自欺**：说完终就翻篇，手却诚实地停不下来。

**反事实**：空终案=「其后复有作工之终言」，逐案计分、罪加一等（20/案高于半途的 15/案）——因为空终不只是没做完，还制造了一个假的「已完成」时刻，误导所有下游（人审、CI、后续会话）。

### 场景 4 · 中断失图（续跑无图——每件事到哪了）

41 轮的会话被掐断（上下文爆了/机器重启/人主动喊停）。新会话接手，第一问：「每件事到哪了？」——没有一张图。通读旧 transcript 重构现场，或者更常见：重做已完成的事（浪费）、跳过半途的事（漏项）、对完成的事再收一次尾（空终）。续跑是 Agent 工程的一等场景，而交接班记录这个概念在运行时里不存在。

**反事实**：程账块是**逐字节确定的续跑图**：逐事一行（幽项/半途/有终/有弃 + 始末序号），新会话挂上同一事册、跑 `zhongshi kuai part1.jsonl part2.jsonl`，跨会话的行程一目了然（T1 始#1 终#4——上一班开的头，这一班收的尾）。

## 价值论证

1. **众事第一次有了行程账**：现有十五层的对象分别是动作、判断、本愿、任务书形状、错误教训、环境变化、承诺话语、见闻重复、输入权威、写域权界、出境之物、记录保真、行前退路、总量花销、人机权柄——全部不问「立了的事各自走到哪」。幽项/半途/空终三个罪名第一次有了确定性定义。
2. **续跑图第一次成为确定性供给物**：程账块（同一事册+同一流 → 逐字节相同，shasum 可证）让中断恢复从「通读 transcript 重构现场」变成「读一张表」。交接班记录从素养变成机制。
3. **插件层的第十六种能力类型**：zhizhi 证明插件可以拦，jiebi 审、zhengnian 供给、buer 记习、weibing 只出诊、jiubian 勘流、youya 巡忆、lunshi 守权界、dingfen 封界、baihe 守境、zhibi 秉笔、yuli 行前定、duzhi 计账、erbing 审柄、fayi 持尺——终始证明插件可以**记程**：立册、行程、结账、供图，结构性零拦截（无 pre-execute 监听器）。
4. **零 Agent 产物**：事册由任务方开工前登记（enroll 一次），此后全是对原始动作流的确定性测量——度量的对象不经过 Agent 的笔，与 zhengnian 的「零 Agent 产物」同旨；对历史流补册重放即见幽项（**追认合法**，duzhi 同款）。
5. **可证伪的价值主张**：对团队自己的历史会话跑 `zhongshi audit`，数一数多少幽项、多少半途、多少空终——每一项都能对回任务书里的一行字与 transcript 里的一片空白。价值自证，不靠叙事。

## 伪需求自检清单

| 质疑 | 回应 |
|------|------|
| "todo 列表 / 任务管理工具不就够了吗？" | 它们是**自愿式**的：依赖 Agent 自觉维护，恰好在最该核销的时候最先被丢弃（zhengnian 同款论证）；且没有门禁、没有分数、没有对流的账——todo 打勾可以作假，勾了没人验。终始的四件套——事册（形状）、程账（流账）、程值（数字）、程账块（续跑图）——把清单从好习惯变成可审计的机制。还有一个机制性理由：todo 类工具的参数里天然全是项词，若计作工则立册即全始、幽项永不可判——终始把 todo 族显式排除出作工面（docs/03 §3），这是 todo 工具自己做不到的自省。 |
| "zhengnian 的本愿契约和 anchors 不是覆盖了吗？" | 对象不同：本愿是**一个**（愿望的锚，守在场），任务是**众**（分项的账，记行程）。anchors 回答「离愿多远」，程账回答「每事到哪」。Agent 可以毫无漂移而漏掉三件分内事（anchors 全程命中、终验一纸凭据也在——漏项两层全绿），也可以逐件做完而早已攀缘出界。一愿与众事，两层各管一张账。 |
| "licheng 的绳账不是追『说到做到』吗？" | 时态与主体都不同：绳账追 **Agent 自己说出口的**未来承诺（话语负债）；终始记**任务方事册里立下的**事（主命分工）。任务书里的第 7 件事 Agent 从没承诺过——立诚看不见它，终始照记它的幽与半。 |
| "weibing 不是体检任务书吗？" | t=0 与 t>0：治未病看条款**写没写**（终验条款、止法条款的形状），终始看众事**走没走到**（写了白写，只有对账能见——duzhi 对 weibing 的同款论证）。体检报告不能代替行程账。 |
| "jiebi 的账实对账不查宣称吗？" | jiebi 审**判断产物**的账本协议（宣称的证据是否真实发生）；终始审**事之行止**（立了的事有无始终）。jiebi 的一切以判断账本存在为前提；幽项恰恰连宣称都没有——它静默到任何以「宣称」为对象的层都看不见。 |
| "词法匹配太粗，能骗吗？" | 能——诚实边界写死（docs/01 第五节）：伪始伪终的痕迹全在账上，骗一次留一次形；确定性词法的保证是可审计可重放可门禁，不是不可欺（zhengnian/erbing 同款分离承诺）。项词由任务方声明，声明权在册方。 |
| "12 件事谁登记？成本多高？" | `zhongshi enroll --item '<json>'` 一次一条，或直接写 `.zhongshi.json`——比写任务书本身便宜一个量级（任务书都写了，册是任务书的机器可读版）。**追认合法**：对历史流补册重放即见当年的幽项半途——线可以后补，越线是硬数字。 |
| "会不会误报，把好会话门禁红灯？" | 判定序宁纵：失败调用也算作工之迹（试错也是始）、未宣终形只点名不造冤、册外之事不审、A 无终不判 B 的失序（不让 B 代 A 受罚）。单半途 15 分不过门（门 30），单空终 20 分不过门——**只有幽项单案即红**（30），因为全流无迹是最不会冤枉的那一种：没有比「一次都没碰过」更确定的没做。 |
| "凭什么说是真实问题？" | todo/清单/燃尽图工具在人类组织与 Agent 产品两界的普及本身就是病的存在证明（需要工具管的事，正是没人管就丢的事）；「agent 说做完了但有 X 没做」是 agent 用户 issue 区的高频抱怨；WBS/DoD/清单革命是人类组织对同一病的制度回应——Agent 世界至今没有机器化的逐项核销层。 |
