# 定分 · 多会话并发写作协议

**一兔走，百人逐之，由名分之未定也；分已定，贪盗不取。** 并发会话的事故不是道德问题，是名分问题——用登记代替谦让，用对账代替记忆。

## 何时用

- 同一仓库/工作区同时有 ≥2 个 Agent 会话（多终端、swarm worker、CI bot 与人并行）；
- 编排器调度多个 worker 前需要划地盘；
- 出现"我的修改不见了 / 谁删了我的文件 / 两个会话改了同一个文件"之后要归因。

## 四步协议

### 1 · 开工领分（先于第一个写动作）

```bash
dingfen claim --id <会话名> --fence 'src/auth/**' --fence 'docs/auth-guide.md'
```

- 分界是**显式 glob**（字面段、段内 `*`、独占段的 `**`），声明你**要写**的径；只读不占分；
- 输出里有 `⚠ 争界` 告警时，说明别的会话已领了相交的分：**换径或先与对方协调**，不要硬闯（`--strict` 可让争界直接退出码 1）；
- 领分输出尾部就是界碑块——看一眼"在册开放之分"，知道哪里是别人的地、哪里是自由地。

### 2 · 写前看碑（接缝处供给）

```bash
dingfen block
```

任何"我要开始写一个不熟的径"的时刻，先看碑。界碑块逐字节确定，可安全注入上下文。

### 3 · 收工审争（完成声明之前）

```bash
dingfen audit <会话A的流.jsonl> <会话B的流.jsonl> --file .dingfen.json
```

- exit 0（带「定」/「竞」且低于门）才许宣布完成；exit 1 时按判词处置：
  - **争写**：交错覆盖已发生——与对方当面对账，恢复被覆盖一侧的工作；
  - **侵入**：你写进了别人的开放之分——撤销或征得对方同意后**改诺登记**；
  - **越分**：漂出了自己声明的分界——把多写的部分交还或补领分。
- **共写不计分**：先后接手是协作的常态，不是罪。

### 4 · 收工销分

```bash
dingfen release --id <会话名>
```

不销分，你的分就一直拦着别人的争界告警——地要还，账要平。

## 纪律与诚实边界

- **宁可换径，不可闯分**：分册告警是结构性的，绕过告警 = 自愿承担争写后果；
- **没领分不丢人**：纯只读会话无需领分；但只要会写，先领分；
- **命令是黑盒**：`bash` 里间接改的文件定分看不见（只判显式路径对象）——别用 shell 绕过自己的分界，那是对账上的自欺；
- **无时不成案**：审计依赖流里的时间戳；给你的会话流保留 `at` 字段，归因才有先后。

## 快查

| 场景 | 命令 |
|---|---|
| 开工 | `dingfen claim --id me --fence 'src/x/**'` |
| 写前 | `dingfen block` |
| 收工 | `dingfen audit a.jsonl b.jsonl --file .dingfen.json` |
| 离场 | `dingfen release --id me` |
| 归因 | `dingfen audit --json` 逐条看 `strifeSpots / trespassEntries / strayEntries` |
