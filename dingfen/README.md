# 定分 · Dingfen

> **一兔走，百人逐之，非以兔为可分以为百，由名之未定也。夫卖兔者满市，而盗不敢取，由名分已定也。**——《商君书·定分第二十六》

一门两千三百年的法家制度设计，能不能精确地解决人工智能的一个真实问题？

能。2026 年的 Agent 不再单打独斗：同一台机器上几个终端、swarm 编排下的并行 worker、CI bot 与人并行——而工作区只有一份。于是有了第十种昂贵的失败：**两只手改同一个文件，谁都没看见对方的手**。交错覆盖让工作无声丢失（争写）、闯进别人正在写的地盘（侵入）、漂出自己声明的边界（越分）；事后两个会话都报告成功，谁在何时覆盖了谁，连问都无处问起。定分把这三种失败变成**可登记、可测量、可门禁、可重放**的结构事实——名分未定，尧舜且逐；名分已定，贪盗不取。

## 它是什么

DeepSeek Harness 的**封界式插件**（Cordis）+ 零依赖审计 CLI + Agent Skill。

## 核心概念

- **分册**（`.dingfen.json`）：机器可读的地契——每个会话开工**领分**（显式 glob 声明写域），收工**销分**；开放时段 `[at, releasedAt)`；
- **三宗**：**争写**（两session交错写同一径，lost update 窗口）、**侵入**（落入他方开放之分）、**越分**（漂出自家分界）；先后接手是**共写**，合法不计分；
- **争值**（0–100）＝ 争写（+30/处，cap 60）＋ 侵入（+30/会话×径，cap 60）＋ 越分（+6/会话×径，cap 30）；分带 **定 0–14 / 竞 15–29 / 争 ≥30**，门默认 30——**单处争写或单径侵入即红**，有受害者的一票即红；
- **界碑块**：接缝处逐字节确定地供给分册公示（谁领了什么、争界几处、每处附**见证径**），注入与否由宿主决定；
- **审争**：多流离线重放——每个流文件是一个会话，合入同一引擎出统一判词，重放同一批流必得同一判词（置吏不收贿）。

## 快速开始

```bash
cd dingfen
npm install          # 仅集成测试需要官方 @deepseek-ai/* 包（devDependencies）
npm test             # 77 tests, 77 pass

# 开工领分（登记写域；争界告警自带见证径）
dingfen claim --id session-a --fence 'src/auth/**'

# 写前看碑（分册公示，逐字节确定）
dingfen block

# 收工审争（多流合审，退出码可进 CI / 编排器）
dingfen audit session-a.jsonl session-b.jsonl --file .dingfen.json

# 收工销分
dingfen release --id session-a
```

## 为什么可信

- **模型无关（model-free）**：零 LLM 调用、零提示词注入、零网络、零子进程、可逐字重放；
- **结构性零拦截**：插件源码里不存在 pre-execute 监听器——界碑公示 + 事后对账足以自治（名分定，民皆愿悫，各自治也）；
- **见证自证**：每处争界告警附一条同时命中两界的具体路径，交运算的输出必须真实通过双方匹配器——告警自带可复现证据；
- **账实对账**：双引擎 `exportStream()` 合并离线 `audit`，侵入/越分/争写与运行时账逐字一致（集成测试实证 72 = 6 + 36 + 30）。

## 诚实边界

1. 没人领分，定分不判越分（未领分只提示，不计分）——声明权在账方；
2. 侵入/越分只判显式 `p:` 路径对象，`bash` 里的写是 `c:` 黑盒，不判——宁可放过，不可错罚；
3. 争写需要全链时间戳，无时之流退出交错判定——无时不成案；
4. 单会话的运行时视图里争写恒为 0（那是流间事实）——每只手只看得见自己，所以需要置吏。
