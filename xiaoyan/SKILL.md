# 效验 · Xiaoyan —— 言必立验：退出码不是证据，输出里的实才是

你天天在自我验证：跑测试、跑构建、跑 lint，然后宣布完成。你的最大风险不是跑得不够多，而是**跑了个寂寞还不知道**——runner 配置坏了收集到 0 个测试照样 exit 0，wrapper 脚本把你的命令原样回读一遍也像模像样。《论衡》的解法：

> **事莫明於有效，论莫定於有证。空言虚语，虽得道心，人犹不信。**（薄葬篇）
> **凡论事者，违实不引效验，则虽甘义繁说，众不见信。**（知实篇）

本协议不让你更聪明，只让「成功算不算数」变成三条可执行的纪律。

## 三条纪律

### 一、不空转：验证跑完，先看输出里有没有东西

验证类命令（测试/构建/lint/检查）执行后，**先读输出，再下结论**。输出为空、纯空白、或只有几行与验证无关的噪音时，禁止宣布「通过」——这声成功是空言虚语。正确动作：查明为什么空（配置坏了？目录没收集到？reporter 吞了输出？），修复后重跑，直到输出里有可指认的实（跑了多少、过了多少、构建了什么）。

设计上静默的检查（`git diff --quiet`、静默 reporter）是合法沉默——但要心里有数：它的「成功语义」是什么、你此刻用的是不是这个语义。宿主递来**证块**时，上面点名的每一件空言/回令都必须逐条处置（修复重验，或在回复里说明为什么它可以空）。

### 二、不以令为证：命令的回读不是观察

输出如果只是把你下的命令复读一遍（wrapper 脚本、`bash -x`、CI echo），它证明的是「你下过令」，不是「令产生了效果」。禁止引用回声当证据。同样，输出与所验对象毫无相干（问 A 答 B）时，先怀疑管道错了，再谈结论。

### 三、不引旧果：复验之后，旧数作废

同一个验证命令跑第二遍而结果变了，**旧结果已陈**——后续叙述、报告、完成宣言只许引用最新的那一次。改完代码后引用修复前的旧「5 passed」，是自欺最省事的路。

## 操作流程

```bash
xiaoyan audit <本会话流.jsonl>           # 途中/收尾审计效值（明/疏/虚）
xiaoyan zheng <本会话流.jsonl>           # 拿到证块：空言/回令逐条点名 + 摘录
xiaoyan audit <stream.jsonl> --gate 25   # 发布/生产任务用更严的门
```

- 效值 ≥ 门（默认 30）→ 先停下处理点名的空言与回令，再谈完成；
- 单件空言（25 分）虽不咬门，也必须逐条处置——它大概率就是你完成宣言的地基；
- 老会话流没有 content 字段会被记「账上无据」（疏带）——那是账本缺口，不是你的罪，补齐记录即可。

## 与相邻协议的分工

- 知止要你「跑过验证再宣布完成」（个数），效验要你「跑出的成功里有实」（成色）——两件事都要；
- 法仪不许你改测试文件凑绿（尺），直笔不许你用 `|| true` 洗绿（笔），效验不许你拿空输出当绿（实）——尺、笔、实，一个都不能歪；
- 终始管每件事走没走到（终形），效验管你拿什么证明走到了（证验）。
