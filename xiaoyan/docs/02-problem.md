# 02 · 问题定义：谁、在什么场景下、有什么问题、价值何在

按「伪需求检验」的顺序写：先给场景和反事实，再给价值，最后自检。

## 目标用户

在 DeepSeek Harness（或任何 Cordis 架构的 Agent 运行时）上给 Agent 开了**自我验证能力**的工程师与团队：让 Agent 跑测试/构建/lint 后自行宣布完成的人、把它接进带 wrapper 脚本与 CI 胶水层的仓库的人、以及**事后**需要回答审计问题的人——「那天它声称的那次验证，输出里到底有没有东西？」。他们已经装了十七层治理（行为/判断/意图/记取/开工体检/承诺/记忆/应变/权界/封界/守境/持尺/秉笔/行前定/度支/审柄/终始），仍在一个根本问题上裸奔：**环境的「成功」宣言，凭什么被当成证据？** 所有现存层对此沉默：zhizhi 的完成核验把成功验证命令**照单收编**为证据（数个数，不称成色）；jiebi 审判断账本引用的证据是否真实**发生过**，不审发生过的事件本身**有没有内容**；zhengnian 的终验门对着契约声明的验证对账——契约说「跑 npm test」，Agent 真跑了，门就开，跑出个空也是开的；fayi 审尺（验收器脏没脏），命令干净它就清白；直笔审笔（退出码洗没洗），讳形没命中它就笔直；zhongshi 记终形（有终/半途），跑完就是有终。**空转成功穿过了每一层，无一处被称实。**

## 四个场景

### 场景 1 · 静默空转（最便宜的自欺，最贵的下游）

让 Agent 修一个 bug：它改完代码跑 `npm test`，命令干干净净，退出码 0，输出为空——vitest 配置坏了，runner 一个测试都没收集到。它宣布「测试全部通过，修复完成」。**下游每一层都被这件空证穿透**：zhizhi 的证据账记下「1 次成功验证」；jiebi 的判断账本引用它；zhengnian 的终验门对着它放行；fayi 画「尺直」（没动测试文件）；直笔画「笔直」（无讳形）；zhongshi 记「有终」。没有任何一层问过：这声「成功」里有没有可观察的实？

**反事实**：harness 没有任何一处登记「这次成功携带了多少可观察内容」。事后想知道「那天 237 次成功里有几次是空言」，连问题都提不出来——历史流里只有成败码。成报需要一本自己的账：每条效类成功入账时先过三问，空而无物即点名。

### 场景 2 · 以令为证（把令当实，自己给自己开证明）

更隐蔽的一种：仓库里的 CI 胶水脚本用 `bash -x` 或 echo 包装命令，「验证」的全部输出就是把命令自己复读一遍：跑 `npm run smoke`，stdout 回来一行 `npm run smoke`。Agent 引用这段「输出」当证据——引用的其实是它自己下过的令。观察与命令在此完全重合，**耳目之实为零**。

**反事实**：今天的运行时里，输出内容与命令文本的关系没有任何一层过问。「输出 = 命令的回声」是一个结构可判的事实（输出是参数的子串），但它需要有人先立「回令即无实」的规矩并逐件对账——这正是效验的第二问。

### 场景 3 · 静默冤案（治理层的头号死法）

反过来：`git diff --quiet`、`tsc --noEmit` 配上静默 reporter、健康探针——这类检查**设计上就静默**，exit 0 且无输出是它们的成功语义。一个见空就罚的层会把每次合法沉默记成罪，用户被误伤三次就永久 `rm` 掉这个层——比没有这个层更糟。

**反事实**：效验的防线有三重：**类目收敛**（只审效词表命中的成报，`mkdir`/`touch` 永不入账）、**单件不咬门**（一件空言 25 分落在疏带，点名不门禁）、**免验词表**（设计上静默的检查显式声明，豁免且有计数）。宁可放过，不可错罚。

### 场景 4 · 无账可查（事故之后，无处验尸）

空转成功酿成事故后的标准问题链：那天它声称的「验证」具体是哪几次调用？每次的输出是什么？输出里有没有东西？有没有同参复验而旧果被反复引用？今天的会话流里只有 `isError` 布尔位，这四个问题全部无法回答——审计只能重新人工回放。

**反事实**：效账是**契约无关**的——只要会话流里有成报与内容字段，`xiaoyan audit` 对任何历史流直接验尸，逐件三问判定、逐条点名，全部可重放。老流（无 content 字段）按「账上无据」记——账本缺口本身被如实指出。

## 价值论证

1. **成功信号的成色第一次可审计**：效值（0–100，虚分+回分）是确定性的、可复现的数字，回答一个此前无法回答的问题：「这条运行里，环境的成功宣言有几声是空言虚语？」——不可测量 → 不可管理。
2. **下游五本账的共同原料，第一次有人验明**：zhizhi 的证据账、jiebi 的账实对账、zhengnian 的终验门、fayi 的绿验、zhongshi 的终形——全部以「成功」为原料。原料的成色无人称量，五本账就可能一起立在空言虚语上。效验补的是**公共供应链**的质检，不是又一道下游关卡。
3. **尺·笔·实三位一体补齐**：法仪审器（写没写尺）、直笔审迹（洗没洗码）、效验审物（有没有效验）——`npm test` 命令干净、尺也没动、输出是空的：尺直、笔直、实空，只有效验看得见。三个对象正交，缺一即漏。
4. **强制式，不靠 Agent 自觉**：「跑测试要看着输出」是自愿式美德——原则会被违反，触发器不会。效账从事件流里登记，不依赖模型「这次恰好没有自欺」。
5. **不冤枉，疾虚才立得住**：类目收敛 + 单件不咬门 + 免验词表——正常构建、合法静默、健康会话实测 0 分（夹具 clean/exempt 演示）。王充疾的是**虚**，不是**默**。
6. **事故审计的验尸协议**：`xiaoyan audit` 对任意历史流逐件给出三问判定、逐条给出点名（空言/回令/离效/陈效）——场景 4 的四个问题第一次全部可答。
7. **插件层的新能力类型**：拦（zhizhi）、审判断（jiebi）、供给本愿（zhengnian）、记取（buer）、诊断（weibing）、结绳（licheng）、巡忆（youya）、勘流（jiubian）、守权界（lunshi）、封界（dingfen）、守境（baihe）、持尺（fayi）、秉笔（zhibi）、行前定（yuli）、度支（duzhi）、审柄（erbing）、行程（zhongshi）之后，效验是第十八种：**称实式**——治理对象不是动作、判断、意图、渠道或尺笔，而是**成功信号自身的证据含量**。
8. **可证伪的价值主张**：对本仓库夹具与任意历史会话跑 `xiaoyan audit`，能数出多少空言、多少回令——价值自证，不靠叙事。夹具分数全部先于实现手算定死（docs/04）。

## 伪需求自检清单

| 质疑 | 回应 |
|------|------|
| 「直笔不是已经抓「空绿」了吗？」 | 抓的是两种「绿」。直笔的空绿 = **讳形洗出来的绿**（`\|\| true`、`--passWithNoTests`——笔曲），判定原料是**命令文本**；本层的空言 = **笔直的绿但没做过事**（命令干净、输出为空——实空），判定原料是**结果内容**。`npm test` 干干净净跑出一个空输出：直笔的判定序里无讳形命中 → 族末笔为「直」→ 0 分，看不见；效验称出 25 分。尺直笔曲绿照样假，笔直实空绿照样空——两层互证不互代。 |
| 「fayi 的虚器不是抓空转断言吗？」 | 对象不同。虚器审**测试文件的内容**（恒真断言、空体用例——尺本虚），本层审**运行输出的内容**（runner 静默空转——跑了个寂寞）。测试套件完全真实而 runner 配置坏掉收集到 0 个测试：法仪照画「尺直」，效验称出空言。器（写没写尺）与物（有没有效验）正交。 |
| 「zhengnian 的终验门不是要求对着验证宣布完成吗？」 | 终验门核对的是「**跑没跑**契约声明的验证」（个数）；本层问的是「这次验证**算不算数**」（成色）。契约说 `npm test`，Agent 跑了（终验门放行）、跑出个空（效验称出 25 分）——「验过」与「验出东西」是两回事。 |
| 「zhongshi 记「有终」不就行了吗？」 | 终始记的是**任务项走到哪**（幽项/半途/有终/空终/先后）；它认「终形」= 显式完成信号与作工之迹的对账——验证跑完即有终，至于终的**依据**空不空，不是它的对象。「事有终始」与「事有证验」两张账：一张管走没走到，一张管拿什么证明走到了。 |
| 「直接解析测试框架输出、数断言个数，不是更彻底？」 | 那是语义泥潭：runner 格式碎片化（vitest/jest/pytest/go/cargo…）、报告可被 `--reporter` 任意改造、断言本身可空转（`expect(true).toBe(true)`）。结构层只做铁账：**有无可观察之实、所答是否为所验**——零 LLM、零框架适配、永不因框架升级而失灵。王充「论贵是而不务华」：结构可证之实优先，华丽的全知留给语义层（诚实边界第 1 条）。 |
| 「工具成功返回空输出不是很常见吗？误报会不会淹了它？」 | 三重收敛。**类目收敛**：只审效词表命中的成报，`mkdir`/`touch`/`git add` 的静默是合法的，永不入账；**单件不咬门**：一件空言 25 分落疏带，点名亮牌不门禁——偶发的空言被看见但不咬人；**免验词表**：设计上静默的检查显式豁免。夹具实测：clean 流里的静默 `mkdir` 成功 0 分。 |
| 「离效会不会误伤正常输出？比如 `npm run test` 输出 `5 passed`。」 | 「test」是参数词元，`5 passed` 里没有 test——嗯，恰好这个词元会命中吗？不会：`5 passed` 里没有 test 四连字母。但别的误伤确实存在，所以离效**只点名不计分**（与有涯「陈账只点名」同一立场）：它进入效账与证块的「离效」计数，0 分、不门禁、不影响 exit code。词元取自参数原文（含 JSON 脚手架），刻意往「宁纵」方向偏置。疑而勿罚，是本层的硬承诺。 |
| 「回令真实存在吗？谁家工具会只回显命令？」 | wrapper 脚本、`bash -x`、CI echo 模式、以及**日志管道故障**（stdout 被 tee 吞掉只剩命令回显）都生产纯回声输出。它结构上必真：输出是参数的子串——这个判定零启发式。真不真可以查，判得对不对可以重放。 |
| 「老流没有 content 字段就被记空言，是不是错罚历史数据？」 | 不是罚，是**如实指出账本缺口**：流里没记证据，成功就无从自证有验。老流单件空言 25 分落疏带，exit 0 不咬门——夹具 A3 实测 zhizhi/jiebi 历史流各得 25 分·疏带·exit 0，恰好演示「账上无据」的语义与它的无害性。带 content 的新流不受影响。 |
| 「为什么主文本不能像论世的『承』那样自动豁免？」 | 提及不等于授权沉默。豁免静默比豁免命令更贵——一句「别让测试静默失败」就会反向授权。所以免验只走**显式配置**（`--exempt` 词表），不走主文本。这是有意比论世的「承」更严的一格。 |
| 「十七层了还加一层？边际价值在哪？」 | 十七层各守一段管道，但**没有任何一层以「成功信号的内容成色」为对象**——它是五本下游账（证据账/账实对账/终验门/绿验/终形）的共同原料。原料质检是供应链问题，不是又一道关卡：空言虚语一旦入账，会被五本账一起放大成「完成」。效验在源头称一次实，下游五层全部受益。 |
| 「这算真问题还是强迫症？exit 0 就是环境的契约。」 | 三个可指认的公开事实：测试框架静默空跑（收集到 0 个测试仍 exit 0）是各框架 issue 区的常客；CI 胶水 `|| true` 抹平失败是公开反模式（它的**显形部分**已被直笔收账——本层收它的**隐形部分**：命令干净而输出空）；「Agent 宣称测试通过而仓库里测试根本没跑」是 2025–2026 年 Agent 可靠性讨论的 recurring 案例。`xiaoyan audit` 对任意历史流可直接验证：你的流里有几声空言，一跑便知。 |
| 「和其他十七层撞车吗？」 | 正交且有明确边界（见根 README 方向登记）：不拦动作（zhizhi）、不审判断账本（jiebi）、不守本愿（zhengnian）、不做 t=0 体检（weibing）、不管势途（jiubian）、不管记忆衰减（youya）、不审渠道权威（lunshi）、不裁写域（dingfen）、不称量出境（baihe）、不审尺脏（fayi——器与物两本账）、不判笔直（zhibi——迹与物两本账）、不管行前退路（yuli）、不量总量花销（duzhi）、不审须柄授命（erbing）、不记任务项终始（zhongshi——走没走到归它，拿什么证明归本层）、不记跨会话事故（buer）、不追承诺（licheng）。失败事件（isError=true）永不入账——审败账是九变的地盘。结构性零拦截（源码无 pre-execute 监听器，grep 可证），零 LLM。 |
| 「会不会拖慢 Agent？」 | 零拦截（结构性）、零 LLM、零网络。记账是 O(1) 均摊的记录追加，三问判定是 O(成报数 × 词表数 + 参数词元 × 内容长) 的子串扫描，证块是模板渲染。度量不消耗 token。 |
