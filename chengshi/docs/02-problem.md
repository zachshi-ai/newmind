# 02 · 问题：Agent 外发重决（已遂之施的再施无账）

## 谁在什么场景下的什么问题

**谁**：把对外行使交给 agent 的工程师与运营——发布、值班、客服、巡检、代理购付——
以及接手收拾这些外发物（PR、评论、工单、邮件、订单）的下一个人、下一个会话。

**场景**：agent 被授权对外行使——建档（`gh pr create` / `gh issue create`）、
发声（`gh pr comment` / `mail -s`）、触发非幂等写入（`curl -d` POST 下单、注册 webhook）。
第一笔已经落地，但 agent 没看见成功：请求超时被 harness 记成失败、循环重扫了同一个队列、
断点续跑后重放了半途的计划、或者干脆「为保险再跑一遍」。第二笔照样落地——
第二个 PR、第二条一模一样的评论、第二封一模一样的邮件、第二笔扣款。

**问题**：已遂之施的**再施**无账，而且三问全部无处问起——
「哪件事做了两次？第二次何以又施？第一次的完成为什么不算数？」

- **双生之物即成事实**：第二条评论已经@了同一批人，第二封邮件已经进了对方的收件箱，
  第二笔 POST 已经在世界那头开了第二张单——它们不在 git diff 里（世界在仓库之外），
  也不在任何一层的账上；
- **第二笔往往同样「有授权」**：任务方授的是「把公告发出去」，不是「发一次」——
  授权层看不见重复，它只看见两次都有命；
- **事后归因无从下手**：是第一次其实失败了？是 agent 没读到输出？是循环重入？
  ——今天的会话流里没有任何一层把这些笔并成一案。

## 问题（治什么病）

四个病形，全部真实存在、全部有据可查：

| 病形 | 流内词面 | 现实对应 |
|------|----------|----------|
| **重告** | 同一 `gh pr create`/`gh issue create`/`gh … comment` 规整命令串成功两笔，其间无凭消、无再命 | 建档双生：循环重扫、断点续跑、排队任务重放——重复 PR/issue/评论是自动化 agent 最常见的扰民事故 |
| **重邮** | 同一 `mail`/`mailx`/`sendmail`/`mutt`/`msmtp` 规整命令串成功两笔 | 双发：值班 agent 对同一事件重复通报，收件人从第二封起开始忽略它——警报疲劳由机器亲手制造 |
| **重单** | 同一 `curl`/`wget`/`http` 携写入方法（`-d`/`--data`/`-F`/`-X POST`）的规整命令串成功两笔 | 非幂等 POST 双生：双下单、双扣款、双注册——幂等键是支付与网关协议的行业标准，agent 流里却没有对应物 |
| **跨会话重决** | 两个会话流里各有一笔同串之施，合审并键 | 「把事故报告归个档」发给两个会话，各归一份——单流看都是初遂，合审才是重决 |

价值锚点：每一笔都真实落在世界上，第二笔是不可追回的既成事实；对账材料全在会话流里
（成功与否是 `isError` 位，施形是命令词面，凭证是 `result.content` 里的成物之柄），
词法可证。工具与协议侧，幂等键、乐观锁、去重窗口都是**世界那头**的防线，要求行使者
带着钥匙来；harness 层的**确定性已遂账**在公开方案里没有对应物——它不假装能判断
「这次重施是不是有意的」（语义判断是禁区），只把已遂与再施做成铁账：
**记账不禁行，账上有遂，再施有价**。

## 相邻层的空白地（为什么必须新开一层）

- **二柄**：一柄一遂。它审**行使之命**（须柄之事有没有先授之命）——两笔重施在它账上
  皆「有命」0 分；授权与重复是两个谓词，同一笔双跑可两账并记；
- **有涯**：一费一害。它审**复命**（同串执行 ∧ 其间全库无成功写——重复之**费**），
  两笔施之间夹一笔写它就哑（恰是循环 agent 的常态），而且它读作效率损失；
  本层审**重决**（已遂之**害**），写间不断罪——同一笔双跑可两账并记（渊鱼×有涯之例）；
- **捭阖**：一出一施。它审出境之**物**（密钥发往了哪个域），本层审已遂之**施**
  （同一笔行使做了几遍）——出境每次都带密才该它立案，不带密的重施它看不见；
- **定分**：一域一世。它裁**仓库写域**的跨会话归属（文件），外发行使落在本仓库之外，
  分册上没有它的地盘；
- **九变**：一败一成。它勘**失败后**的盲捶（重复的失败），本层审**成功后**的重决
  （重复的成功）——流序里成与败逐字可分，两账各记一半。

## 价值（为什么不是伪需求）

1. **每一笔都真实落在世界上**：双生之物不是「可能有害」的推断，是收件人已经看见的
   事实；重单病形的下游是真实的钱；
2. **意图可豁免而词面须留痕**：轮询心跳本来就该一遍一遍打——遂册 allow 明言即豁施；
   主渠道再命（「再发一遍」）即承施；两者之外的同串再施，不是罪，是**账**：
   留痕有价、点名有责、门禁有阈；
3. **记账不禁行**：不拦施（拦是 zhizhi 的地盘）、不碰工具、不跑语义分析——扫描全部
   发生在流内词面上，观察永不反噬；「成事不说」的反面是「成事要记」，记是本层的
   全部姿态；
4. **可证伪**：遂形词法、判定序、分数公式全部锁死于 03；同流重放必得同判词；
   跨项目历史流可验尸复算——错了改实现，不改标准。

## 产品形态

- **成事式插件**（DeepSeek Harness 插件层，Cordis，结构性零拦截）：挂 `tools/result`
  观察口，遂账入账，遂牌块接缝供给；
- **零依赖审计 CLI**（`chengshi`）：多流离线重放合审（跨会话重决可证），
  可验尸任何历史会话；
- **Agent Skill**：给派活方与 agent 的开册/再命协议。
