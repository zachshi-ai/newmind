# 03 · 设计：成事 · chengshi —— DeepSeek Harness 的已遂重施治理（成事式插件）

> 本文锁死全部判定语义；实现与本文冲突时改实现，不改本文与 04 的手算期望。

## 1. 能力类型与接缝

新能力类型：**成事式插件**（第三十三个）。zhizhi 证明插件可以拦，jiebi 证明可以审，
zhengnian 证明可以供给，erbing 证明可以审柄，youya 证明可以审费，dingfen 证明可以裁域——
成事证明插件可以**审已遂之施的再施**：哪件事做成了、做成了几次、第二次何以又施、
善后了没有。

```
tools/result   emit   观察施面入遂账（唯一写入口）
（无 pre-execute）     —— 零拦截是结构性的
principal（流事件）     线下审计判承施——运行时视图无主文，承不判（诚实降级）
```

设计约束（与全仓同规）：模型无关（零 LLM、零提示词注入、零网络、零子进程、零文件系统探测）；
观察永不反噬（监听器异常吞掉，管道照常）；遂册持久化归 CLI（allow/disallow），
插件只吃注入的 book 对象；单会话视图的案与值只采本会话，跨会话归并归离线合并审计。

## 2. 遂面与遂账（通道锁死）

对象键与工具族同全仓（object.js 同规：`p:` 文件 / `c:` 命令 / `n:` 不透明；
observe/write/exec/other 四族）。

流解析向后兼容地扩展一类非工具事件（erbing 已引入，本层沿用）：
`{"type":"principal","text":"…"}` 主渠道文本——只用于**承施**判定（§5.3），
`turn_start`/`turn_end`/`reanchor`/`appeal` 跳过。

**施主（deed head）**：段内首个非旗标、非 `KEY=VALUE` 环境前缀、非 `sudo`/`nohup`/
`command`/`nice` 包装词的词元，取 basename、小写化——只用于遂形匹配；
**遂键**（deed key）：整段规整（trim + 连续空白折叠为单空格），**保留原大小写**——
同串才并键（变参重施不入键，宁漏登记）。

**遂账（施面唯一）**：exec 族 `c:` 命令分段（`&&` `||` `;` `|`，引号不切——与全仓
segments 同规）→ 段施主与旗标命中遂形（§3）且该调用成功（`isError !== true`；
null 按已发生入账——老流宁记）→ 按遂键记一笔遂（载 seq、session、ref、
`result.content`——成物之柄的提取源）。

**观察不是施**：observe 族永不入账。**失败不遂**：`isError === true` 一律不入账
（试施不遂——超时但实际已落地的第一笔在流内只见失败，宁漏，§12 登记）。
write 族与 other 族永不入账。

## 3. 遂形（默认形表，三族 15 形）——无册照判

| 族 | # | 形名 | 词法（段施主 ∧ 段内词面） |
|----|---|------|--------------------------|
| **启族**（外建档） | 1 | gh 建档 | 施主 `gh` ∧ 词元序 `pr\|issue` + `create` |
| | 2 | gh 评论 | 施主 `gh` ∧ 词元序 `pr\|issue` + `comment` |
| | 3 | gh 发版 | 施主 `gh` ∧ 词元序 `release` + `create` |
| | 4 | gh 片 | 施主 `gh` ∧ 词元序 `gist` + `create` |
| | 5 | gh 标 | 施主 `gh` ∧ 词元序 `label` + `create` |
| | 6 | gh api 显 POST | 施主 `gh` ∧ `api` ∧ 旗标 `-X POST` ∨ `--method POST` |
| | 7 | gh api 默 POST | 施主 `gh` ∧ `api` ∧ 旗标 `-f` ∨ `--raw-field` ∨ `-F` ∨ `--input`（无显式方法旗标时——gh api 默 POST） |
| **邮族**（外发信） | 8–12 | 五基名 | 施主 ∈ `mail` `mailx` `sendmail` `mutt` `msmtp` |
| **单族**（非幂等写） | 13 | 显 POST | 施主 ∈ `curl` `wget` ∧ 旗标 `-X POST` ∨ `--request POST` |
| | 14 | 默 POST | 施主 ∈ `curl` `wget` ∧ 旗标 `-d` `--data` `--data-raw` `--data-binary` `--data-urlencode` `-F` `--form` 之一，且**无** `-X/--request`（有则以显式方法判——PUT/GET/DELETE 不入，PATCH 不入） |
| | 15 | httpie | 施主 ∈ `http` `https` ∧ 次词元恰为 `POST` |

- **为什么是这三族**：启族与邮族是**开类**（重施即双生，世界不设防——第二条评论
  次次都发得出去）；发布类（`npm publish` 同版硬错）与收敛类（`terraform apply`、
  PUT 语义）**自守或自愈，默认排除**（erbing delegated 双跑 publish 夹具喂本层
  必零案——排除即边界，§10）；
- **无册照判**：遂形开箱在岗，册只管 allow 豁免（§4），v1 不扩形。

## 4. 遂册（再施授权，声明权全在任务方）

```json
{ "version": 1, "allow": ["curl -d*hooks.example/beat*"] }
```

- **allow（允列）**：glob 串数组——本任务**明言可再施**的遂键（轮询心跳、重试型
  通报等设计上重复之物）。宽 glob：词元含 `*` 时按通配全匹配、`*` 跨空白段；
  不含 `*` 时规整逐字相等。命中允列的遂笔**豁施**（豁免在判定序第一位，§5）；
- **无册照判**：遂形开箱在岗，册缺失 = 全账（已遂照账）；
- 册是结构化 JSON、唯一入口（CLI allow/disallow），无词旗标覆盖；
- 册缺失自动建册（允列是授权，空册 = 全账）。

## 5. 判定序（锁死，逐遂键逐笔恰一态）

对同遂键的第 n 笔（n ≥ 2，按流序；首笔恒 **初遂** 0 分）：

| 序 | 条件 | 案别 | 分 |
|----|------|------|----|
| 1 | 遂键命中允列 | **豁施** | 0（注记） |
| 2 | 自上一笔遂后流内存在**消据** | **已消** | 0（注记：补过之施——既往不咎） |
| 3 | 自上一笔遂后、本笔遂前存在**再命**（限同会话） | **承施** | 0（注记：新命开新决） |
| 4 | 其余 | **重决** | +30/案（cap 60） |

### 5.1 消据与成物之柄

- **成物之柄**：从该遂键**首笔遂**的 `result.content` 提取首个 URL，取其路径**末段
  资源号**（`https://github.com/acme/app/issues/7` → `7`；`…/pull/42` → `42`；
  `…/gist/abc123` → `abc123`）；content 无 URL → 无柄；
- **消据**：某笔成功 exec 段**含消词 ∧ 含柄资源号**（整词元相 等）。消词表 11 词：
  `close` `cancel` `revoke` `dismiss` `void` `refund` `delete` `destroy` `deactivate`
  `unlink` `archive`；
- **消跨会话有效**（合审拼接流序；下一个会话收尾上一个会话的双生物，是补过的常态）；
- 消据只对**其后**的再施开新决（序 2 位置）；末笔之施**之后**的消据是**末消**：
  只出注记不销案（§8）——世界已双生，凭消只证知悔，不证未发（与 fangchuan 已浚异调、
  与 kaocheng 灭物同调，理由登记于 §12）。

### 5.2 再命（承施的两条词法通道，声明权在主渠道）

再命事件 = principal 文本，pos 严格介于上一笔遂与本笔遂之间（**限同会话**——
另一会话的主文无从认作本会话之命），且满足其一：

- **对象通道**：principal 文本含该遂键的**对象词元**（施键非旗标词元，长 ≥3，
  剔通用词表：`gh` `api` `curl` `wget` `http` `https` `mail` `mailx` `sendmail`
  `mutt` `msmtp` `post` `get` `bash` `sudo` `echo`——任意一个整词命中）；
- **命词通道**：principal 文本含**命词表 12 词**之一（`重发` `再发` `再试` `重试`
  `再来` `重跑` `再跑` `再施` `resend` `retry` `rerun` `again`），**且本笔是该
  principal 之后同会话的首笔遂**（一次再命只开一决）。

两通道皆不中 → 不承。先命之遂不溯既往：再命只豁其后首笔，第 n+1 笔照判。

### 5.3 运行时视图与主文（勘误：原「承施恒不判」与 A6 账实一致冲突，先于实现落盘）

插件只挂 `tools/result`，看不见 principal 事件——单会话运行时视图**照判重决**，
但凡有重决案必附注记「线上无主文，承不判——终裁归线下」：主渠道可能已再命而
运行时不可见，此注记把误报的出口留在案上。CLI 全流审计读原始流（principal
事件在内），承施照判——**终裁归线下**。exportStream 导出的流不含 principal
（运行时本就未见过），重放判重决与运行时账实一致；审计方要辨承施，须对原始
会话流跑 `chengshi audit`。

## 6. 重值与门禁

```
chong = min(60, 30 × 重决案数)
total = min(100, chong)
```

分带：**谐 0–29 / 叠 30–59 / 沓 ≥60**。门默认 30：

- **单重决即红**——重决是已经发生的世界事实（第二条评论已发出），与「单处吞形还在
  两可」不同调（fangchuan 黄牌之例不适用于既成之施）；
- 初遂、已消、豁施、承施恒 0 分；末消注记不销案不改分。

## 7. 遂牌块（接缝供给，逐字节确定）

```
【成事 · 遂牌】
遂形：15 形（启 7 · 邮 5 · 单 3）
遂册：允 1 键（curl -d*hooks.example/beat*）
遂账：初遂 2 · 重决 1 · 已消 1 · 豁施 3 · 承施 1
重决：gh·issue·create 3f8a1c2b ×2（初遂 seq 3，再施 seq 7）
已消：gh·issue·create 9d4e5f60 ×2（消于 seq 5）
末消：mail 1a2b3c4d（消于 seq 12——善后留痕）
```

- **遂名**（掩码）：`施主基名·资源词` + djb2 指纹（遂键 hex 8 位）——块与 issues
  **永不携带命令原文与实参**（URL、邮箱、单据参数都进不了供给面，掩码是结构性保证）；
- 无册遂牌（确定性文本）：`遂册：未立（允列无据，已遂照账）`；
- 案行排序：重决 → 已消 → 豁施 → 承施 → 末消，族内按遂名指纹字典序；
  同输入两次渲染逐字节相同（shasum 可证）。

## 8. issues 行序（锁死）

重决点名（`重决：<遂名> ×n（初遂 seq i，再施 seq j…）`）→ 已消注记 → 豁施注记 →
承施注记 → 末消注记 → 全谐单行（`事皆遂 ×0 —— 成事不说，遂事不谏`，无任何案与
注记时出此行）。

## 9. 插件 API 与 CLI

**插件**（`chengshi-dsh`，Service 名 `chengshi`）：`report()` 汇总、`ledger()` 遂账
全文（逐键逐笔）、`paizi()` 遂牌块、`gate()` 门禁裁决、`exportStream()` 导出会话流
（call/result 成对、args 原样），供 `chengshi audit` 离线重放对账。

**CLI**（零依赖，`chengshi`）：

```
chengshi audit <s1.jsonl> [s2 …] [--file <遂册>] [--gate n] [--json]
chengshi allow --key <glob> [--file <遂册>]     立允（允列授权，重复去重）
chengshi disallow --key <glob> [--file <遂册>]  销允
chengshi list [--file <遂册>]                   阅册
chengshi block [--file <遂册>]                  遂牌块（遂形与遂册公示，逐字节确定）
chengshi gate --value <n> [--gate n]            门禁裁决
chengshi --help | --version
```

默认册 `./.chengshi.json`；allow/disallow 册缺失自动建册；disallow 无此键 exit 2；
list 册缺失 exit 2。退出码：0 通过 / 1 门禁失败 / 2 用法与输入错误。

## 10. 与既立各层的方向边界（结构性，不是纪律性）

知止拦动作，解蔽审判断，正念守意图，治未病体检开工，九变勘应变，有涯守见闻，
论世审发令资格，定分裁写域，捭阖守出境，法仪护尺，直笔保笔，豫立审备，度支量入，
二柄审柄，终始记程，效验称实，名实核名，立诚结诺，稽疑稽问，乡校听声，知足量出，
审曲审残全，舍筏审落物之宿，渊鱼审入目之禁，不贰记跨会话之训，水土审境变复位，
考诚考交付之契，恒法审规矩源之名分，知行审知行断层，防川审交付代码的吞错之形，
平准审依赖籍面之附；**成事审已遂之施的再施**：遂面（词面）→ 遂账（同键并案）→
重值（门禁）→ 遂牌（供给）。

- **二柄**：一柄一遂。它审**行使之命**（授没授——无命自专是侵柄，已答重问是渍请），
  本层审**已遂之账**（做没做过——两笔皆有命的重施它全放行）。erbing mixed 双跑
  `terraform apply` 喂本层零案（收敛类排除），边界互证；
- **有涯**：一费一害。它审**复命**（同串执行 ∧ 其间全库无成功写——重复之**费**，
  殆值），本层审**重决**（已遂之**害**，重值）——两笔施之间夹一笔写它就哑（恰是
  循环 agent 常态），本层照记；同一笔双跑可两账并记（渊鱼×有涯同一装载两账之例）；
- **九变**：一败一成。它勘**失败后**的盲捶，本层审**成功后**的重决——isError 位
  逐字可分，两账各记一侧；
- **捭阖**：一出一施。它审出境之**物**（泄密面），本层审已遂之**施**（重复面）——
  同一条 `curl -d` 可以两账并记：带密出境归它，同串再施归本层；
- **定分**：一域一世。它裁**仓库写域**（文件之地），外发之施落在仓库外的世界，
  分册无名；
- **立诚**：一诺一施。它追**说出口的诺**（话语→凭据），本层记**落了地的施**
  （行使→行使）——从没承诺过的行使它看不见，本层照记；
- **终始**：一程一施。它记**任务方事册**的众事行程（无册不判），本层记**默认遂形**
  的行使次数（无册照判）；
- **考诚**：一契一物，本层一施一世——契上物对契约条款，遂账对世界次数；
- **论世**：一权一世。它审**谁有资格发令**（物渠道冒充主命），本层的再命只认
  **主渠道亲口**（principal 事件）——谁发令归它，发了几遍归本层；
- **zhizhi**：账与闸分治。拦动作是它的地盘，本层从不拦——成事全部发生在接缝之后，
  观察永不反噬；
- **jiebi/zhengnian/weibing/jiubian/youya（费侧见上）/lunshi/fayi/zhibi/yuli/duzhi/
  erbing（柄侧见上）/zhongshi（程侧见上）/xiaoyan/mingshi/jiyi/xiangxiao/zhizu/shenqu/
  shefa/yuanyu/buer/shuitu/licheng（诺侧见上）/kaocheng（契侧见上）/hengfa/zhixing/
  fangchuan/pingzhun：对象键正交（判断/意图/开工体检/势途/渠道/尺/笔/退路/量入/

## 12. 既知从宽代价（宁漏方向，逐条登记）

- **变参不入键**：遂键是规整命令串——同施而改了参数（换标题再建、改正文再发）不入
  同键，宁漏；
- **超时已落地**：第一笔实际已成功但流内 isError=true（超时被记失败）——试施不入账，
  其后的同串成功笔判初遂不判重决（流内无从知其已遂，宁漏）；
- **排除类的重施**：`npm publish` 同版重推自守（registry 硬错）、`terraform apply`
  与 PUT 收敛自愈、`git push` 的重复是推进不是重复（推的是新提交）——三侧默认
  排除，其重施不入账（排除即边界，登记）；
- **邮族无柄**：信不出 URL，`result.content` 无从提成物之柄——邮族的凭消不可见，
  免案唯允册与再命两途（登记）；
- **承施限同会话**：主文与施必须同流——跨会话的「他已让另一个会话重发」无从认命
  （宁记不承，重决照案，理由见注记）；
- **运行时无主文**：运行时视图照判重决、附「线上无主文」注记（§5.3）——主渠道
  已再命而运行时不可见者，运行时红、线下承，终裁归线下全流审计（宁记方向：
  双生之物先入账，误报有注记可辨）；
- **一次再命只开一决**：principal 之后的第二笔同串遂照判重决（命词通道从宽到
  「紧邻首笔」为止）；
- **末消不销案**：善后留痕不改分——双生之物曾被世界看见，凭消只证知悔
  （与 fangchuan 已浚异调、kaocheng 灭物同调，理由登记）；
- **柄资源号是弱凭**：消据 = 消词 ∧ 资源号整词元——`close 7` 认消；资源号撞他物
  （另一对象的 7）理论可诬，消词在场作强闸（宁纵方向：错认消据的代价是把重决
  记成已消——漏记一侧）；
