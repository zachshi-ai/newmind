# 成事 · Chengshi — Agent 协作协议

> **「成事不说，遂事不谏，既往不咎。」——《论语·八佾》**
>
> 已经做成的事，先入账再动手。本协议不限制你怎么行使（拦是知止的地盘），
> 它要求：对外行使的每一笔成功，账上有一笔；再施之前查账，再施之后对账——
> 既往不咎留给补过的人（消了再施是新决）。

## 何时用此 Skill

- 工程师想防住「agent 把同一个 PR/issue/评论/邮件/POST 做了两遍」（超时重试、
  循环重扫、断点续跑、「为保险再跑一遍」都是它的病因）；
- CI 需要一道「已遂重施」门禁（重值 ≥ 30 即红——单重决即红）；
- Agent 需要自查：这件事账上是不是已经遂过？再施有没有任务方的允列或主渠道的再命？

## 给派活的工程师

```bash
cd your-repo
chengshi allow --key "curl -d*hooks.example/beat*"     # 轮询心跳类，先立允
# ……Agent 作业……
chengshi audit session.jsonl --file .chengshi.json     # 收工审遂（exit 码可进 CI）
chengshi block --file .chengshi.json                   # 遂牌块：遂形与遂册公示
```

- **无册照判**：遂形 15 形开箱在岗——不立册也审，册只管允列一侧；
- **排除即边界**：发布类（同版自守）、terraform/PUT（收敛自愈）、`git push`
  （重复是推进）不在遂形表——它们的重复不记账；
- **门禁**：重值 ≥ 30 即红——单重决即红（双生之物是已经发生的世界事实）。

## 给 Agent 的五条纪律

1. **动施先问账**：遂牌块在接缝处公示遂账——同一件事要再做一遍之前，先看
   遂名 ×遂次；账上有遂，再说「再做一次」；
2. **允列趁开工立**：设计上就该重复的行使（心跳、轮询），开工时向任务方讨允列
   （`chengshi allow`），允列上的再施不入案；
3. **再命要留痕**：人真的说了「再发一遍」？让这句主渠道话进流——线下审计读到它
   才能判承施；运行时看不见主文，先红后核；
4. **补过要消据**：发现做重了，去把多余的那份关掉（消词 + 成物之柄同在一段）——
   消了再施是新决；善后留痕（末消注记）不销案，但它是你知悔的凭据；
5. **词法可欺但骗一次留一次形**：换标题再建、改正文再发，账上是两个键——
   别把变参当成隐身术。

## 判定语义速查

| 案 | 对象 | 判定 | 分值 |
|---|---|---|---|
| 重决 | 同串之施成功两笔，无允列、无凭消、无再命 | 已遂之施被再施 | +30/案（单案即红） |
| 已消 | 再施之前有凭消（消词 ∧ 成物之柄） | 补过之施（既往不咎） | 0（注记留痕） |
| 承施 | 两施之间有同会话主渠道再命（对象词元 ∨ 命词 ∧ 紧邻首笔） | 新命开新决 | 0（注记） |
| 豁施 | 遂键命中遂册允列 | 任务方明言可再施 | 0（注记） |
| 末消 | 末笔之施后有凭消 | 善后留痕 | 0（注记，不销案） |

- 重值 = min(60, 30×重决)；分带 谐/叠/沓，门 30；
- 遂形三族 15 形：启 7（gh 建档/评论/发版/片/标/api 显默 POST）· 邮 5
  （mail/mailx/sendmail/mutt/msmtp）· 单 3（curl/wget 显默 POST、httpie POST）；
- 消词 11 词（close/cancel/revoke/dismiss/void/refund/delete/destroy/deactivate/unlink/archive）；
  命词 12 词（重发/再发/再试/重试/再来/重跑/再跑/再施/resend/retry/rerun/again）；
- 全部判定零 LLM：遂形是词面、允列是 glob——词法可欺但骗一次留一次形。
