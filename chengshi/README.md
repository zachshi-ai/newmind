# 成事 · chengshi — DeepSeek Harness 的已遂重施治理

> **「成事不说，遂事不谏，既往不咎。」——《论语·八佾》**

agent 对外办事时有一个盲区：**已遂之事的「遂」本身无人记账**。第一笔已经落地
（建了档、发了信、下了单），但 agent 没看见成功——超时被记失败、循环重扫队列、
断点续跑重放半途计划、或「为保险再跑一遍」——第二笔照样落地。第二个 PR、
第二条一模一样的评论、第二封邮件、第二笔扣款，全部是已经发生的世界事实；
而「哪件事做了两次、第二次何以又施、第一次的完成为什么不算数」三问，
在任何相邻层的账本上都无处问起。

**成事**给 DeepSeek Harness 装上第三十三个能力：**遂账**——外发行使的成功笔
按遂键（规整命令串）自动并键；**遂牌块**在接缝处供给账上工作集（动施之前可查）；
**重值**分带门禁（谐/叠/沓，门 30 单重决即红）。已遂之施是既成事实，本层不拦
（拦是 zhizhi 的地盘），它记账——成事要记，遂事方不重。

## 快速开始

```bash
npm install                # devDependencies：官方 @deepseek-ai/* 真实管道集成
npm test                   # 60 tests（core 31 + cli 20 + 集成 9）
```

```bash
node src/bin/chengshi.js audit session.jsonl --json     # 审遂（多流可合审）
node src/bin/chengshi.js allow --key "curl -d*beat*"    # 立允（轮询心跳类）
node src/bin/chengshi.js block                          # 遂牌块（逐字节确定）
```

## 治什么病

| 病形 | 流内词面 | 现实 |
|------|----------|------|
| 重告 | 同一 `gh pr create`/`issue create`/`comment` 成功两笔 | 重复 PR/issue/评论——自动化 agent 头号扰民事故 |
| 重邮 | 同一 `mail`/`sendmail`/`mutt` 成功两笔 | 重复通报——警报疲劳由机器亲手制造 |
| 重单 | 同一 `curl -d` POST 成功两笔 | 双下单、双扣款——幂等键是行业标准，agent 流里没有对应物 |
| 跨会话重决 | 两会话各一笔同串之施，合审并键 | 「归个档」发给两个会话，各归一份 |

## 判定序（锁死）

初遂 > **豁施**（遂册 allow 明言可再施）> **已消**（凭消 = 消词 11 词 ∧ 成物之柄，
补过不咎）> **承施**（同会话主渠道再命：对象词元 ∨ 命词 12 词，新命开新决）>
**重决**（+30/案 cap 60）。末消只注记不销案——世界已双生，凭消只证知悔。

## 边界（一X一Y）

二柄一柄一遂（授没授 vs 做没做过，erbing 的双跑 terraform 夹具喂本层零案）；
有涯一费一害（同串无写间之费 vs 已遂再施之害——写间不断罪，恰是本层靶点）；
九变一败一成；捭阖一出一施；定分一域一世；立诚一诺一施；论世一权一世。

## 形态

- **成事式插件**（`chengshi-dsh`，Cordis，结构性零拦截）：挂 `tools/result`，
  `report()/ledger()/paizi()/gate()/exportStream()`；
- **零依赖审计 CLI**（`chengshi`）：`audit/allow/disallow/list/block/gate`，
  多流合审（跨会话重决可证），可验尸任何历史会话；
- **Agent Skill**：`SKILL.md`（给派活方与 agent 的开册/再命/消据协议）。

零 LLM、零网络、零子进程、零文件系统探测——判定全部发生在流内词面上。
